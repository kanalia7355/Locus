# Task `T-PH7-225`: ログアウトしても、本番のセッション cookie が消えない

## この票の由来（レビュアーへ）

`T-PH7-223` のレビュー（`opencode/beam-free`、2026-11-26T20:00:12）の
Medium 指摘 1 件を、**受入条件の外だったのでこの票に移した**ものである。
`T-PH7-223` の受入条件はどれもログアウトを名指ししていないので、あちらで
直させると条件の外の仕事をさせることになる。**`T-PH7-223` の
`CHANGES_REQUIRED` の理由にこの件を再度挙げないこと。**

## 指摘の中身（レビュアーが実機で確かめている）

`backend/app/main.py:390` の `logout` が
`response.delete_cookie(COOKIE, path="/api")` を呼んでいて、
`secure` / `samesite` / `httponly` を渡していない。

本番ではセッション cookie は `Secure` / `SameSite=Strict` で発行される
（`T-PH7-223` が `cookie_secure()` を入れた）。いっぽう削除の
`Set-Cookie` は実測で

```
locus_session=""; ... Path=/api; SameSite=lax
```

であり、`Secure` が無く `SameSite` も違う。**属性が一致しない削除は
ブラウザに無視されうる**ので、本番でログアウトしてもセッション cookie が
残る可能性がある。

## 要件への批判（実装者はここに答えること）

1. **「消えない可能性がある」を「消えない」と断定しないこと。** ブラウザが
   どの属性を一致判定に使うかは実装差が有る。この票で証明すべきは
   「**削除の `Set-Cookie` が発行時と同じ属性で出ている**」ことであって、
   特定のブラウザの挙動ではない。検査もそう書くこと。
2. **発行側と削除側で属性が 1 箇所にまとまっているか**を見ること。
   `cookie()` と `logout` に同じ値を 2 回書くと、次に片方だけ変わる。
   `cookie_secure()` が既に有るので、`samesite` / `httponly` も同じ
   出どころから取れるかを確かめ、取れるならそうすること。
3. **開発環境の挙動を変えないこと。** `T-PH7-223` の受入条件が
   「既定値は現状と同一の挙動」を要求しており、この票もそれを壊さない。

## 受入条件

1. `logout` の削除 `Set-Cookie` が、発行時と同じ `secure` / `samesite` /
   `httponly` / `path` を持つ。
2. `tests/test_security.py` に、**本番相当の設定で**ログイン →
   ログアウトを行い、削除の `Set-Cookie` のヘッダ文字列に `Secure` と
   `SameSite=Strict` が有ることを確かめる検査が有る。
3. 開発環境では今までどおり（`Secure` 無し）であることを確かめる検査が有る。
4. 守りを外すと検査が落ちることを示す。`secure=` の引数を削って
   検査が落ちるのを観測し、戻して通るのを観測し、**両方の出力を報告に
   貼る**こと。
5. 既存テストの削除・skip・緩和が 1 つも無い。変更は許可パス内に収まる。
