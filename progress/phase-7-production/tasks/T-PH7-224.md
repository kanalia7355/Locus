    TLS 必須。「証明書の入手方法（社内 CA / 自己署名 + 配布）は
    配備手順の課題として別途詰める」と明記されている。本ジョブがその「別途」である。
  - `T-PH7-223` が**起動時の拒否**を実装する。しかし起動要件を満たしていても、
    配備する人が証明書をどこから得るのか、どの口で待ち受けるのか、
    外向き通信をどう塞ぐのかを知らなければ配備できない。
  - 既存の運用文書は `docs/operations/`（`LOCAL_LOOP_STARTUP_REPAIR.md`、
    `SAFE_AUTO_MERGE_SETUP.md`、`WINDOWS_CI_STARTUP_FINDINGS.md`）と
    `docs/WINDOWS_SERVICE_SETUP.md` 系で、**いずれもループ運用向け**であり
    本番配備の手順は存在しない。
  - **文書だけのジョブにしないこと**。手順書は書いた瞬間から実装と乖離する。
    本ジョブは「手順書」と「稼働中の設定が手順書どおりかを照合する実行可能な確認」を
    対にして納める。
- **Implementation Details**:
  1. `docs/operations/PRODUCTION_DEPLOYMENT.md`（新規）に配備手順を書く。最低限:
     - 証明書の入手方法を**選択肢として両方**書く:
       (a) 社内 CA で発行、(b) 自己署名 + 各端末への配布。
       それぞれの作業手順、置き場所、権限（鍵は配備ユーザのみ読める）、
       期限切れ時の交換手順、期限の確認方法。
     - TLS の張り方を `LOCUS_TLS_TERMINATION` の 2 形態
       （`proxy` / `native`）に分けて書く。`proxy` の場合は前段の要件
       （転送先は私設インタフェース、`LOCUS_TRUSTED_PROXY` に前段を明示）。
     - 待ち受けの設定（`LOCUS_PRIVATE_INTERFACE`）と、
       公開インタフェースに出さないための確認方法。
     - 許可ホスト（`LOCUS_ALLOWED_HOSTS`）の決め方。ワイルドカード禁止の理由。
     - 外向き通信の遮断（`ALLOW_CLOUD_EGRESS=false` / `LOCAL_ONLY_MODE=true` と、
       OS/ファイアウォール側の遮断）。
     - 本番ストアが PostgreSQL であること（オーナー決定 3）への参照。
       本ジョブで PostgreSQL 移行の手順を書き切る必要はないが、
       どのジョブが担うかを示すこと。
     - 設定名は `T-PH7-223` の `backend/app/deployment.py` の定義と**同じ名前**を使う。
       勝手に別名を書かないこと。
  2. `docs/operations/PRODUCTION_VERIFICATION_CHECKLIST.md`（新規）に運用確認の
     チェックリストを書く。各項目は「誰が」「何を実行して」「何が見えたら合格か」の
     3 点を含むこと。最低限: 証明書の出自と期限、待ち受けが私設インタフェースに
     限られていること、公開インタフェースから到達できないこと、外向き通信が
     遮断されていること、セッション cookie に `Secure` が付いていること、
     管理者以外が管理経路を読めないこと。
     **各項目に、下記 3 の確認スクリプトで自動確認できるか否かを明記する**
     （自動で見られないもの＝人が目で確認するものを、はっきり分けること）。
  3. `scripts/check_deployment.py`（新規）を作る。
     - 既定（引数なし）は**オフラインの照合のみ**を行う: 環境変数と
       証明書ファイルの実在・権限・期限を読み、`backend/app/deployment.py` の
       定義と突き合わせ、不足・不正を一覧して**終了コードを非 0** にする。
       設定名の一覧は `deployment.py` から**import して得る**こと。
       スクリプト側に名前を書き写さない（書き写すと乖離する）。
     - 既定では**ソケットを一切開かない**。到達性や外向き遮断の実地確認は
       `--probe` のような明示的な引数でのみ行い、既定には入れないこと
       （`tests/test_security.py:247-253` が合成テスト内でのソケット接続を
        禁じているのと同じ理由で、オフラインで走らせられることを守る）。
     - 出力に証明書の秘密鍵・パスワード・セッション値を**出さない**。
       証明書は主体名・発行者・期限のみを出す。
     - `scripts/verify.py` と `pyproject.toml` は保護パスなので**触らない**。
       CI への組み込みは別途オーケストレータが行う。
  4. 手順書・チェックリスト・スクリプト・`deployment.py` の 4 者が**同じ設定名**を
     指していることを、テストで機械的に照合する（下記受入条件 2）。
- **Acceptance Criteria**:
  1. `tests/test_deployment_check.py`（新規）に、`scripts/check_deployment.py` を
     合成環境で駆動するテストがある。すべてオフラインで完結すること。
