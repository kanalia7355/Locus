# Task `T-PH7-223`: 本番起動要件（TLS と私設インタフェースが無ければ起動しない）（`PROD-002` / `PROD-003` / `IAM-017`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PROD-002`（認可された私設ネットワーク接続。
  「LAN に居ることが権限にならない」）、`PROD-003`（本番配備の制御。
  私設インタフェース / ファイアウォール / 許可リスト、該当箇所の TLS）、
  `IAM-017`（本番の TLS とセッション配備）。
  出典の整理は `docs/plans/REQUIREMENTS_TRACEABILITY_MATRIX.md:10-11` と
  `docs/plans/OWNER_REEVAL-C-STORAGE-MISC.md:180`。
- **Background**:
  - オーナー決定 2026-11-16（`progress/phase-6-extensions/OWNER_DECISIONS.md` テーマ 5）:
    「通信の暗号化は必要。社内ネットワーク内想定だが、web UI のため
    id と password のある人はブラウザで使用したいはず」。
    社内限定でも**ブラウザから使う以上 HTTPS を張る**ことが確定している。
  - いまの起動は `backend/app/main.py:208-215` で
    `APP_ENV != "development"` なら無条件に `RuntimeError` を上げ、
    **本番はそもそも起動できない**（`main.py:1` の docstring も
    「Production startup is deliberately unsupported」と書いている）。
    `ALLOW_CLOUD_EGRESS` と `LOCAL_ONLY_MODE` の検査もここにある。
  - 配備に必要な値はすべて**固定値**で、設定できない:
    `main.py:266` の `TrustedHostMiddleware(allowed_hosts=["127.0.0.1","localhost"])`、
    `main.py:270-271` の接続元 `{"127.0.0.1","::1"}` 限定、
    `main.py:33-46` の `ALLOWED_ORIGINS` / `ALLOWED_HOSTS`、
    そして `main.py:195-198` の `cookie()` が `secure=False` を渡している。
    `secure=False` のまま LAN に出すと、セッション cookie が平文経路にも乗る。
  - **本ジョブの要点は「起動させること」ではなく「不足していたら起動を拒むこと」**。
    設定が揃っていない本番は、動いてしまうより止まる方が安全である。
- **Implementation Details**:
  1. 設定の読み取りと検査を `backend/app/deployment.py`（新規）に集め、
     `create_app` はそれを呼ぶだけにする。検査を関数として切り出すことで、
     サーバを起動せずにテストから直接駆動できるようにする
     （`create_app()` 経由の確認と、関数直呼びの確認の両方を受入条件にする）。
  2. 受け付ける設定（環境変数。既定値は**現状と同一の挙動**になること）:
     - `APP_ENV`: `development`（既定）/ `production`。
     - `LOCUS_TLS_TERMINATION`: `proxy` または `native`。本番で**未設定なら起動拒否**。
       - `native` の場合は `LOCUS_TLS_CERT_FILE` と `LOCUS_TLS_KEY_FILE` が
         **実在して読める**こと。無い・読めないなら起動拒否。
       - `proxy` の場合は `LOCUS_TRUSTED_PROXY` に前段の私設アドレスが
         明示されていること。未設定なら起動拒否
         （「誰かが前で TLS を張っているはず」を信用しないため）。
     - `LOCUS_PRIVATE_INTERFACE`: 待ち受けアドレス。本番で**未設定なら起動拒否**。
       値は私設アドレス（`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`）に
       限り、`0.0.0.0` / `::` / 空文字 / ワイルドカードは**拒否**する。
     - `LOCUS_ALLOWED_HOSTS`: 許可するホスト名の明示列挙（カンマ区切り）。
       本番で未設定・空・`*` を含む場合は**起動拒否**。
     - `ALLOW_CLOUD_EGRESS` / `LOCAL_ONLY_MODE`: 既存の検査（`main.py:212-215`）を
       そのまま残す。本番でも同じく外向き通信は既定で拒否。
  3. **fail closed**: 判定できない・解釈できない値は拒否側に倒す。
     未知の `APP_ENV`（`staging` など）、未知の `LOCUS_TLS_TERMINATION` の値、
     数値や真偽値の解釈に失敗した場合はすべて `RuntimeError` で起動拒否。
     「設定が無ければ安全側の既定で動く」実装にしないこと
     （本番で TLS 無しに静かに起動するのが最悪の結果である）。
  4. 設定が**すべて揃っている**場合は起動を許し、そのとき次を設定値から導く:
     - `TrustedHostMiddleware` の `allowed_hosts` は `LOCUS_ALLOWED_HOSTS` の値。
     - 接続元の判定（`main.py:270-271`）は `LOCUS_PRIVATE_INTERFACE` の
       属するネットワークに限る。**LAN に居ることが認可にならない**ので、
       既存の認証・認可（`_authenticate` と各経路の権限検査）は一切緩めないこと。
     - `cookie()` は本番で `secure=True` を渡す。`httponly=True` と
       `samesite="strict"` は変えない。
     - `development` では**現在の固定値のまま**にする（既定値を変えない）。
  5. 起動拒否のメッセージは、不足している設定の**名前**を示す。
     値（証明書の中身、鍵の内容、ホスト名以外の秘匿値）は出さないこと。
  6. `main.py:1` の docstring と `/api/health`（`main.py:315-317`）の
     `"mode": "development-local-only"` は、本番で起動できる形になった時点で
     嘘になる。両方を実態に合わせて直すこと。
  7. **既存テストの扱い**: `tests/test_api.py:558-561`
     （`test_production_startup_is_disabled`）は `APP_ENV=production` のみを設定し
     `pytest.raises(RuntimeError, match="development")` を表明している。
     本ジョブで拒否理由が「TLS 未設定」に変わるため、この表明は
     **新しい契約に合わせて更新してよい**（同じ厳しさで、
     「設定不足の本番は起動を拒む」ことを表明し続けること）。
     表明の削除・`pytest.skip`・`match` の削除は禁止。
     `tests/test_security.py:271-276`（`test_reject_cloud_configuration`）は
     そのまま通ること。
- **Acceptance Criteria**:
  1. `tests/test_production_startup.py`（新規）に、**起動を拒む**ことの否定テストがある。
     それぞれ単独で `create_app()` が `RuntimeError` を上げること
     （`monkeypatch.setenv` で環境を作り、サーバは起動しない。完全にオフライン）:
     - `APP_ENV=production` で `LOCUS_TLS_TERMINATION` 未設定
     - `LOCUS_TLS_TERMINATION=native` で証明書・鍵のパスが未設定、
       または実在しないパス、または読めないパス
     - `LOCUS_TLS_TERMINATION=proxy` で `LOCUS_TRUSTED_PROXY` 未設定
     - `LOCUS_PRIVATE_INTERFACE` 未設定
     - `LOCUS_PRIVATE_INTERFACE=0.0.0.0`、`::`、空文字、公開 IP
     - `LOCUS_ALLOWED_HOSTS` 未設定、空、`*` を含む
     - `LOCUS_TLS_TERMINATION` に未知の値
     - `APP_ENV=staging`（未知の環境名）
     いずれも**実装前なら起動してしまう／別の理由で落ちる**ので、
     理由の文言まで表明して区別すること。
  2. 検査関数を直接呼ぶテストも同じ組み合わせで通ること
     （`create_app` 経由だけに依存しない）。
  3. 設定が揃った本番で `create_app()` が成功し、そのとき:
     - `TrustedHostMiddleware` の許可ホストが `LOCUS_ALLOWED_HOSTS` と一致する
     - ログイン応答の `Set-Cookie` に `Secure` と `HttpOnly` と `SameSite=Strict`
       が付く（`development` では `Secure` が付かないことも合わせて表明する）
     - `/api/health` の `mode` が `development-local-only` ではない
     証明書は `tmp_path` に置いた**合成ファイル**で足りる（本物の TLS は張らない）。
  4. `development`（環境変数なし）での挙動が現在と同一であること:
     許可ホスト・接続元判定・cookie 属性が変わっていないことを表明する。
  5. 本番で起動できても**認可は緩まない**こと: 未ログインの
     `GET /api/projects` が 401、非管理者の `GET /api/admin/audit` が 403 であることを
     本番設定の app に対して表明する（`PROD-002`「LAN に居ることが権限にならない」）。
  6. `ALLOW_CLOUD_EGRESS=true` / `LOCAL_ONLY_MODE=false` が、
     本番設定が揃っていても**なお起動を拒む**こと。
  7. 起動拒否のメッセージに証明書・鍵の内容が含まれないこと。
  8. `tests/test_api.py` と `tests/test_security.py` に退行がない
     （上記 Implementation Details 7 の更新を除く。更新箇所と更新後の表明を
     REPORT に明記すること）。
  9. 変更は許可パス内に収まる。実際の配備手順書と運用確認は `T-PH7-224` が扱う
     ので、本ジョブでは文書を書かない。
