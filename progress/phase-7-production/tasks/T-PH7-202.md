# Task `T-PH7-202`: Windows 共有フォルダ（SMB）コネクタ（`DATA-008`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `DATA-008`。オーナー決定 2026-11-16「win 共有フォルダ、GoogleDrive、
  BOX 等々」「チェック頻度は 10 分おき程度か、権利設定に変更があったら発火するようにする」。
- **depends_on**: `T-PH7-201`。共通インタフェース・巡回・元保存先の関門・

  `T-PH7-201` が `done` になるまで着手しない。
- **Background**:
  - SMB は 3 種のうち**唯一、変更通知 API が無い**。オーナー決定の「権利設定に変更があったら
    発火」は、SMB では **ACL のハッシュ比較**（`T-PH7-201` が用意した経路）で実現する。
    つまり SMB の権限失効の反映は、最悪で巡回 1 周ぶん（既定 10 分）遅れる。
    この遅れは実装の都制約であって、受入条件を満たさない言い訳ではない。
    **遅延の最大値を測って REPORT に数字で書くこと。**
  - Windows の共有フォルダの権限は、共有レベルの権限とファイルシステムの ACL の
    **両方**で決まり、実効権限は和ではなく制限の強い側になる。片方だけ見ると
    「読めないはずの人が読める」と判定しうる。両方を見るか、
    片方だけなら**より制限の強い側に倒す**こと。
  - 利用者の対応付けが要る。Locus の利用者 ID は `users.username`（`[a-zA-Z0-9][a-zA-Z0-9_.-]{2,63}`）で、
    Windows の SID とは別物。どう対応付けるかは本ジョブで決めて REPORT に書く。
    **当てずっぽうの名前一致で広い権限を与えないこと**（同名の別人がいる前提で設計する）。
- **Implementation Details**:
  1. `backend/app/connectors/smb.py` に `T-PH7-201` の共通インタフェースの実装を 1 つ置く。
     `backend/app/connectors/__init__.py` の登録表に 1 行足す。それ以外の既存ファイルは触らない。
  2. **オフラインで試験できる形にする**ことが本ジョブの設計上の主要な制約。
     - 対象の列挙・改訂値（更新時刻とサイズなど）・本文の読み出しは、
       **ローカルの一時ディレクトリ**を共有の代わりに使って試験できるようにする。
       UNC パス（`\\host\share\...`）とローカルパスの差を、経路の組み立て 1 か所に閉じる。
     - **ACL の読み出しと実効権限の判定は、差し替え可能な縫い目（seam）にする。**
       本番は Windows の API（`win32security` 相当）または `icacls` の出力解析を使い、
       試験は合成の ACL 提供器を注入する。**ACL ハッシュの計算と比較、
       実効権限の制限の強い側への倒し込み、利用者対応付けは、
       縫い目の内側ではなく外側（純粋な関数）に置き、合成入力で全分岐を試験する。**
     - 実際の Windows API を叩く部分は、この環境では試験できない。
       **その 1 か所がどこかを REPORT に明記する**（レビュアがその行だけを人の目で見るため）。
  3. 安定した同一性: ファイル名とパスは移動・改名で変わる。
     可能ならファイル ID（NTFS のファイル参照番号など）を使い、使えない場合は
     「移動・改名は別オブジェクトとして扱い、古い側は削除として扱う」と決め、
     その選択と理由を REPORT に書く。どちらを選んでも、
     **移動を機に権限が緩む経路が無いこと**をテストで固定する。
  4. パスの封じ込め: 管理者が設定した共有の根より上へ出られないこと。
     `..`、シンボリックリンク、ジャンクション、UNC の別ホストへの横飛び、
     Windows の予約名（`CON`、`NUL` など）、代替データストリーム（`file.txt:stream`）を
     すべて拒否する。既存の `unsafe_document_name` は**資料名の規則であって経路の封じ込めではない**ので、
     それに頼らないこと。
  5. 本文の取り込みは既存の制限をそのまま使う。現在の対応形式は `.txt` `.md` `.csv`、
     UTF-8、256 KiB（`service.py` の `MAX_CONTENT_BYTES`、`unsupported_extension`）。
     **本ジョブで対応形式を増やさない**。形式の拡張は `DATA-007`（`T-PH6-103`）、
     未知形式の解析は `T-PH6-104` のサンドボックスが先に必要。
     読めない形式は「対象外」として記録し、索引しないこと（黙って飛ばさない）。
  6. 資格情報: Locus のプロセスが共有へ到達する資格情報は OS の資格情報ストアに置く
     （オーナー決定 2026-11-16 テーマ 1 E5）。リポジトリ・ログ・進捗記録・監査行に書かない。
     本ジョブでは**資格情報の保管機構を実装しない**。参照のみ（非機密の参照名）にとどめ、
     未実装であることを REPORT に書く。
  7. 社内回線内のみ（オーナー決定 E3）。外向きの宛先へ出る経路を作らないこと。

## REPORT
- **`backend/app/connectors/smb.py`** (new): Implemented the SMB/Windows-share `SourceConnector` (`kind="smb"`). The connector is offline-testable: a local directory acts as the share root and ACL readout is injected through an `AclProvider` seam (`get_snapshot`). Pure functions outside the seam handle all decision logic: `effective_permission` (most-restrictive share+file, unknown/unobtainable => not readable), `map_locus_user` (exact explicit mapping only, no guessy name match), and `permission_hash_for_snapshot` (stable hash over share+file ACL decisions). Path assembly is closed in one place (`resolve_within_root`), accepting local or UNC roots. Path containment rejects `..`, symlinks/junctions/reparse points (including inside-root), other-host UNC, Windows reserved device names, and NTFS ADS (`:` outside drive prefix); rejections are recorded in `connector.rejections` (observable, not silent) and operations fail closed (no exception passthrough to callers). Listing uses `os.walk(followlinks=False)` and prunes reparse-point dirs. Supported content is limited to existing formats via `app.formats.format_for` (txt/md/csv, UTF-8, 256 KiB / `max_bytes=262144`); unsupported/oversized/non-UTF-8/empty/control-char files are recorded as `out_of_scope` and not indexed. `accepts_notifications()` returns `False` (SMB has no permission-change notification API; polling + ACL-hash comparison is used).
- **`backend/app/connectors/__init__.py`**: Registered `SmbSourceConnector` in `CONNECTOR_FACTORIES` as `"smb"` (one registry entry), keeping the existing synthetic entry.
- **`tests/test_storage_connector_smb.py`** (new): Offline synthetic tests covering the job acceptance criteria: simultaneous invisibility across all 6 paths after ACL revocation+cycle; ACL hash stable-skip/no-reindex and unrelated-ACL change firing while visibility stays unchanged; effective-permission most-restrictive pure-function and connector combinations (share allow/file deny, reverse, one side unobtainable); path containment individually for `..`, symlink outside root, junction outside root, other-host UNC, Windows reserved names, ADS (each recorded refusal, fail-closed, no passthrough); move/rename identity and no permission loosening; undecidable ACL provider exception/unknown and unreachable share fail closed with no 500; out-of-scope format/size/non-UTF-8 observable as `out_of_scope`; explicit user mapping (no similar-name grant); pure hash stability.

**Required design/report items:**
- **Windows-API-untestable 1 place**: `WindowsAclProvider.get_snapshot` in `backend/app/connectors/smb.py` (marked `# pragma: no cover`, isolated seam). It is the only place that would call Windows ACL APIs (`win32security`). If it is broken, it catches exceptions and returns `None`, so the connector/service fail closed: ACL snapshots become undecidable and source objects become unreadable/invisible rather than permissive.
- **Max permission-revocation reflection delay (default interval, no notification, worst case)**: `10 minutes` (600 seconds). `accepts_notifications()` is `False` and `SourceScheduler` default interval is 600s (`DEFAULT_INTERVAL_SECONDS`); with no push notification, a revocation is observed at the next poll, worst case one full interval.
- **Stable identity choice**: object identity is the **share-root-relative path** (`object_id`). Move/rename therefore becomes a different object and the old binding is treated as missing/deleted on cycle (fail closed by can_read/snapshot returning undecidable). I include NTFS inode (`st_ino`) in the revision when available for observability, but I did not make inode the primary object_id because offline/local-dir tests and non-NTFS behavior need a deterministic path identity; the job allows this fallback. Move does not loosen permission: old bound document is denied on missing/unknown ACL, and the moved object's ACL is evaluated independently.
- **User mapping**: explicit configured mapping `Locus username -> Windows identity` (`user_mapping` dict), exact `dict.get` only. No name normalization/guessing; unmapped users return `False` with `REASON_UNMAPPED_USER` recorded. This avoids same-name-different-person privilege grants.
- **Credentials**: not implemented/stored. The connector takes only non-secret config (root, mapping, injected ACL provider). No credential material is read/written by this change; OS credential-store integration remains unimplemented as required.
- **Path containment single assembly point**: `resolve_within_root` in `backend/app/connectors/smb.py` is the only root+object path assembly point; both local and UNC roots pass through it and containment/reparse checks.

**Inconsistencies found between documentation/job text and code:**
- Job text cites "UTF-8, 256 KiB (service.py's `MAX_CONTENT_BYTES`, `unsupported_extension`)"; in code there is no `MAX_CONTENT_BYTES` constant in `service.py`. The effective limit comes from `app.formats.SUPPORTED_FORMATS`/`DocumentFormat.max_bytes` (262144) via `format_for`/`max_content_bytes()`, and `service.unsupported_extension` delegates to `format_for`. I followed the code's format table.
- `AGENTS.md`/older docs reference `loop_engine/` and `docs/planning/...` as active; `docs/agent/CONSTRAINTS.md` marks `loop_engine/` deprecated and the harness/PROTOCOL as authoritative for harness tasks. I treated `CONSTRAINTS.md`/`PROTOCOL.md` as the harness constraint source and did not touch those paths.

**Risks / limitations left behind:**
- Real Windows ACL readout is unimplemented (`WindowsAclProvider.get_snapshot` returns `None` until wired to win32security/icacls and a real share identity model). It is fail-closed by design.
- Symlink-creation test is skipped on this Windows env due privilege (`WinError 1314`); junction-outside-root rejection is individually asserted and passes, and reparse detection covers symlinks/junctions in code. I did not weaken the symlink test; it skips only when the OS refuses symlink creation.

FINDINGS
- Low: `backend/app/connectors/smb.py` (`is_windows_reserved_name`): the reserved-name check splits on "." but does not strip trailing spaces/dots, so names like "CON " (trailing space) bypass the reserved-device-name rejection. On real Windows such names cannot normally be created, so practical risk is low, but the check does not fully match "all Windows reserved names." Smallest fix: strip trailing spaces and dots from the base name before the set lookup.
- Low: `backend/app/connectors/smb.py` (`is_reparse_point`): for a path that does not exist, `os.stat(..., follow_symlinks=False)` raises OSError and the function returns True, so `path_has_reparse_within` treats any missing component as a reparse point and fails closed. This is safe (fail-closed) but causes over-rejection of non-existent object ids passed directly to `can_read`/`permission_hash` (rejected as SYMLINK rather than UNREADABLE). Smallest fix: distinguish `FileNotFoundError`/`ENOENT` from other OSErrors and return False for a genuinely missing path, while keeping fail-closed for other stat errors.
- Low: `backend/app/connectors/smb.py` (`_scan_object`): when `candidate.exists()` is False or `candidate.is_file()` is False, the method returns None without recording a `Rejection`, so unreadable/special files are silently skipped rather than observable. Smallest fix: record `REASON_UNREADABLE` in that branch, matching the rejection-recording intent used for format/size/encoding failures.
