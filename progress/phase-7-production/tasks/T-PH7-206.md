# Task `T-PH7-206`: 利用者 1 人ごとの OAuth トークンを預かる場所を作る

## SCOPE — レビュアーはここを先に読むこと（2026-11-28 23:17 当番）

**オーナーが 2026-11-28 23:16 に接続の主体を決めた**:
`T-PH7-203 / T-PH7-204：(1)許可、(2)利用者ごとのOAuth`。
つまり**サービスアカウントではなく、利用者 1 人ごとの OAuth** である。

この票は**その器だけ**を作る。**Drive も Box もこの票では触らない**
（`T-PH7-203` / `T-PH7-204`）。器が無いまま接続側を書くと、
トークンの置き場所が各コネクタに散らばる。

**なぜ利用者ごとなのかを、実装者は理解しておくこと。** サービスアカウント
1 つで全ファイルを読める構成は、「利用者本人が今読めるか」を別途
問い合わせる必要があり、**問い合わせを忘れた経路がそのまま権限の穴になる。**
利用者本人のトークンで読めば、読めないものは読めない。

## いまある物（当番が実測、2026-11-28 23:17）

- `backend/app/connector_gdrive.py`（420 行、`T-STC-003`）は
  **サービスアカウント**で動いている（`LOCUS_GDRIVE_SERVICE_ACCOUNT_FILE`、
  JWT bearer grant）。`backend/app/connector_box.py`（495 行、`T-STC-004`）は
  **CCG**（client credentials）である。
- どちらも `ConnectorProtocol`（`list_items` / `fetch_content`）だけを実装し、
  **`can_read(source_id, object_id, user_id)` を持っていない。**
  つまり取り込みはできるが、**利用者ごとの権限判定は一切していない。**
- **トークンを預かる場所はどこにも無い。** `keyring` に相当するものは
  `backend/requirements.lock` に無い。

**この票はその 2 つのコネクタを書き換えない。** 置き場所を作るだけである。

## 決めたこと（当番。オーナーが別を言えばそれに従う）

1. **保管先は OS の資格情報ストアである** —— オーナー決定
   「鍵は OS 標準の資格情報ストアに保管する（Windows 資格情報マネージャ等）」。
2. **新しい第三者ライブナリを 1 つも足さない。** `pyproject.toml` は保護パスである。
   Windows では標準の `ctypes` から DPAPI（`crypt32`）を呼べる。
   それが使えない環境では、すでに宣言されている `cryptography==50.0.2` で
   暗号化したファイルに退避してよい —— **ただしその場合は
   「OS のストアではない」ことを記録に残すこと。** 黙って弱いほうへ落ちない。
3. **同意の受け口は loopback へのリダイレクトにする**（`127.0.0.1` の
   一時ポート）。外部からの着信を受ける経路は作らない ——
   `backend/app/main.py` は `APP_ENV` が `development` 以外なら起動を拒否し、
   配備の形を変えるのはこの票の仕事ではない。
4. **試験は合成の応答のみで成立すること。** 実在の Google / Box アカウント、
   実在の資格情報、実通信を 1 つも必要としない。

## Implementation Details

1. `backend/app/credentials.py`: 利用者 ID と提供元（`gdrive` / `box` …）の
   対で、**refresh トークンを預かり・取り出し・消す**こと。
2. `backend/app/connectors/oauth.py`: 同意（authorization code）→ トークン交換
   → 更新（refresh）→ 失効（revoke）。**トークン交換の宛先は注入できる形に
   すること** —— そうでないと合成の応答で試験できない。
3. `backend/app/main.py`: 同意を始める経路と loopback の戻り先。
   **管理 API ではなく利用者本人の操作である**ことに注意
   （`/api/admin/*` の 403 の作法は `T-PH7-216` の話で、ここではない）。
4. **期限切れのトークンで読めると答えてはいけない。** 更新に失敗したら
   「判定不能」であり、判定不能は**拒否**である。

## Acceptance Criteria

1. 利用者ごとに refresh トークンを預け、取り出し、**消せる**こと。
   消した後に取り出すと「無い」と答えることを実行結果で示すこと。
2. **トークンがリポジトリ・ログ・進捗記録・監査行・例外メッセージ・
   API 応答のどこにも出ないこと。** `scripts/secret_scan.py` を通すだけでは
   不十分 —— **応答の生データを記録しない作り**であることを検査で表明すること。
   仕込むトークンは `sk-synthetic-0N-not-a-real-key` の 4 つのいずれかを
   **そのままの値で**使う（他の値はゲートに弾かれる）。
3. **更新（refresh）に失敗したとき、「読める」と答えないこと。**
   期限切れ・失効・到達不能の 3 つを合成の応答で作り、**すべて拒否側に
   落ちる**ことを実行結果で示すこと。同期や更新の失敗を許可の証拠として
   扱わない。
4. **OS のストアに置けなかったときに、黙って弱いほうへ落ちないこと。**
   退避した事実が記録に残ることを検査で表明すること。
5. 同意の戻り先が **`127.0.0.1` のみ**であること。外部のホストを
   戻り先として受け付けないことを検査で表明すること。
6. **新しい第三者ライブラリが 1 つも増えていないこと。** `pyproject.toml` と
   `backend/requirements.lock` の差分が 0 行であることを報告すること。
7. 試験が**実在のアカウント・資格情報・通信を 1 つも必要としない**こと。
8. `python -m pytest tests/test_credential_store.py tests/test_connector_oauth.py tests/test_security.py tests/test_api.py -q` が **PASS**。件数を報告すること。
9. 既存の検査を削除・skip・緩和しない。変更が `allowed_paths` 内に収まっている。
   **`connector_gdrive.py` と `connector_box.py` はこの票では触らない。**
