# Task `T-PH7-207`: 外向き通信を「既定拒否＋明示列挙」にする

## SCOPE — レビュアーはここを先に読むこと（2026-11-28 23:17 当番）

**オーナーが 2026-11-28 23:16 に外向き通信を許可した**
（`T-PH7-203 / T-PH7-204：(1)許可、(2)利用者ごとのOAuth`）。

**だが「許可」は「全部開ける」ではない。** オーナー決定 2026-11-16 テーマ 1 E3 の
作法は**既定拒否＋宛先の明示列挙**であり、
`docs/plans/PHASE2_STORAGE_ACL_RESEARCH.md` §4.6 の
「コネクタの実装は外向き通信の許可を含意しない」も維持する。
この票はその**仕組み**を作る票で、宛先を 1 つも開けない。

**いまの実装は、許可しようとすると起動を拒否する**（当番が実測、
`backend/app/deployment.py:113-117`）:

```python
def _validate_common_flags(environ):
    if _parse_bool_flag(environ, "ALLOW_CLOUD_EGRESS", "false"):
        _reject("Cloud egress is disabled (ALLOW_CLOUD_EGRESS)")
    if not _parse_bool_flag(environ, "LOCAL_ONLY_MODE", "true"):
        _reject("Only local mode is supported (LOCAL_ONLY_MODE)")
```

`ALLOW_CLOUD_EGRESS=true` にすると**起動そのものが拒否される**。
つまりフラグは「許可するための入口」ではなく「拒否の二重化」になっている。
これを**列挙された宛先だけを開ける形**に変える。

## Implementation Details

1. **既定は今のまま外向き拒否である。** 設定が何も無い状態の挙動を
   1 ビットも変えないこと。
2. 許可は**宛先の列挙**で与える（ホスト名の一覧。ワイルドカードを
   受け付けないこと —— `*.googleapis.com` を許すと、そこに居る
   すべてのサービスを許したことになる）。
3. **列挙に無い宛先への接続は、接続する前に拒否されること。**
   「出てみて失敗した」ではなく「出さない」。
4. 許可された宛先の一覧が、**起動時に記録に残ること**。
   何が開いているかを後から読める形にする。
5. **宛先をこの票で 1 つも開けない。** Google や Box のホスト名は
   `T-PH7-203` / `T-PH7-204` がそれぞれ自分の宛先を足す。

## Acceptance Criteria

1. **何も設定しないときの挙動が変わっていないこと。** 既定で外向きが
   拒否されることを表明する既存の検査が、そのまま通ること。件数で示すこと。
2. 宛先を 1 つ列挙した状態で、**その宛先は通り、列挙に無い宛先は拒否される**
   ことを実行結果で示すこと（合成の宛先でよい。実通信は不要）。
3. **ワイルドカードを受け付けないこと。** `*` を含む宛先を設定したら
   起動が拒否されることを表明する検査が有る。
4. 列挙に無い宛先が**接続の試行より前に**拒否されることを示すこと。
5. 許可された宛先の一覧が起動時の記録に出ること。**資格情報は 1 つも
   出ないこと**（宛先はホスト名だけであり、トークンや鍵を書かない）。
