# Task `T-PH7-204`: Box コネクタ（`DATA-008`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `DATA-008`。オーナー決定 2026-11-16「win 共有フォルダ、GoogleDrive、
  BOX 等々」「チェック頻度は 10 分おき程度か、権利設定に変更があったら発火するようにする」。
- **depends_on**: `T-PH7-201`。
- **着手できない理由（意図的）**: `allowed_paths` と `test_cmd` を `未確定` にしてある。
  ループはこのジョブを拾わない。`T-PH7-203`（Google Drive）と**同じ 2 つの未設計**が原因で、
  どちらも 1 ジョブで決められない。
  1. **資格情報と外向き通信**。Box への接続は外部への通信で、現在の起動時検査
     （`backend/app/main.py` の `LOCAL_ONLY_MODE` / `ALLOW_CLOUD_EGRESS`）が既定で拒否している。
     オーナー決定 2026-11-16 テーマ 1 E3 は通信を「社内回線内」に限っており、
     Box への外向き通信はその範囲外。別の許可が要る。
  2. **変更通知の受け口**。Box の webhook は **Box 側から Locus へ向かう着信**を必要とする。
     いま Locus には外部からの着信を受ける経路が存在せず、本番配備も実装上無効
     （`backend/app/main.py` は `APP_ENV` が `development` 以外なら起動を拒否する）。
     受け口を作ることは配備の形の変更であり、本ジョブの範囲を超える。
- **着手前に決めなければならないこと**:
  1. **外向き通信の許可**: Box の API 宛先への通信をオーナーが明示的に許可するか。
     許可する場合の宛先の明示列挙（既定拒否＋列挙）。
  2. **接続の主体**: Box のサービスアカウント（JWT / CCG によるアプリ利用者）か、
     利用者 1 人ごとの OAuth か。前者だと「利用者本人が今読めるか」を
     別途問い合わせねばならず、問い合わせを落とした経路がそのまま権限の穴になる。
     Box には代理操作（As-User）の仕組みがあるが、
     **代理の権限そのものが広い**ので、代理できること自体を許可の証拠にしてはならない。
  3. **資格情報の保管**: OS の資格情報ストア（オーナー決定 E5）に何をどう置くか。
     更新と失効の手順。`T-PH7-202` `T-PH7-203` と共通の機構にするか、
     どのジョブが先に作るかを決める。
  4. **変更検知の手段**: webhook（着信が必要）か、イベント API の差分取得を
     短い間隔で回すか。後者は通知ではなく高頻度の巡回であり、
     オーナー決定の「変更があったら発火」を厳密には満たさない。
     採る場合は**最大遅延をオーナーに示して了解を得る**こと。
     webhook の署名検証を省略しないこと（検証の無い受け口は誰でも叩ける）。
  5. **権限判定の単位**: Box の権限は共同作業者（collaboration）の役割、
     グループ、フォルダからの継承、共有リンク（公開・社内限定・共同作業者限定）が混ざる。
     どこまでを「読める」と見るか。とくに**公開共有リンク**を
     Locus の誰に対して「読める」と扱うかは、取り違えると全員に見せてしまう。
     親フォルダからの継承と個別の制限が食い違う場合は、**制限の強い側に倒す**。
  6. **Locus 利用者と Box アカウントの対応付け**: どの属性で結ぶか、
     対応の付かない利用者をどう扱うか（既定は「何も見せない」）。
  7. **この環境での試験方法**: 外部資格情報と通信が無い状態で何をどこまで試験できるか。
     最低限、`T-PH7-201` の共通インタフェースに対する**合成の Box 応答**での試験は可能。
     実通信部分の確認手順（誰がどの環境でいつ確認するか）を決めること。
  8. **対応形式**: Box Notes などの独自形式は変換が要る。
     変換するか、しないか（しないなら「対象外」として記録する）。
     形式の拡張自体は `DATA-007`（`T-PH6-103`）の仕事で、
     現在の対応形式は `.txt` `.md` `.csv`、UTF-8、256 KiB。
- **確定時に受入条件へ入れること**:
  1. **同時不可視**: 元保存先で閲覧権を失った利用者が、`T-PH7-201` の 6 経路
     （資料一覧・チャンク・`related`・検索候補・過去の出典・過去の生成回答）から
     同時に見えなくなること。1 経路でも残ったら落ちるテスト。
  2. 変更検知（webhook または採用した代替手段）で、巡回間隔を待たずに 1 の不可視化が起きること。
     代替手段を採った場合は**最大遅延を数字で**示すこと。
  3. webhook を採る場合、**署名検証に失敗した着信を処理しない**こと。
     偽の着信で可視性を操作できないこと（偽造した「権限が戻った」通知で見えるようにならない）。
  4. 判定不能・到達不能・トークン失効は**すべて拒否**（見せない）。
     同期の失敗を許可の証拠として扱わないこと。
  5. サービスアカウントや代理操作の広い権限が、利用者の権限として扱われないこと。
  6. 共有リンクの扱いが決定どおりであり、**全員に見える経路が意図せず生まれていない**こと。
     親フォルダ継承と個別制限の食い違いが制限の強い側に倒れること。
  7. 資格情報がリポジトリ・ログ・進捗記録・監査行・エラーメッセージに出ないこと
     （応答の生データを記録しない作りにする）。
  8. 外向き通信が、明示的に許可された宛先以外へ出ないこと。
     `LOCAL_ONLY_MODE` の既定（外向き拒否）を既定のまま保つこと。
  9. 試験は合成の応答のみで成立し、**実在の Box アカウント・資格情報・通信を
     必要としない**こと。
