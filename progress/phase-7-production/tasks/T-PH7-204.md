# Task `T-PH7-204`: Box の権限判定を、利用者本人のトークンで行う（`DATA-008`）

Drive 側で作った形をそのまま使うためで、**同じ判定を 2 度設計しない。**

- 実装しているのは `ConnectorProtocol` の `list_items` / `fetch_content` **だけ**で、

**だからこの票の仕事は、権限判定を利用者本人のトークンに載せ替えることである。**

## Box に固有の危険 —— As-User の委任は、許可の証拠ではない

**Box の As-User 委任は広い。** 管理者のトークンに `As-User` ヘッダを付けると
その利用者として読めるが、**「委任できた」ことは「その利用者が読める」ことの
証拠ではない。** 委任の範囲は管理設定で決まり、利用者本人の権限とは別物である。

**だから `can_read` の答えは、利用者本人のトークンで実際に読めたかどうかだけで
決める。** As-User を許可の証拠として使ってはいけない。これは
`T-PH7-203` の受入条件 4（サービスアカウントの広い権限）と同じ形の危険で、
Box では委任という別の顔で現れる。

## 当番が決めたこと（`T-PH7-203` と揃えてある）

- **変更通知 → 巡回。最大遅延は 10 分。** Box からの着信を受ける経路は作らない。
- **リンク共有 → 「読める」の証拠として扱わない。**
  Box の共有リンクは Drive と同じで、取り違えると全員に見せてしまう。
- **Locus 利用者と Box アカウントの対応付け → 本人の同意で作る。**
  同意していない利用者には何も見せない。
- **形式の変換 → この票では行わない。** Box Notes はファイルではないので
  「対象外」として記録し、**対象外であることが分かる形**で返す
  （黙って空にしない）。
- **試験は合成の応答のみ。** 実在の Box アカウント・資格情報・通信は不要。
