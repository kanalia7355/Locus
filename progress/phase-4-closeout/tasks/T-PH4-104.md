# Task `T-PH4-104`: 出典ダイアログのスクロール追従が Windows ローカルで成立しない

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PH-ROADMAP-4`（出典表示のキーボード・可視性）。T-PH4-103 監査の残置事項ではなく、
  2026-11-15 のローカル全検証で検出した既存不具合。
- **Background**:
  - `frontend/e2e/workspace.spec.ts:180`「citations open the actual page and chunk and reject stale targets」
    の最後の assertion `dialog.scrollTop > 0` が Windows ローカル（Chromium headless）で `0` となり失敗する。
  - 同一の失敗は本件検出時の変更を一切適用しない HEAD（`4d07db3`）でも再現するため、
    T-PH4-102 / T-PH4-103 の回帰ではない。
  - hosted CI では `verify.py` が secret scan 段で停止していたため、
    `ea6b508` 以降この E2E は CI で一度も実行されていない。したがって
    「CI では緑」という判断根拠は現時点で存在しない（2026-11-15 の push で判明する）。
- **Implementation Details**:
  1. まず hosted CI の結果を確認し、Linux でも失敗するか・ローカル固有かを切り分ける。
  2. ローカル固有なら、`sourceTarget.current.focus()` による暗黙のスクロール依存をやめ、
     明示的な `scrollIntoView`（`block: "center"`）など決定的な方式へ変更する。
     UI ベースラインの見た目・操作感は変えない。
  3. アサーションの弱体化（`scrollTop > 0` の削除・緩和）は禁止。
- **Acceptance Criteria**:
  1. `workspace.spec.ts` 13 件が Windows ローカルと hosted CI の両方で green。
  2. 出典ダイアログのフォーカス移動・Esc 復帰・引用箇所の可視性に退行がない。
  3. 変更が許可パス内に収まる。

## REPORT

- Implemented by: Claude Code (`claude-opus-5`)
- Changed Files: `tests/e2e_server.py`（1 文の UPDATE に `index_checkpoint=0` を追加）
- Summary:
  - **hosted CI でも同一に失敗することを確認**（run 43682050295、`ec946b3`、E2E 18 件中 17 passed・
    同じ `expect(scrollTop).toBeGreaterThan(0)`）。ローカル固有ではなく実在の不具合。
    なお `ea6b508` 以降この E2E は CI で一度も実行されていなかった（secret scan で先に停止していた）ため、
    「CI では緑」という従来の記録は根拠にならない。
  - **根本原因は `T-PH3-101` の再開可能インデックス化による意味変化**。`_index()` は
    `index_checkpoint + 1` 頁から処理するようになった。e2e fixture (`tests/e2e_server.py`) は
    `seed_synthetic`（1 頁・インデックス済み・`index_checkpoint=1`）の後に 2 頁の本文へ差し替えて
    `_index()` を再実行するため、**1 頁目が再インデックスされず古い短い本文のチャンクが残る**。
    結果として出典ダイアログの内容が短くなり、引用箇所へのスクロールが発生せず `scrollTop === 0` になっていた。
  - 再現実験（本修正前）: `seed_synthetic` 後の `index_checkpoint` が `1`、本文差し替え後の chunks は
    `[(1,1,107),(2,1,15)]` = 1 頁目が旧 `SYNTHETIC_TEXT` のまま。
  - 修正: fixture が本文を差し替える際に `index_checkpoint=0` を同時に書き、差し替え後の全頁を
    インデックスさせる（fixture の本来の意図）。プロダクトコードは変更していない。
    アプリの通常経路では本文差し替えは発生せず（取込は新規 document 行、`cancel` は本文を空にする）、
    チェックポイントの意味自体を変える仕様根拠がないため、`_index()` 側には手を入れない。
  - アサーションの緩和・削除は行っていない。
- 残件（owner 判断用・非阻塞）: 「本文を差し替えたら checkpoint を戻す」という不変条件は現在
  呼び出し側の責務である。将来 document の本文を更新する経路を追加する場合は `_index()` 側で
  checkpoint 整合性を担保する設計判断が必要（本タスクの範囲外）。
