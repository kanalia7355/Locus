# Task `T-PH4-104`: 出典ダイアログのスクロール追従が Windows ローカルで成立しない

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PH-ROADMAP-4`（出典表示のキーボード・可視性）。T-PH4-103 監査の残置事項ではなく、
  2026-11-15 のローカル全検証で検出した既存不具合。
- **Background**:
  - `frontend/e2e/workspace.spec.ts:180`「citations open the actual page and chunk and reject stale targets」
    の最後の assertion `dialog.scrollTop > 0` が Windows ローカル（Chromium headless）で `0` となり失敗する。
  - 同一の失敗は本件検出時の変更を一切適用しない HEAD（`4d07db3`）でも再現するため、
    T-PH4-102 / T-PH4-103 の回帰ではない。
  - hosted CI では `verify.py` が secret scan 段で停止していたため、
    `ea6b508` 以降この E2E は CI で一度も実行されていない。したがって
    「CI では緑」という判断根拠は現時点で存在しない（2026-11-15 の push で判明する）。
- **Implementation Details**:
  1. まず hosted CI の結果を確認し、Linux でも失敗するか・ローカル固有かを切り分ける。
  2. ローカル固有なら、`sourceTarget.current.focus()` による暗黙のスクロール依存をやめ、
     明示的な `scrollIntoView`（`block: "center"`）など決定的な方式へ変更する。
     UI ベースラインの見た目・操作感は変えない。
  3. アサーションの弱体化（`scrollTop > 0` の削除・緩和）は禁止。
- **Acceptance Criteria**:
  1. `workspace.spec.ts` 13 件が Windows ローカルと hosted CI の両方で green。
  2. 出典ダイアログのフォーカス移動・Esc 復帰・引用箇所の可視性に退行がない。
  3. 変更が許可パス内に収まる。
