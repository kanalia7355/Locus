# Task `T-PH4-102`: 質問ジョブの優先度・公平性（bounded queue, PH-ROADMAP-4 残部）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PH-ROADMAP-4` 残部「priority/fairness」
  （`docs/plans/PHASE_STATUS.md` Phase 4 Remaining 列）
- **Background**:
  - 質問ジョブと取り込みジョブは共有リソース制限付きの bounded queue で管理されている
    （`docs/planning/ui-and-multiuser-design.md` 参照）。現状は先着順単一スロットで、
    複数ユーザー同時利用時に特定ユーザーが飢餓する可能性がある。
    **能力 (capacity) の数値目標を新設してはならない**（roadmap §4 P3: measure before claiming）。
- **Implementation Details**:
  1. 先に `backend/app/service.py` のキュー実装と `frontend/src/ChatQueue.tsx` を読む。
  2. スケジューリング: **同一ユーザー連続実行の抑制（fair-share / round-robin）**を最小実装する。
     - キュー上限・実行中スロット数は既存値を変更しない（現状の bounded 制約を維持）。
     - 待ち行列内の順序は「公平性」規則で入れ替わるため、UI には
       「待ち位置は混雑により変動する」旨を表示する。
     - 優先度指定 API は追加しない（自己優先の乱用を防ぐ。設計判断は REPORT に記録）。
  3. 管理画面: `AdminSettings.tsx` の Load 表示に、待ち行列のユーザー分布
     （件数のみ・本文なし）を追加する（metadata-only 原則を維持）。
  4. テスト: 公平性の特性テスト（同一ユーザーが連続 2 回取らないこと、
     取り消し済みジョブが順序に影響しないこと、取消・失敗ジョブの退行なし）。
- **Acceptance Criteria**:
  1. 複数ユーザー待ちで同一ユーザーの連続実行が発生しない（合成テストで検証）。
  2. 既存の取消 (`PH4A`)・キュー上限・失敗報告の退行なし。
  3. 管理画面の負荷表示に待ち行列分布（件数のみ）が追加されている。
  4. 変更が許可パス内、実行時の挙動変化はスケジューリング順序のみ。
