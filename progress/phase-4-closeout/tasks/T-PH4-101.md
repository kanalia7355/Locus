# Task `T-PH4-101`: ローカル LLM ストリーミング応答（PH-ROADMAP-4 残部）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PH-ROADMAP-4` 残部「Actual local LLM streaming」
  （`docs/plans/PHASE_STATUS.md` Phase 4 Remaining 列）
- **Background**:
  - 現状の回答生成は非ストリーム（完了まで待って一括表示）。設計上の制約は
    `docs/architecture/ARCHITECTURE.md`（local LLM default）と
    `docs/planning/ui-and-multiuser-design.md`（bounded dialogue / 共有リソース制限）。
    実装済みの Ollama ローカルパス (`loop/TASK-local-ollama-rag`) を発展させる。
- **Implementation Details**:
  1. 先に `backend/app/service.py`（回答生成・キュー・キャンセル）と
     `frontend/src/App.tsx`（ChatQueue / 実行中質問の扱い）を実装読解してから設計する。
  2. バックエンド: ローカル LLM パスで **SSE (Server-Sent Events)** ストリーミングを追加する。
     - 応答は既存の ACL・境界チェック・bounded dialogue 制限を**すべて通す**（省略禁止）。
     - キャンセル (`PH4A` で実装済み) と共存させる。キャンセル時にストリームを中断し、
       部分応答を履歴に残さない等の挙動は既存のキャンセル意味論に合わせる。
     - ストリーミングが使えないモデル/環境では既存の非ストリーム経路へ自動フォールバック。
     - 監査は既存の metadata-only 方式を維持する。
  3. フロントエンド: 段階描画（逐次追記）、取り消し中の表示、アクセシビリティ上の
     `aria-live="polite"` 等を既存の話者/メッセージ構造に沿って追加。
     UI ベースライン (`docs/planning/UI_IMPLEMENTATION_BASELINE.md`) の見た目と
     インタラクションを壊さない。
  4. 外部クラウド API の呼び出しは**禁止**（egress なし、ローカルのみ）。
     AI 生成物が「提案 (suggestion)」である旨の表示を維持する。
  5. テスト: ストリーミング経路の API テスト（SSE 断片、キャンセル中断、ACL 拒否時は
     ストリーム開始前 403）、Vitest 逐次描画テスト。既存テストの削除・緩和禁止。
- **Acceptance Criteria**:
  1. ローカル LLM 利用時、回答が段階的に表示される（合成テストで検証）。
  2. キャンセル済み質問のストリームが中断され、完了扱いにならない。
  3. 権限のない質問（プロジェクト外・非公開文書のみ参照）はストリームが開始されず拒否される。
  4. 関連テスト全部が green、既存機能（キュー・取消・引用）の退行がない。
  5. 許可パス外の変更なし。
