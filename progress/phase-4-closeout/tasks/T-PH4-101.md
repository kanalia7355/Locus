# Task `T-PH4-101`: ローカル LLM ストリーミング応答（PH-ROADMAP-4 残部）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `PH-ROADMAP-4` 残部「Actual local LLM streaming」
  （`docs/plans/PHASE_STATUS.md` Phase 4 Remaining 列）
- **Background**:
  - 現状の回答生成は非ストリーム（完了まで待って一括表示）。設計上の制約は
    `docs/architecture/ARCHITECTURE.md`（local LLM default）と
    `docs/planning/ui-and-multiuser-design.md`（bounded dialogue / 共有リソース制限）。
    実装済みの Ollama ローカルパス (`loop/TASK-local-ollama-rag`) を発展させる。
- **Implementation Details**:
  1. 先に `backend/app/service.py`（回答生成・キュー・キャンセル）と
     `frontend/src/App.tsx`（ChatQueue / 実行中質問の扱い）を実装読解してから設計する。
  2. バックエンド: ローカル LLM パスで **SSE (Server-Sent Events)** ストリーミングを追加する。
     - 応答は既存の ACL・境界チェック・bounded dialogue 制限を**すべて通す**（省略禁止）。
     - キャンセル (`PH4A` で実装済み) と共存させる。キャンセル時にストリームを中断し、
       部分応答を履歴に残さない等の挙動は既存のキャンセル意味論に合わせる。
     - ストリーミングが使えないモデル/環境では既存の非ストリーム経路へ自動フォールバック。
     - 監査は既存の metadata-only 方式を維持する。
  3. フロントエンド: 段階描画（逐次追記）、取り消し中の表示、アクセシビリティ上の
     `aria-live="polite"` 等を既存の話者/メッセージ構造に沿って追加。
     UI ベースライン (`docs/planning/UI_IMPLEMENTATION_BASELINE.md`) の見た目と
     インタラクションを壊さない。
  4. 外部クラウド API の呼び出しは**禁止**（egress なし、ローカルのみ）。
     AI 生成物が「提案 (suggestion)」である旨の表示を維持する。
  5. テスト: ストリーミング経路の API テスト（SSE 断片、キャンセル中断、ACL 拒否時は
     ストリーム開始前 403）、Vitest 逐次描画テスト。既存テストの削除・緩和禁止。
- **Acceptance Criteria**:
  1. ローカル LLM 利用時、回答が段階的に表示される（合成テストで検証）。
  2. キャンセル済み質問のストリームが中断され、完了扱いにならない。
  3. 権限のない質問（プロジェクト外・非公開文書のみ参照）はストリームが開始されず拒否される。
  4. 関連テスト全部が green、既存機能（キュー・取消・引用）の退行がない。
  5. 許可パス外の変更なし。

- Summary:
  1. **アダプタ** (`local_model.py`): `generate()` に `on_delta` を追加。渡された場合のみ
     Ollama へ `stream: true` で要求し、NDJSON を 1 行ずつ検証して断片を返す。
     既存の非ストリーム経路（`stream: false`）は未変更で、`on_delta` 無しの呼び出しは完全に従来動作。
     検証は従来と同等（`model` 一致、`role=assistant`、`tool_calls` 拒否、identity エンコーディング、
     リダイレクト禁止、1MiB 上限、回答 20,000 文字上限、`done` 必須、空回答拒否）。
     `on_delta` が投げた例外は 502 に変換せずそのまま伝播させる（取消を「モデル障害」にしない）。
     `stream` を無視して単一 JSON を返すデーモンには、終端の改行なし本文を 1 断片として扱って
     **自動的に劣化動作**する（UI は一括表示、確定メッセージは同一）。
  2. **サービス** (`service.py`): `start_stream_chat()` が空きスロットを使うインライン対話のために
     `chat_jobs` 行を `running` で作る。これにより既存の取消 API (`PH4A`)・再起動スイープ・
     「1 会話に処理中 1 件」規則がそのまま適用される。待機列（queued）には入らない。
     `stream_stopped()` は取消要求・終了・消滅を 1 つの判定で返し、`finish_stream_chat()` は
     未コミット終了を閉じる（取消要求があれば `cancelled` が勝つ）。
     **`send()` は未変更**。すなわち権限・添付・引用の再確認、モデル I/O 中のトランザクション非保持、
     回答の単一アトミックコミットという既存の安全性はそのまま維持される。
  3. **API** (`main.py`): `POST /api/conversations/{id}/messages/stream` が SSE を返す。
     事象は `start`(job_id) → `delta`* → `message` | `cancelled` | `fallback` | `error`。
     送信前チェック（モデル未設定・セッション無し・スロット占有）では **SSE を開始せず 409** を返し、
     呼び出し側は通常の `POST /messages`（= 既存の待機列 202 経路）へ戻る。
     モデル呼び出しは別スレッドで実行し、断片はキュー経由で SSE 生成器が送出する。
     取消確認は 0.25 秒間隔に制限（トークンごとの DB 読取を避ける）。
     SSE 生成器にはモデル待機上限 +30 秒の上限を設け、応答を無期限に開かない。
     監査は既存のメタデータのみ（`chat.streaming` は job id のみ、本文を書かない）。
  4. **フロント** (`api.ts` / `App.tsx`): `streamRequest()` / `isEventStream()` / `streamEvents()` を追加。
     送信はまずストリームを試し、イベントストリームでなければ従来の `POST /messages` に自動フォールバックする
     （したがってブラウザ・サーバ・モデルのいずれが未対応でも挙動は従来どおり）。
     到着中の本文は既存の `aria-live="polite"` のメッセージ一覧内に追記表示し、
     進行中の交換に `aria-busy` を付ける（二重の live 領域は作らない）。
     「生成中の未検証の提案です」と明示し、確定後は通常のメッセージ（出典付き）に置き換える。
     ストリーミング中は `chat-jobs` ポーリングを停止する（SSE が唯一の進行情報源）。
     取消ボタンは既存の `cancelPendingJob()`（`DELETE /chat-jobs/{id}`）をそのまま使う。
  5. 外部クラウドへの送信は追加していない（接続先は `127.0.0.1:11434` 固定、`trust_env=False`）。
