## 3b. ループ基盤の封じ込め修復（2026-11-15）

ジョブを実際に流して判明した欠陥と修復。いずれもテストで固定済み（`tests/test_jobloop.py` 21 件）。

| 症状 | 原因 | 修復 |
|---|---|---|
| ワーカーが「実装した」と報告するのに作業ツリーが無変更で、**メインチェックアウトが変更されていた**（3 回） | 連結 worktree の `.git` はメインリポジトリを指すファイルで、セッションがそこをプロジェクト根と解決する | ジョブごとに**リポジトリ外のローカルクローン**を作る方式へ変更 |
| 同上（4 回目） | **ブリーフがメインチェックアウトのパスを名指し**していた。ワーカーは作業ディレクトリより指示に従う | ブリーフは自分のワークスペースのみを名指し、外部への書き込みを封じ込め違反として明示 |
| 失敗が検出できるのは「無変更」ゲートだけだった | 封じ込めを検証していなかった | dispatch 前後でメインチェックアウトを指紋比較し、差分があれば即 `blocked` でオーナーへ報告 |
| 長いブリーフでワーカーが起動できない | Windows のコマンドライン長上限 | ブリーフを標準入力で渡す |
| ゲートが Windows パスで失敗 | シェル経由の引用符 | コントローラ生成のゲートは引数配列で実行（シェルなし） |
| テンプレートの文字列をそのまま返した応答が「オーナー判断要求」になった | プレースホルダを質問として受理 | プレースホルダを検出して**試行失敗**として扱う |
| レビュー済みコミットがマージできない | コントローラ自身の進捗記録でチェックアウトが汚れていた | 記録のみを先にコミット、他人の未コミット変更があれば停止 |

封じ込めの逸脱で消費された試行は、ジョブの失敗ではないため `attempts` を戻している
（`PROTOCOL.md` §5.4 の趣旨。知見は `.agents/skills/job-isolation/SKILL.md` に固定）。

## 4. 進行管理

- ジョブ 1 件 = 実装（無料モデル）→ 決定論的ゲート（許可パス・保護パス・`test_cmd`・ruff・secret scan）
  → 別モデルの読取専用レビュー → Conventional Commit → 統合ブランチへ `--no-ff` マージ。
- 判断が必要になった時点でジョブは `blocked` になり、`OWNER_DECISIONS.md` に質問が追記される。
  他のジョブは止めない。
- 使用枠切れはモデルの失敗ではないため試行を消費せず、次の無料モデルへローテーションする。
- 運用手順は `docs/JOBLOOP.md`。
