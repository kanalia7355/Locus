# Task `T-PH5-102`: 参照に至る全経路で現行 ACL を証明する（`DATA-004`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `DATA-004 — Search and graph permission filters`
  （gap state `未着手`、remaining: "Implement and test current ACL at lexical/vector/graph
  neighbor, export, cache, job and model-context paths"）
- **Background**:
  - ベクトル・グラフ経路はプロトタイプに存在しない（将来拡張）。本タスクの対象は
    **現在存在する経路**に限る: 字句検索、関連資料、出典の原文・チャンク、会話履歴の再表示、
    待機ジョブ（`chat_jobs`）の実行、モデルに渡す文脈（`citations`）。
  - 個別の ACL テストは散在しているが、「どの経路でも**その時点の**権限で判定される」ことを
    経路網羅で示した証跡がない。権限を剥がしたあとに古い結果が漏れないことが要点。
- **Implementation Details**:
  1. 先に `backend/app/service.py` の `_can_read` / `_citations` / `documents` / `related` /
     `source` 相当の経路と `process_next_chat` / `send` を読み、**実際の経路名を列挙**すること。
  2. 新規ファイル `tests/test_retrieval_acl_paths.py` に、経路ごとに 1 つ以上の
     「権限変更後に漏れない」回帰テストを書く。少なくとも次を網羅する:
     - 字句検索（`documents` 相当）
     - 関連資料
     - 出典の原文・チャンク取得
     - 会話履歴の再表示（過去の生成回答のマスク）
     - 待機ジョブの実行時（投入後に権限が失効した場合）
     - モデルに渡す文脈（`generate` に渡る `citations`）
     権限の剥がし方は既存テストと同じ手段（メンバーシップ削除・公開取消・無効化・権限の明示拒否）を使う。
  3. **テストで欠陥が見つかった場合のみ** `backend/app/service.py` を最小修正する。
     修正が必要になった場合は REPORT に「どの経路が漏れていたか」を明記する。
     欠陥がなければコード変更なしで良い（その場合もテストは残す）。
  4. 既存テストの削除・緩和は禁止。新規テストはすべて「漏れたら落ちる」形で書くこと
     （権限を剥がす前に成功することも確認し、剥がした後に失敗することを確認する）。
- **Acceptance Criteria**:
  1. 列挙した 6 経路すべてに、権限失効後の非漏洩を検証する合成テストがある。
  2. 各テストは権限剥がし前の成功も確認している（空虚なテストではない）。
  3. `tests/test_security.py` に退行がない。
  4. コード修正を行った場合、その根拠（漏れた経路と再現手順）が REPORT にある。
  5. 変更は許可パス内に収まる。
