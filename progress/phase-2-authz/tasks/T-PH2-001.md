# Task `T-PH2-001`: 委任受領側 UI の改善と非委任権限者の作成操作ガード・文言整合

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `IAM-011`, `UI-008` (Owner Formal Decision Entry 6 / `DP-071` in `docs/plans/OWNER_DECISIONS_2026-11-10-ENTRIES.md`)
- **Worktree / Branch**: `task/T-PH2-001` (base: `phase/2-authz`)
- **Allowed Paths**:
  - `frontend/src/Delegations.tsx`
  - `frontend/src/Delegations.test.tsx`
  - `frontend/src/App.tsx`
  - `frontend/src/App.test.tsx`
  - `progress/phase-2-authz/tasks/T-PH2-001.md`
- **Implementation Details**:
  1. **非委任権限者（受領専任者）に対する委任作成フォームの制御 (`DP-071`)**:
     - 現在 `frontend/src/Delegations.tsx` (`AdminDelegations`) では、`options.projects` が空（＝本人が委任を付与できるプロジェクトが0件の一般利用者）であっても「管理委任を作成」フォーム全体が常時表示され、有効期間セレクト等が操作可能な状態になっている。
     - Owner Entry 6 (`DP-071`: 「権限がない操作を UI から実行できないようにし、委任の有効期限・付与元・権限範囲・失効状態・自己失効操作を利用者が理解できる UI」) に従い、`options && options.projects.length === 0` の場合は委任作成フォームを非表示にする（または「現在、他の利用者へ委任できるプロジェクト権限はありません。受領した委任の確認と取り消しのみ行えます。」等の明確な案内表示に切り替える）こと。
  2. **受領した委任と付与した委任の明確な識別・失効理由表示 (`DP-071`)**:
     - `frontend/src/Delegations.tsx` の委任一覧において、各委任が「受領した委任（付与元・権限範囲・有効期限・現在の状態/失効理由・自己失効操作）」か「付与した委任（受領者・権限範囲・有効期限・現在の状態/失効理由・取り消し操作）」かを一般利用者が一目で区別できるよう表示ラベル・構成を整理する（既存の aria-label や確認ダイアログの安全性・アクセシビリティ契約は維持すること）。
  3. **`frontend/src/App.tsx` の古い未実装文言の整合化**:
     - `frontend/src/App.tsx` 1696行目（`RoleEditor` 内）の `ロールは現在のプロジェクト内で有効です。管理権限の委任は無効です。` を、プロジェクトスコープの作業権限委任（管理権限自体は委任不可）の実態と矛盾しない正確な案内文言（例: `ロールは現在のプロジェクト内で有効です。管理操作の権限は委任できません。` 等、既存テストを壊さない表現）または適切な説明に整えること。
     - `frontend/src/App.tsx` 1311行目（`settings` ページ）の `LAN公開、回復、管理委任、保存期間は承認待ちです。` について、プロジェクト単位の管理委任は実装済みであり組織全体委任・本番運用項目が未承認であることを踏まえ、誤解を与えない表現に更新すること（既存の `App.test.tsx` 等のアサーションと整合させること）。
- **Acceptance Criteria**:
  1. 委任付与権限を持たない利用者（`options.projects` が空）で `AdminDelegations` を開いた際、委任作成フォームから作成操作を実行できず、受領した委任の閲覧（付与元・権限範囲・有効期限・失効状態）および自己失効（`DELETE /api/admin/delegations/{id}/cancel`）が明確に行えること。
  2. 委任付与権限を持つ利用者（`options.projects` が1件以上）では、従来通り委任の作成・付与者取り消し・受領委任の取り消しがすべて動作し、既存の `Delegations.test.tsx` の全ケースが通ること。
  3. 新規または更新した Vitest テストで、受領専任者（`options.projects: []`）が受領委任を確認・自己失効できること、および作成フォームが非活性/非表示であることを検証すること。
  4. `npm --prefix frontend test -- --run src/Delegations.test.tsx src/App.test.tsx` が全件 PASS すること。
- **Reviewer Model (実装モデルとは別モデルを指定)**: `unassigned`
