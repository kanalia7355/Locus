# Task `T-PH9-427`: どのモデルが実際に票を納めたかを、ループ自身に数えさせる

## SCOPE — レビュアーへ（先に読むこと）

**この票は数えるところまでである。** 集まった数を**使って順位を決めること**、
**`shift_check` で報告すること**は、どちらも**この票の範囲外**で、
データが溜まってから別票にする。レビューでそれらを要求しないこと。
`PREFERRED` の並びを触らないこと（それは `T-PH9-426`）。

## なぜこの票があるか

`roster.json` が各モデルについて持っているのは
`dispatches` `containment_stops` `cooldown_until` `exhausted_streak`
`unavailable_streak` `observations` `tool_incompatible` だけで、
**「このモデルが票を納めたか」は 1 件も記録されていない**（2026-11-27 05:17 実測）。

いっぽう `PREFERRED` のコメントは
「**capability** order for implementation work, best first」
「models we have **evidence** for」と書いている。
**その証拠が機構の中に無い。** だから 2026-11-27 05:18 に順位を決めるとき、
当番は **96 票の記録ファイルを手で数える**しかなかった
（`status: done` の票を `model:` ごとに数え、`attempts` を足す）。
`T-PH9-426` がその手集計の結果である。

`.jobloop/supervisor.log` には `delivered` / `attempt-failed` の行が 114 本あるが、
**どのモデルだったかを書いていない**ので結合できない。
手で数え直さずに済むようにするのがこの票である。

## Implementation Details

1. `jobloop/roster.py` に、引き渡しと失敗を 1 件ずつ数える仕組みを足す。
   既存の鍵の名前付けに合わせ、**新しい鍵を 2 つ**持たせる
   （例: 納めた数と、試行が失敗した数）。
   - **既存の鍵の意味を変えないこと。** `dispatches` `observations` は
     いまの意味のまま（古い記録が読めなくなる）。
   - `exhausted_streak` と紛らわしい名前を避けること。`roster.json` には
     読み手のいない `exhaustion_streak` が 1 件残っていて、
     **1 文字違いの鍵が実際に混乱を生んだ**（申し送り 2026-11-27 03:20）。
2. `jobloop/controller.py` の、結果が確定する箇所から 1 を呼ぶ。
   `delivered` と `attempt-failed` の**両方**を数えること
   （納めた数だけでは「3 回試して 1 回納めた」と「1 回で納めた」が区別できない）。
   - **`escalated`（訊いて止まった／判断待ち）は数えないこと。** あれはモデルの
     能力の話ではなく、票の側の問題である（試行も消費しない）。
   - 回転・枠切れ・CLI が起動しなかった場合も**数えないこと**（既存の
     `mark_exhausted` / `mark_unavailable` の領分）。
3. 記録に失敗しても**ジョブを止めないこと**。計器がジョブを落としてはならない。

## Acceptance Criteria

1. **修正を外すと落ちる検査**: 合成のジョブが納めたとき、そのモデルの
   「納めた数」が 1 増え、試行が失敗したとき「失敗の数」が 1 増える。
   どちらも `roster.json`（テストでは一時ファイル）に**永続する**こと。
2. **数えてはいけないものを数えていないこと**: `escalated`、回転、枠切れ、
   CLI 起動の失敗のそれぞれで、1 の 2 つの数が**どちらも増えない**。
3. **既存の記録が読めること**: 新しい鍵を持たない既存のエントリを読んでも
   例外にならず、既定値として 0 として扱われる。
4. **既存の鍵の意味が変わっていないこと**: `dispatches` `observations`
   `containment_stops` `exhausted_streak` `unavailable_streak` の
   増え方が従来どおりであることを表明する検査があること。
5. `python -m pytest tests/test_jobloop_roster_delivery.py tests/test_jobloop.py -q` が PASS。
   `tests/test_jobloop.py` は**作業前 108 passed / `def test_` 108 件**。
   **件数を減らさないこと**、作業後の件数を `## TEST` に貼ること。
