# Task `T-PH9-424`: 解けない `depends_on` が、票を黙って永久に止める

## SCOPE — レビュアーはここを先に読むこと（2026-11-26 22:22 当番）

- **依存の解決をフェーズ横断にする票ではない。** それは設計の変更であり、
  オーナー判断が要る。この票は**黙って止まるのをやめさせる**だけである。
- **いま止まっている 2 件は当番が手で直した**（`T-PH7-212` と `T-PH9-405` の
  `depends_on` から、別フェーズの id を外した）。**この票は再発を防ぐ側である。**

## 事実（2026-11-26 22:22、当番が実測）

`jobloop/tasks.py:118-127`:

```python
def unmet(self, task: Task) -> list[str]:
    status = {other.id: other.status for other in self.tasks}
    return [name for name in task.depends_on if status.get(name) != "done"]
```

`self.tasks` は**いま歩いているフェーズの票だけ**である。`supervise_loop` は
フェーズごとに別プロセスで `run` するので、他フェーズの票は見えない。
**見えない id は `status.get()` が `None` を返し、`None != "done"` なので
「満たされていない依存」として残り続ける。** 票は `todo` のまま
`waits for <その id>` と表示され、**何をしても永久に派遣されない。**

実際に止まっていた 2 件:

```text
T-PH7-212  (heavy, 0/3)  depends_on: T-PH7-211, T-PH9-422
    → T-PH9-422 は 20:48 に done。それでも waits for T-PH9-422 と出ていた
T-PH9-405  (light, 0/3)  depends_on: T-PH6-127
    → T-PH6-127 は done。一度も派遣されないまま、誰も気付いていなかった
```

**`T-PH7-212` は当番が 19:19 に自分で付けて踏んだ。`T-PH9-405` のほうは
それより前からで、気付かれていなかった。** リポジトリ全体を走査して、
この形はこの 2 件だけだった。

**なぜ危ないか**: 綴り間違いでも同じことが起きる。`depends_on: T-PH6-1227`
と書けば、その票は二度と動かず、`status` の表示は「待っている」と言うだけで
**待っている相手が存在しないことを誰も教えてくれない。**

## 要件への批判（実装者はここに答えること）

1. **既存の正しい依存を 1 つも壊さないこと。** 同じフェーズ内の
   `depends_on` は今までどおり効かなければならない。`progress/phase-*/` の
   実データで、いま `ready` な票が `ready` のままであることを示すこと。
2. **「無視して通す」と「声を上げる」のどちらにするかを自分で決めて、
   理由を報告に書くこと。** 黙って通すと、本当に他フェーズの成果を待つ票が
   早く走って失敗する。黙って止めるのが今の挙動である。
   **当番の推奨は「止めたままにして、理由を見えるところに出す」** ——
   解決できない依存だと分かる形にすること。どちらを選んでも、
   **選んだ理由を報告に書くこと。**
3. **`status` の表示を変えるなら、人が読んで原因が分かる言葉にすること。**
   `waits for T-PH9-422` では、それが「まだ終わっていない」のか
   「このフェーズから見えない」のか区別が付かない。**この区別が付くことが
   この票の値打ちである。**
4. 新しい検査は `tests/test_jobloop_depends.py` に書くこと。
   `tests/test_jobloop.py` はいま `T-PH9-421` が握っている。

## 受入条件

1. 同じフェーズ内に存在しない id を `depends_on` に持つ票について、
   `status` の出力（または同等の記録）が**「このフェーズから解決できない」と
   読み取れる**こと。`waits for <id>` とだけ出る今の形は不可。
2. その票が**黙って `ready` になってしまわない**こと（勝手に依存を
   無視して派遣しない）。
3. 同じフェーズ内の `depends_on` の挙動が 1 つも変わらないこと。
   `done` の依存は満たされ、`todo` の依存は満たされない。
4. 綴り間違い（存在しない id）と、他フェーズの実在する id の 2 つを
   検査で区別して示すこと。**どちらも「解決できない」側に落ちることを
   示せばよい** —— この票で両者を区別する必要は無い。
5. `tests/test_jobloop_depends.py` に、(a) 同フェーズの `done` 依存が通る、
   (b) 同フェーズの `todo` 依存が止まる、(c) 解決できない id が
   「解決できない」と分かる形で止まる、の 3 つを示す検査が有る。
6. 既存テストの削除・skip・緩和が 1 つも無い。変更は許可パス内に収まる。

## 当番の申し送り

**フェーズを跨いで待たせたいときの正しいやり方は、`depends_on` ではなく
`status: blocked` である**（当番が手で戻す）。これは `T-PH7-212` の
22:22 のメモにも書いた。この票が通れば、同じ間違いをしても**気付ける**。
