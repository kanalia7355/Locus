# Task `T-PH9-413`: 監督は 1 台だけ動く。止めろと言われたら速やかに止まる

## SCOPE — レビュアーへ（先に読むこと）

- **「2 台目は黙って終わる」にしないこと。** 起動を断るときは**理由と先に走っている
  PID を印字して**終わること。黙って終わると、起動したつもりの人が
  「動いている」と誤解する（それが 2026-11-18 に 17 時間を失った型である）。
- **古い鍵（stale lock）で永久に起動できなくなってはいけない。** 書いた PID の
  プロセスが**もう居なければ、鍵は無効として奪う**こと。受入条件 3 がそれを固定する。
- **待機の方針（`T-PH9-408` / `T-PH9-410`）には触らないこと。**
  変えるのは「待っている間に止まれるか」だけである。

## TASK DEFINITION (Assigned by Orchestrator, 2026-11-24 14:40)

- **なぜこの票があるか（2026-11-24 14:32 に私が起こした事故）**:
  **監督が 4 台同時に走っていた。**

  ```
  PID 35300  12:28:33  supervise_loop

  PID 11252  14:32:39  supervise_loop
  ```

  3 台は現に `jobloop run` の子を持って**同時にサイクルを回していた**
  （14:00:15・14:06:52・14:32:39）。`supervise_loop` の docstring は
  「フェーズを 1 つずつ歩くのは意図的である。どのフェーズも同じチェックアウトの
  同じ統合ブランチへマージするので、2 台が同時に走れば**1 つのリポジトリで
  2 つのプロセスが git 操作をする**ことになる」と明記している。
  **その禁止事項が 4 重に破られていた。**

- **なぜそうなったか（仕組みの側の原因。私の不注意だけではない）**:
  1. 停止は `.jobloop/stop` を**サイクルの前に 1 回**見るだけである。
     アイドル時の待機は `time.sleep(waiting)` で、`waiting` は最大 **1200 秒**。
     つまり**置いてから最大 20 分、止まらない**。
  2. 私はその 20 分を待たずにマーカーを外し、新しい監督を立てた。
     古い監督は**マーカーを一度も見ずに**眠りから覚めて走り続けた。
  3. **二重起動を防ぐ仕組みが無い。** だから 3 回繰り返して 4 台になった。
- **何を疑わせたか（今夜の損失）**: 21:32 以降に繰り返した
  「ワークスペースは空なのに作業が本体にある」「別の票の製品コードが本体に現れる」
  「`integration branch is dirty` が数分おきに出る」は、
  **複数の監督が同じチェックアウトで同時に派遣・マージしていた**ことで
  説明が付く。私は `T-PH9-406`（記録が本体パスを教える）を原因として起票したが、
  **少なくとも一部はこの二重起動が原因だった可能性が高い**。
  この票が入ったあと、同じ形が止まるかどうかを観測する価値がある。

- **Implementation Details**:
  1. **起動時に単一実行の鍵を取る**（`.jobloop/` の下に PID を書く形でよい）。
     既に生きている監督が居たら、**その PID を印字して**起動を断る。
  2. **鍵は死んだら奪える**こと。書かれた PID が存在しなければ、
     古い鍵として上書きする。終了時（通常終了・`stop`・例外）には**外す**こと。
  3. **待機中も `stop` を見る。** 長い `sleep` を短い刻みに分け、
     刻みごとに `.jobloop/stop` を確認して、置かれていれば**その場で抜ける**。
     刻みの長さは定数にして名前を付けること（数秒〜十数秒で十分である）。
  4. 心拍に「起動を断った」「`stop` を見て抜けた」を**1 行ずつ残す**こと。

## Acceptance Criteria

   現在の実装は 2 台目がそのまま走り出すので落ちる。
2. **修正を外すと落ちる検査（その 2）**: 長い待機の最中に `.jobloop/stop` を置くと、
   **刻みの長さ程度で**抜けること（1200 秒待たないこと）。
3. **直しすぎていないことの検査**:
   - 鍵に書かれた PID が**存在しない**場合は、起動できること（古い鍵で詰まらない）。
   - 通常終了・`stop`・例外のいずれでも鍵が残らないこと。
   - `stop` が無い限り、待機の**合計時間**は `T-PH9-408` が決めた値から変わらないこと
     （刻みに分けただけで、速く叩くようになっていないこと）。
4. 心拍に「断った」「抜けた」が記録されること。
5. `python -m pytest tests/test_jobloop.py -q` が PASS。

On Windows, `pid_alive()` uses `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` and `GetExitCodeProcess` (`STILL_ACTIVE == 259`, treating `ERROR_ACCESS_denied` as alive); on POSIX it uses `os.kill(pid, 0)`.

  - When the lock file holds a non-existent (stale) or unreadable PID, `acquire_lock()` reclaims it cleanly. `release_lock()` runs in a `try ... finally` block so the lock is removed on normal cycle completion, `.jobloop/stop`, and unhandled exceptions.
  - Added `STOP_POLL_SECONDS = 5.0` and `wait_or_stop(seconds, stop, step=STOP_POLL_SECONDS)` to break inter-cycle sleeps into 5-second slices, checking `.jobloop/stop` on every slice while preserving the exact total wait duration determined by `idle_wait()` / `--pause` (`T-PH9-408` / `T-PH9-410`) when `stop` is absent.
