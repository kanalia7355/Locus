# Task `T-PH9-414`: 自分のコミットがもうマージできない票を、永久に回し続けない

## SCOPE — レビュアーへ（先に読むこと）

- **`refresh()` の「進んでいるワークスペースはリセットしない」判断は正しい。壊さないこと。**
  2026-11-21 にレビュー済み 5 件（`T-PH6-104`・`T-PH7-201`・`T-PH7-223`・`T-PH8-301`・
  `T-PH8-302`）を消した事故への対策である。この票は**その拒否を撤回する票ではない**。
  拒否したまま、その先で詰まらないようにする票である。
- **コミットを捨てる実装は不可。** 捨てずに退避してから基点を移すこと。
- 無人実行で基点を**自動的に**移してよいかは、この票では決めない。
  この票の仕事は「永久に繰り返さない」ことと「人が測り直さずに決められる記録を出す」ことまで。

## TASK DEFINITION (Assigned by Orchestrator)

- **なぜこの票があるか**: `review` にある票の自分のコミットが統合ブランチにもう
  マージできなくなると、ループは**何も escalate せずに同じ失敗を永久に繰り返す**。
  経路は 3 つの正しい判断の組み合わせで、どれ一つも単独では欠陥ではない。

  1. `Controller.refresh()` は、ワークスペースが `behind > 0` かつ `ahead > 0` のとき
     リセットを拒否し、`WORKSPACE NOT REBASED` を記録する（上記の事故対策。正しい）。
  2. 古い木でゲートを再実行すると**通る**（その木の中では整合しているため）。
  3. マージだけが衝突し、`escalated - the merge conflicted` として人に回る。

  そして**人が書ける裁定には、これを解く手段が無い**。状態を `doing` に戻しても
  `refresh()` は依然として拒否するので、基点は動かない。`resume` は試行を消費しないので、
  試行上限にも周回上限にも当たらず、`diagnose` にも「繰り返している」とは出ない。

- **Implementation Details**:
  1. **同じ失敗を繰り返さない。** ある票のワークスペースが `behind > 0` かつ `ahead > 0` で、
     **その ahead のコミットでのマージが既に衝突として記録されている**とき、
     次のサイクルで**ゲートを再実行しない**こと。古い木のゲートが通ることは分かっており、
     通っても結果は変わらないため（`no-reviewer` の判断が「分かっていることを確かめ直さない」
     としているのと同じ理由）。
  2. **人が測り直さずに決められる記録を出す。** 衝突で escalate するときの記録に、
     少なくとも次を入れること。いま人が手で測っている値である。
     - 基点のコミットと日時、統合ブランチに対する **commits 遅れ**
     - その票自身の変更（`merge-base..HEAD` の `diff --stat`。
       **`FETCH_HEAD..HEAD` ではない** — 2 つの先端の比較になり、他票の変更が混ざる）
     - 退避先の ref 名（下記 3）
  3. **コミットを捨てずに退避する。** 基点を移す前に、その票自身のコミットを
     ワークスペース内の ref（タグでよい）に残すこと。手作業では
     `stale/<票 ID>-<MMDD>` を使った。`git show` で元の変更が読めること。
  4. `jobloop/controller.py` と `tests/test_jobloop.py` の 2 ファイルで収まる見込み。
     `T-PH9-406` が同じ 2 ファイルを触るので、**この票は 406 の後に走る**
     （`depends_on` に入れてある）。

## ACCEPTANCE CRITERIA

1. `behind > 0` かつ `ahead > 0` で、その ahead のコミットのマージが既に衝突として
   記録されている票に対し、**次のサイクルでゲートが再実行されないこと**を示す試験がある。
2. 基点を移す経路を通ったとき、**その票自身のコミットが ref として残っている**ことを
   示す試験がある（`git show <ref>` が元の変更を返す）。捨てる実装は不可。
3. 基点を移したあと、`refresh()` が `behind=0` / `ahead=0` と判定することを示す試験がある。
4. 衝突の escalate 記録に、基点の日時・**commits 遅れ**・`merge-base..HEAD` の変更量・
   退避 ref 名が入っていることを示す試験がある。
5. `refresh()` の既存の防御（clean tree かつ ahead なしの両方が成り立つときだけリセットする）
   が**壊れていない**ことを示す既存試験が通り続けること。
6. `python -m pytest tests/test_jobloop.py -q` が緑。
7. `python -m ruff check jobloop tests` と `python -m ruff format --check jobloop tests` が緑。
