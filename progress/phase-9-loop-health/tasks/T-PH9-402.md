# Task `T-PH9-402`: 生き残った `serve --stdio` を孤児として見えるようにする

## TASK DEFINITION (Assigned by Orchestrator, 2026-11-23 19:27)

- **なぜこの票があるか**: `scripts/shift_check.py` の孤児検査が、
  **木の生き残りという一番高くついた形を構造的に見られない**。
  `live` の各プロセスは

  ```python
  session = "run --standalone" in command
  ```

  で印を付けられ、`orphans()` は `if session and not running(parent)` だけを見る。
  実測したプロセスの形はこうである。

  ```
  PID 43464  parent 3608 (cmd.exe)   opencode.exe run --standalone --model ... --format json
  PID 35868  parent 43464            opencode.exe serve --stdio --port 0
  ```

  **`serve --stdio` の側は `session` が偽**なので、起動役（`run --standalone`）が
  死んで `serve` が生き残った木は、親が居なくなっても
  `orphans()` から見えない。これは 2026-11-20 に 1 件のジョブと 2 時間を
  失った形そのものである（`opencode run` は起動役で、直接の子だけ殺すと
  木が生き残り、継承した標準出力を握ってコントローラを塞ぐ)。

- **今日それが起きた記録**:
  1. 18:50 に親を失った木（根 PID 37000、子孫 25 前後）を落としたが、
     `taskkill /T /F` が**数個の PID で「終了できませんでした」を返した**。
  2. 19:23 の `shift_check.py` は `ok  no orphaned worker` と印字した。
  3. その 2 分後に `opencode.exe` PID 4200（19:09:42 生成、親 PID 35488 は既に無し、
     子孫を含め 4 プロセス）が**生きているのを見つけた**。
  4. 19:12 に本体チェックアウトへ `REPORT.md`（`T-PH5-101` の報告文。
     同票は 11-15 に `done`）が現れ、**無関係な `T-PH6-127` が封じ込めで停止した**
     （その裁定は `progress/phase-6-extensions/tasks/T-PH6-127.md`）。
  5. PID 4200 の木を落として復旧した。

  2 と 3 の間に親が死んだ可能性は**排除できない**。だからこの票は
  「検査が嘘をついた」ではなく、**「検査が見られない形がある」**を直す。
  見られない形は上のコードから読めるので、これは推測ではない。

- **Implementation Details**:
  1. 孤児の判定を、`run --standalone` という**文字列ではなくワーカーの木**で行う。
     `opencode.exe` のうち、`serve --stdio` であっても
     **親 PID が存在しない**ものは孤児である。
  2. **誤検知を増やさないこと。** 2026-11-22 に、`python.exe`/`opencode.exe` に
     絞った一覧の中に親が居るかで判定したせいで、
     `cmd.exe` 経由で起動された**作業中の**ワーカーを全部孤児と呼び、
     11 分走っていたジョブを `taskkill` させた。親の生存は
     **`running(pid)` で id を引いて確かめる**（一覧の membership で判定しない）。
     `orphans()` の docstring にその経緯が書いてあるので消さないこと。
  3. 報告には **PID・生成時刻・どの形（`run` か `serve` か）** を出す。
     読む人が `taskkill /PID <id> /T /F` に渡せること。
