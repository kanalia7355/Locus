# Task `T-PH9-412`: いま GitHub CI を赤くしている型エラーを消す

## SCOPE — レビュアーへ（先に読むこと）

- **挙動を変えないこと。** これは型注釈の修正だけである。冷却の長さ、
  封じ込めの計数、`diagnose` への差し込みといった**振る舞いに触ってはいけない**。
  振る舞いを変える票は別にある（`T-PH9-409`）。
- **`strict = true` を緩めないこと。** `pyproject.toml` の `[tool.mypy]` は
  `strict = true` で、CI がその設定で回している。`# type: ignore` の乱用や
  設定の緩和で通すのは**この票の受入条件を満たさない**。
  直し方は `cast` か、明示的な型での受け取りである。
- **`T-PH9-410` と同じファイルを触る**ので `depends_on` に入れてある。

## TASK DEFINITION (Assigned by Orchestrator, 2026-11-24 14:00)

- **なぜこの票があるか**: GitHub CI の `Prototype quality`（`.github/workflows/quality.yml`）
  は `scripts/verify.py --e2e --audit` を回し、その中に

  ```
  ("python-types", [sys.executable, "-m", "mypy", "backend/app", "jobloop"], ROOT, 180)
  ```

  がある。**`jobloop/` は CI の strict mypy の対象である。**
  ところが**ジョブのゲートは mypy を 1 度も回していない**
  （`jobloop/gates.py` に `mypy` の文字が無い。ruff は
  `["backend", "tests", "scripts", "jobloop"]` と CI と同じ範囲で回しているのに、
  mypy だけが抜けている）。
  だから**型エラーはゲートを通り、CI だけが赤くなる**。
- **証拠（独立のレビュアーが記録した実測）**: `T-PH9-404` のレビューは
  こう書いて承認した。

  > Low: `jobloop/roster.py:301-316` — the patched `survey`/`report` helpers still
  > return `Any` from `original_survey(...)`/`original_report(...)` calls, so mypy
  > reports `no-any-return` on lines 304, 315, 316 (plus the pre-existing one on
  > line 162).
  > … mypy is not a configured gate for this task, so the residual
  > `no-any-return` errors above were not treated as blocking.

  **「この票のゲートではない」は正しい。しかし CI のゲートではある。**
  そして `T-PH9-404` は **2026-11-24 にマージされた**（`a4dc40b`）ので、
  この 3 件はいま統合ブランチに乗っている。
  4 件目（レビューが「既存」と呼んだもの）は、それより前から乗っている。
- **直す場所（現在の行で特定済み）**:
  1. **`Roster._state()`（`jobloop/roster.py:83`）** —
     `-> dict[str, dict[str, float]]` と宣言しているが、返しているのは
     `json.loads(...)` の結果を `isinstance(loaded, dict)` で絞っただけのもので、
     mypy から見れば `dict[Any, Any]`。これがレビューの言う「既存」の 1 件である。
  2. **`survey`（`jobloop/roster.py:323`）** — `-> list[Any]` と宣言して
     `original_survey(...)`（`getattr` 由来なので `Any`）を返している。
  3. **`report`（`jobloop/roster.py:331`）** — `-> str` と宣言して
     `original_report(...)` を返している。
  4. **`_containment_report_from_disk`（`jobloop/roster.py:293`）** —
     `-> str` だが、`json.loads` 由来の値を経由している。
     **mypy が何を言うかを自分で確かめてから直すこと**（上の 3 件で足りるなら触らない）。
- **やり方**:
  - `json.loads` の結果は**一度明示の型で受ける**（例: `cast(dict[str, dict[str, float]], loaded)`）。
    ただし `cast` は嘘をつける道具なので、**`isinstance` の確認を外さないこと**。
    確認を残したうえで型を名乗る。
  - `getattr` で取り出した関数は、**呼び出し結果を明示の型で受ける**。
  - **行番号はマージで動く。** 上の番号は 2026-11-24 14:00 時点のものなので、
    `python -m mypy backend/app jobloop` の出力を自分で読んで対象を決めること。

## Acceptance Criteria

1. **`python -m mypy backend/app jobloop` が 1 件もエラーを出さないこと**（これがこの票の本体）。
   件数ではなく**0 件**を報告すること。
2. **`pyproject.toml` を変更していないこと**（`strict` を緩めていないこと）。
   `# type: ignore` を足した場合は、**1 件ずつ理由を報告**すること
   （理由の無い `ignore` は受入条件を満たさない）。
3. **振る舞いが変わっていないこと**: `python -m pytest tests/test_jobloop.py
   tests/test_diagnose.py tests/test_selfrepair.py -q` が PASS し、
   既存の検査を 1 つも削除・skip・緩和していないこと。
4. `isinstance` などの実行時の確認を外していないこと（型を名乗るだけにしないこと）。
5. 直した箇所を**1 件ずつ**、mypy が何と言っていたかと併せて報告すること。
