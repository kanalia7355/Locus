## これは既知の原因で、対策は既に入っている

`jobloop/worker.py` の `run_opencode` のコメントがこう書いている
（引用、2026 年のいつかの実測）。

> `--standalone` is what makes the worktree the session's working directory.
> Without it the CLI reuses a background service whose directory is wherever
> it was first started, and a worker edits the main checkout instead of its
> own worktree — observed, not theoretical.

**そして `--standalone` は現に渡されている。** 渡しているのに同じ症状が
4 回出た。つまり**対策が効いていない**か、**別の経路がある**。
これを突き止めるのがこの票である。

参考として、第 2 段（`run_agy`）のコメントは
「agy はプロセスの作業ディレクトリを取るので `--standalone` に相当する
忘れ物は無い。**セッションの `init` イベントが worktree を報告した**」と
書いている —— つまり**セッションが自分の作業ディレクトリを報告する経路は
存在する**。

## 要件への批判（実装者はここに答えること）

1. **原因を当てずに直さないこと。** まず `--standalone` を渡した
   `opencode run` のセッションが**どのディレクトリを自分の作業場所だと
   思っているか**を測ること。`--format json` の出力か、session の init
   相当のイベントに出ているなら、それを根拠にすること。
   **出ていないなら「出ていない」と報告すること** —— その場合、
   この票の直し方は 2 の防御側だけになる。
2. **防御は「気付いて止める」であること。** 本体チェックアウトのファイルを
   消す処理をこの票に入れてはいけない（それは `T-PH9-421`）。
   ここで入れるのは、**派遣を始める前か始めた直後に、セッションの
   作業ディレクトリがワークスペースでないと分かったら、仕事をさせずに
   終わらせる**判定である。
3. **`Ending` のどれを返すかを決めて、理由を報告に書くこと。**
   試行を消費してよいのか（`EXHAUSTED` / `OUTAGE` は消費しない）。
   ワーカーの落ち度なのか環境の落ち度なのかで答えが変わる。
   **どちらだと判断したかを書くこと。**
4. **偽陰性より偽陽性が怖い。** 「作業ディレクトリが違う」と誤判定して
   正常な派遣を殺すと、今日 5 件のマージを生んだ経路が止まる。
   パスの比較は正規化（大文字小文字、`\` と `/`、短縮名）を踏むこと。
   Windows である。

## 受入条件

1. `opencode run --standalone` のセッションが報告する作業ディレクトリを
   読む経路が有るかどうかを**測って報告している**。有る場合はその値を
   ワークスペースと比較している。無い場合は「無い」と報告している。
2. 作業ディレクトリがワークスペースでないと判定できた場合、ワーカーに
   仕事をさせずに `Result` を返す。**本体チェックアウトのファイルを
   読み書きしない。**
3. 返す `Ending` と、それが試行を消費するかしないかが、報告で説明されて
   いる（決めた側に `tests` が有る）。
4. 判定のパス比較が正規化を踏んでいる。`tests/test_jobloop_worker_cwd.py` に
   (a) 大文字小文字だけ違う、(b) 区切りが `\` と `/` で違う、
   (c) 本当に別のディレクトリ、の 3 つを与えて、
   **(a) と (b) は同じ場所と見なし、(c) だけ止める**ことを示す検査が有る。
5. `--standalone` が渡されていることを固定する検査が有る
   （コマンド列に含まれること）。外す変更への歯止めである。
6. 既存テストの削除・skip・緩和が 1 つも無い。変更は許可パス内に収まる。
