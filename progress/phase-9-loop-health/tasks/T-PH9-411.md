# Task `T-PH9-411`: 全体の秘密走査がコマンドライン長で落ちるのを直す

## SCOPE — レビュアーへ（先に読むこと）

- **走査の範囲を狭めて通すのは禁止である。** 「引数が多いから `--all-files` だけにする」
  「追跡ファイルの一部だけ見る」は**検出を減らす方向**で、この票の目的に反する。
  見る対象は今までと**同じ集合**でなければならない。受入条件 2 がそれを固定する。
- **`SYNTHETIC` の完全一致の集合と `EXCLUDED` の除外規則は 1 文字も変えないこと。**
  鍵らしい文字列を検査に植えるための閉じた集合であり、
  `tests/test_secret_scan.py` が「集合の外は落ちる」ことを固定している。

## TASK DEFINITION (Assigned by Orchestrator, 2026-11-24 14:35)

- **なぜこの票があるか（2026-11-24 14:30 の実測）**:
  `python scripts/secret_scan.py` を引数なしで走らせると、**落ちる**。

  ```
  FileNotFoundError: [WinError 206] ファイル名または拡張子が長すぎます。
  ```

  `scan()` は `git ls-files` で得た**追跡ファイルを 1 件ずつコマンドライン引数**に
  並べて `detect_secrets` を起動する（`*paths`）。測った:

  | 項目 | 値 |
  |---|---|
  | 追跡ファイル数 | **808** |
  | `./<path>` を並べた概算バイト数 | **32,213** |
  | Windows のコマンドライン上限 | 約 **32,767** |

  これに固定の引数（インタプリタの絶対パス、`-m detect_secrets`、`-c 2`、
  `scan`、`--all-files`、`--no-verify`、`--exclude-files <正規表現>`、
  `--exclude-secrets <正規表現>`）が加わって**上限を越えた**。
  **今日越えたばかり**で、票を 1 件足すたびに悪化する。
- **なぜ重いか**: これは**オーケストレーターがシフトを閉じる前に手で回す検査**である。
  ジョブのゲートは「そのジョブが変更したパスだけ」を見る設計なので、
  **シフトが書いた記録（裁定・票）は全体走査でしか見られない**。
  2026-11-22 には、私が裁定に鍵の形をした文字列を貼ってしまい、
  それが 2 時間赤のまま残って `T-STC-001` を止めた。**その再発を防ぐ唯一の検査である。**
  いま、それが動かない。
- **幸い、嘘はつかなかった**: 黙って 0 件と報告するのではなく
  **例外で落ちた**ので気付けた。この性質は保つこと
  （走査できなかったときに成功を返してはならない）。
- **Implementation Details**:
  1. パスを**分割して複数回起動**し、結果を合わせる
     （1 回あたりの引数長が上限に収まるようにする。余裕を見ること）。
  2. **走査する集合は変えない。** 分割の境界で取りこぼさないこと。
  3. **分割の単位をファイル数ではなく長さで決める**こと
     （パスの長さはばらばらなので、件数では上限を保証できない）。
  4. 走査できなかった場合は、**0 件ではなく失敗を返す**こと（現在の性質を保つ）。
  5. 1 回で収まる環境では**挙動を変えない**こと。

## Acceptance Criteria

1. **修正を外すと落ちる検査**: 引数長が上限を越える数のパスを与えると、
   **現在の実装は例外で落ち、修正後は走査が完了する**こと。
   （上限は実行環境に依らず検査できるよう、長さの閾値を注入できる形にする。）
2. **範囲を狭めていないことの検査**: 分割して走査した結果の集合が、
   1 回で走査した場合と**同一**であること。境界で取りこぼさないことを固定する。
3. **走査できなければ失敗を返すことの検査**: スキャナの起動に失敗したときに
   0 件成功を返さないこと。
4. `SYNTHETIC` / `EXCLUDED` の値と、「集合の外の鍵らしい文字列は落ちる」挙動が
   変わっていないこと。
5. `python -m pytest tests/test_secret_scan.py -q` が PASS。
