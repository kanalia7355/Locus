**オーケストレーターが実装を読んで、どちらも本物だと確かめてある。**

1. **非有限の `cooldown_until` が最短の冷却を覆い隠す。**
   `cooldown_wait` は `remaining <= 0` で過去の記録を弾くが、`until` が
   `NaN` だと `remaining <= 0` は**偽**になるので `wait = nan` が通る。
   `soonest is None` のときに `soonest = nan` となり、以後
   `wait < nan` は常に偽なので、**本当に近い冷却が二度と採用されない**。
   Python の `json` は `NaN` / `Infinity` を既定で受け付けるため、
   壊れた（あるいは手で触られた）ロスターで現実に起こりうる。
2. **`UnicodeDecodeError` でアイドル経路が落ちる。**
   `Roster._state()` は `(OSError, json.JSONDecodeError)` しか捕まえない。
   UTF-8 として読めないロスターはそのどちらでもない例外を投げ、
   `idle_wait` → `cooldown_wait` → `_state()` の経路で**監督が落ちる**。
   `supervise_loop` にある `installed_models()` の `try/except` は
   **この呼び出しを覆っていない**（`idle_wait` はその外側にある）。

- **Implementation Details**:
  1. 非有限の値（`NaN` / `±Infinity`）を持つ記録は**飛ばす**（`math.isfinite`）。
  2. ロスターの読み取りが**どんな例外でも**落ちないようにする。
     `Roster._state()` 側で受けるのが筋（読めないロスターは「記録が無い」と同じ）。
  3. 落ちなかった代わりに**沈黙しないこと**。読めなかった事実を 1 行残す。
  4. 冷却の意味・待機の方針は変えない。
