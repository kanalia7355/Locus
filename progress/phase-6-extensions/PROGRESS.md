### 進行中の障害

`T-PH6-103` は封じ込め違反で `blocked`。ワーカーが自分のクローンではなく
メインチェックアウトに書いた。逃げた変更は破棄し、チェックアウトは復元済み
（`tests/test_api.py` 22 件 green を確認）。根本原因は未特定で、1 回目の試行が
**900 秒 timeout** で終わっている点が手がかり。コントローラ側の固めは Claude Code が
直接行う（走っているループに自分自身の改修をさせない）。

`T-PH6-104` と `T-PH6-106` は `allowed_paths` を `未確定` にしてある。これは
**セキュリティ境界の設計が先**という意味で、ループは未確定スコープのジョブを拾わない
（`tasks.py` の `allowed_paths`）。`T-PH6-104` の設計が通ってから両方のスコープを確定する。

## 5. 進行管理

- 1 ジョブ = 実装（無料モデル）→ 決定論的ゲート（許可パス・保護パス・`test_cmd`・ruff・
  secret scan）→ 別モデルの読取専用レビュー → Conventional Commit → 統合ブランチへ `--no-ff`。
- オーナー決定 2026-11-16 により、**無人での自動実行**と、別モデルのレビュー合格を
  独立した合格として扱うことが許可された。`main` への合流も許可されている。
  手順は「統合ブランチで全ジョブ done → CI green → PR → CI green を確認してマージ」に一本化する。
  `main` への直接 push・履歴の書き換え・CI の迂回は行わない。
- セキュリティ境界に触れるジョブ（`T-PH6-104` `T-PH6-106`、Runner 一式）は、
  無料モデルに実装させる前に Claude Code が設計を書き、受入条件を具体化してから出す。
