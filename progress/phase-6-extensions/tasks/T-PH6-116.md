# Task `T-PH6-116`: 出典モーダルを `<dialog>` に移し、自前のフォーカストラップを撤去する

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`「`ui-components/dialog`」
  （`GoogleChrome/modern-web-guidance`）。
- **Background**:
  - 出典の原文を出すモーダルは `App.tsx:1457-1503` にあり、
    `div.modal-backdrop` + `section[role="dialog"][aria-modal="true"]` の自前実装。
    Tab の巡回を **35 行の `onKeyDown`** で手書きしており、
    `querySelectorAll` で可視の操作対象を集めて先頭と末尾を繋いでいる。
  - ネイティブの `<dialog>` を `showModal()` で開けば、背景の `inert` 化・
    フォーカスの封じ込め・Esc での閉じ・`::backdrop`・最前面レイヤが**全部無償**で付く。
    `<dialog>` は 2022-03 以降広く利用可能（Safari 15.4 / Firefox 98）で、
    対応状況の心配は無い。
  - 自前のトラップは可視判定まで見ている分だけ丁寧だが、`inert` な領域の扱い、
    シャドウ境界、ブラウザの UI（アドレスバー）へのフォーカス移動は再現できていない。
    自分で書く理由が無い。
  - **先に設定ダイアログ（`T-PH6-112`）でやらない理由**: あちらは `App.tsx` の構造変更を
    伴う重いジョブで、同時にやると差分がレビュー不能になる。既にある小さなモーダル 1 つで
    作法を確定させ、`T-PH6-112` はそれに倣う（`T-PH6-112` の修正指示 A に記載済み）。
- **Implementation Details**:
  1. `div.modal-backdrop` + `section[role="dialog"]` を `<dialog>` 1 つに置き換える。
     表示・非表示は `open` 属性や React の条件分岐ではなく、
     **`showModal()` / `close()`** で行う（`show()` は使わない。モーダルにならない）。
  2. **`role="dialog"` と `aria-modal="true"` を自分で書かない。**
     ネイティブの modal に付けると読み上げが二重になる（ガイドの明示的な禁止事項）。
     名前は `aria-label="出典の原文"` を残すか、見出しに `id` を付けて
     `aria-labelledby` で結ぶ。どちらでもよいが名前を失わせないこと。
  3. **自前の Tab 巡回（`onKeyDown` の `Tab` 分岐）と Esc 分岐を削除する。**
     両方ネイティブが行う。削除後に手で挙動が落ちていないことを確認すること。
  4. 「閉じる」ボタンは `<form method="dialog">` で包めば JS 不要。
     開いた直後の初期フォーカスは `autofocus` を「閉じる」ボタンに置く
     （既存の `sourceClose` ref による手動フォーカスは不要になる）。
  5. 背景クリックで閉じる挙動は維持する。`closedby="any"` を付けるが、
     **Safari が `closedby` 未対応なので背景クリックの JS フォールバックを残す**
     （`dialog` 自身への `click` で、クリック座標が内容の矩形外なら `close()`）。
     属性だけに頼って既存の挙動を落としてはいけない。
  6. CSS に次を足す。`html` / `body` へ `overflow: hidden` を当てる手口は使わない。
     ```css
     dialog:modal { overscroll-behavior: contain; }
     dialog::backdrop { overflow: hidden; overscroll-behavior: contain; }
     ```
     `@supports` や `CSS.supports()` でこの機能を判定しないこと
     （全ブラウザが対応を名乗るため判定が意味を持たない。ガイドの注意）。
  7. `::backdrop` の色は既存トークン `--color-backdrop` を使う。新しい色を導入しない。
  8. 入場アニメーション（`@starting-style` + `transition-behavior: allow-discrete`）は
     **任意**。付けてもよいが受入条件にはしない。付ける場合、
     退場側は Firefox / Safari が `overlay` 未対応なので即時で構わない。
     `styles.css` の `prefers-reduced-motion` 一括停止がそのまま効くため追加配慮は不要。
  9. **jsdom に `showModal()` は無い**（実測: `jsdom` 29.1.1 で
     `typeof el.showModal === "undefined"`）。`frontend/src/test-setup.ts` に
     最小限の代替実装を置いて既存の単体テストを通すこと。代替実装は
     「`showModal()` で `open` を立てる / `close()` で下ろす」程度に留め、
     **モーダル性を代替実装で“証明”しないこと**（それは e2e の仕事）。
- **Acceptance Criteria**:
  1. `App.tsx` に `role="dialog"`・`aria-modal`・自前の `Tab` 巡回が**残っていない**
     （出典モーダルについて。他の箇所は触らない）。
  2. `App.test.tsx` に次のテストがある。
     - 出典を開くと `<dialog>` が開き、読み上げ名が取れる。
     - 「閉じる」で閉じる。
     - 背景クリックで閉じる（`closedby` に依存しないフォールバック経路）。
  3. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する**（本物の証明はここ）。
     - 出典モーダルを開いた状態で `Tab` を 20 回押しても、
       フォーカスがモーダルの外の要素に移らない。
     - `Escape` で閉じる。
     - 開いている間、背後の本文がスクロールしない。
     - 追加前に、現状（自前実装）でその検査が意味を持つことを確認する。
       `screen-invariants` スキルの手順（まず測る）に従うこと。
  4. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  5. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
