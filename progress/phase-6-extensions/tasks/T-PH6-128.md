# Task `T-PH6-128`: 抽出した本文を取り込みに繋ぐ（`DATA-006` 第 2 段）

## TASK DEFINITION (Assigned by Orchestrator)

- **なぜこの票があるか**: `T-PH6-104` の配線部分を切り出したもの。
  レビュー（`opencode/deepseek-v4.1-flash-free`, 2026-11-22T09:40）が High を 3 件挙げ、
  そのうち 2 件がこの配線に属していた。**2 件とも私が実測で確認した**。
  `T-PH6-104` は境界そのもの（`backend/app/sandbox.py`）に絞り、ここは
  「その境界を取り込み処理から呼ぶ」部分だけを扱う。
- **前提**: `T-PH6-104` が `backend/app/sandbox.py` を提供する
  （`extract_with_sandbox(...)` が JSON を標準出力で返し、`sandbox` の種別を記録する）。
  設計の正本は `docs/architecture/DOCUMENT_EXTRACTION_BOUNDARY.md`。
- **実測済みの失敗（これを繰り返さないこと）**:
  1. **封筒をそのまま本文として保存していた。** 抽出成功時に
     `documents.content` を抽出器の**生 stdout**（`{"body": ...}` という JSON の封筒）で
     上書きしており、`_index` が封筒を chunk していた。
     `json.dumps` が `\f` を `\\f` に変えるので**改ページが壊れる**。
     実測: `pytest tests/test_security.py tests/test_ingestion_progress.py -q` が
     **2 failed**（`test_synthetic_scanned_pages_and_attachment_conversation_binding`、
     `test_restart_resumes_from_checkpoint_without_duplicate_chunks`）。
     配線の 77 行を外すと **23 passed** に戻る。
  2. **読めない出力を隔離していなかった。** 設計 §6「JSON として読めない出力は、
     すべて隔離」が実装されておらず、成功判定が**終了コードと出力サイズだけ**だった。
     `print("not json")` は `ready` になり、`not json` が本文として索引される。
  3. **二重封筒**: 抽出と走査完了の間で落ちると `recover_jobs()` が行を再投入し、
     既に封筒になっている `content` をもう一度包む。
     **読み出した列を封筒の保存先に使い回さないこと。**

- **Implementation Details**:
  1. 抽出器の stdout は `json.loads` し、**`body` だけ**を `documents.content` に入れる。
     封筒そのものを列に入れない。
  2. `json.loads` に失敗した出力、`body` を持たない出力は**隔離**する
     （`ready` にしない）。利用者に出す理由は既存の `reason` の語彙に合わせ、
     内部のパス・コマンド・スタック・抽出器の名前を出さない。
  3. 再投入で二重に包まれない形にする。必要なら封筒は列ではなく呼び出しの戻り値として扱う。
  4. `sandbox` の種別（`docker` / `subprocess`）を取り込み記録に残す。
     **子プロセス系統でネットワーク遮断やメモリ上限を主張しないこと**
     （設計 §5 の不変条件）。
