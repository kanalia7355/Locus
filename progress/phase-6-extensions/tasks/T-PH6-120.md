# Task `T-PH6-120`: 発言へ飛んだときに、注意書きと入力欄の裏へ着地しないようにする

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`
  「スクロール余白」「スクロールアンカリング」。
- **Background**:
  - `T-PH6-111` で入力欄が画面下部に固定され、`T-PH6-115` でチャット領域の上部に
    注意書きが常時表示される。つまりスクロール容器（`.messages`）の
    **上下が別の要素に覆われる**状態になる。
  - 「最後の発言が入力欄の裏に隠れる」という元の不具合は `T-PH6-111` が
    **構造で**解いている（入力欄をスクロール容器の外に出し、容器側に余白を確保した）。
    **本ジョブはその話ではない。**
  - 残っているのは **プログラムからスクロールさせたときの着地位置**。
    `App.tsx:581` の `scrollIntoView({ block: "nearest" })` は、
    覆っている要素の存在を知らないので、飛び先が注意書きや入力欄の裏に入る。
    出典から該当箇所へ飛ぶ操作・新しい回答へ移る操作で起きる。
  - 正しい道具は、スクロール容器側の **`scroll-padding-block`**
    （覆われている分だけ、容器のスクロール基準を内側へ寄せる）と、
    必要なら対象側の **`scroll-margin-block`**。どちらも広く利用可能で、
    ポリフィルも機能判定も不要。
  - **スクロールアンカリングについて**: 既定の `overflow-anchor: auto` のおかげで、
    SSE で上に内容が増えても読んでいる位置がずれない。これは**既定の動作**なので
    実装は不要。やってはいけないのは `overflow-anchor: none` を書くことだけ。
    将来これを書いて壊さないよう、検査を 1 本置く。
- **Implementation Details**:
  1. `.messages`（スクロール容器）に `scroll-padding-block` を与える。
     上は注意書きの高さ分、下は入力欄の高さ分。
     固定値を手書きせず、`T-PH6-111` / `T-PH6-115` が既に使っている
     高さのカスタムプロパティを再利用すること。無ければ変数を 1 つ用意して
     CSS 側で一元管理する（JS から毎回測って書き込む作りにしないこと）。
  2. `scroll-behavior` は足さない。`scrollIntoView` に
     `behavior: "smooth"` も書かない。
     **理由**: `styles.css` の `prefers-reduced-motion` 一括停止は
     `scroll-behavior: auto !important` を当てるが、
     JS 側で `behavior: "smooth"` と明示した呼び出しは止められない。
     いまは誰も明示していない（確認済み）ので、その状態を保つ。
     どうしても滑らかにしたい場合は `matchMedia("(prefers-reduced-motion: reduce)")`
     で分岐すること。
  3. `overflow-anchor: none` を**書かないこと**。既存コードにも無い（確認済み）。
  4. 既存の `scrollIntoView({ block: "nearest" })` は変えなくてよい。
     `scroll-padding-block` が効けば着地位置が直る。
     直らない場合に限り `block: "start"` へ変え、理由を REPORT に書く。
- **Acceptance Criteria**:
  1. `.messages` に `scroll-padding-block` があり、値が上下の固定要素の高さと
     同じ変数から導かれている（固定の数値を二重に書いていない）。
  2. `styles.css` と `frontend/src` に `overflow-anchor: none` が無い。
  3. `App.tsx` に `behavior: "smooth"` が無い。
  4. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - 会話を 3 往復以上に伸ばし、上端まで戻してから出典を開いて該当箇所へ飛ぶ
       （または先頭の発言へ `scrollIntoView` させる）。
       飛び先の要素の矩形上端が**注意書きの下端より下**にあり、
       下端が**入力欄の上端より上**にあること。
       つまり覆われている領域に着地していないこと。
     - **追加前に、現状でこの検査が落ちることを確認する。**
       落ちないなら、覆いの高さが足りていないか、先行ジョブが既に解いている。
       その場合は検査だけ残し、落ちなかった事実を REPORT に書くこと
       （`screen-invariants` スキル: 落ちたことのない検査は試されていない）。
     - 会話を伸ばしている最中（SSE 受信中に相当する状態）に、
       読んでいる位置（`.messages` の `scrollTop`）が勝手に飛ばないこと。
       これがスクロールアンカリングを将来壊さないための検査。
  5. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  6. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
     `scroll-initial-target` は使わない（Chromium 専用。
     `MODERN_WEB_ADOPTION.md` で却下済み）。
