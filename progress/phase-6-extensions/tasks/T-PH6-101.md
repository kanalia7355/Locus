# Task `T-PH6-101`: 社内 LAN 配信で落ちる `crypto.randomUUID()` を直す

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針（`docs/plans/UI_OPENCODE_RESEARCH.md` §2 #15、§6.6）。
  オーナー決定 2026-11-16「UI は `UI_OPENCODE_RESEARCH.md` を参考に」。
- **Background**:
  - `frontend/src/App.tsx:642` が `crypto.randomUUID()` を直接呼んでいる。
  - この API は **SecureContext 専用**。開発は `http://localhost` なので SecureContext
    扱いで動くが、オーナー決定どおり社内 LAN で `http://<ホスト名>` 配信した瞬間、
    `crypto.randomUUID is not a function` の `TypeError` になり、
    **資料の添付とアップロードが丸ごと失敗する**。
  - つまり「ローカルでは通るが配備先で落ちる」種類の欠陥で、今は誰も踏んでいないだけ。
  - 同じ問題を OpenCode は `packages/app/AGENTS.md`「Insecure Origins (HTTP LAN)」で
    明文化して回避している。
- **Implementation Details**:
  1. `frontend/src/api.ts` に `uniqueKey()`（名前は既存の命名に合わせてよい）を追加する。
     `crypto.randomUUID` が**関数として存在するときだけ**それを使い、
     無いときは `crypto.getRandomValues` で、それも無ければ時刻＋カウンタで
     衝突しない文字列を返す。例外を投げないこと。
  2. `App.tsx` の `crypto.randomUUID()` をこの関数に置き換える。
     他の挙動（添付の並び、キーの用途）は変えない。
  3. `frontend/src/api.test.ts` に、次の 3 つを検証するテストを書く。
     - `crypto.randomUUID` がある環境ではそれが使われること
     - `crypto.randomUUID` が **undefined** の環境でも例外を投げず、値を返すこと
     - `crypto` 自体が貧弱な環境（`getRandomValues` も無い）でも値を返し、
       連続呼び出しで**重複しない**こと
  4. 既存テストの削除・緩和は禁止。既存の `vitest` 設定とテストの書き方に合わせる。
- **Acceptance Criteria**:
  1. `frontend/src/App.tsx` に `crypto.randomUUID` の直接呼び出しが残っていない。
  2. 上記 3 ケースのテストがあり、フォールバック実装を壊すと落ちる。
  3. `npm --prefix frontend run test` が全件 PASS（既存 89 件に退行がない）。
  4. 変更は許可パス内に収まる。
