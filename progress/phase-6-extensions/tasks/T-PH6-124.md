# Task `T-PH6-124`: SecureContext 専用 API の使用を止め、再発を検査で止める

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `OWNER_DECISIONS.md`「UI 方針」§6.6
  （`crypto.randomUUID()` のフォールバックを承認）。
  `docs/plans/UI_OPENCODE_RESEARCH.md` 項目 15「`[SecureContext]` API の警備」。
  `MODERN_WEB_ADOPTION.md`「SecureContext 専用 API を使わない」。
- **Background**:
  - Locus は**プレーン HTTP で LAN 配信**される前提の画面がある
    （本番は TLS 必須と決まっているが、開発と検証はプレーン HTTP）。
    非 `localhost` の `http://` では `isSecureContext === false` になり、
    `[SecureContext]` 指定の API は**存在しない**。
  - この落とし穴は一度踏んでいる: `crypto.randomUUID()` が
    LAN で `TypeError` になる実バグとして報告され、`api.ts:212` で対処済み。
  - **未対処の実例が 1 件残っている**: `ProvisionUser.tsx:44` の
    `navigator.clipboard.writeText(temporaryPassword)`。
    `navigator.clipboard` も `[SecureContext]` 専用で、LAN では `undefined`。
    - 正確に言うと**画面は落ちない**。呼び出しが `try/catch` の中にあるので、
      `TypeError` は捕まって「コピーできませんでした。パスワードを選択して
      コピーしてください。」が出る。
    - しかし**結果として、LAN では必ず失敗するボタンが置かれている**。
      仮パスワードを配るのは管理者の実務動線で、ここで毎回失敗する。
    - 落ちないので `appearance.spec.ts` の「自前のコードが例外を投げない」検査にも
      引っかからない。測らなければ分からない種類の不具合。
  - 同じことが今後も起きる。**人の注意ではなく検査で止める**のが本ジョブの主目的。
- **Implementation Details**:
  1. `ProvisionUser.tsx` を直す。
     - コピー機能が使えるかを**先に判定する**
       （`navigator.clipboard` の存在、または `isSecureContext`）。
     - 使えないときは**ボタンを出さない**。代わりに、仮パスワードを
       利用者が選択してコピーしやすい形で見せる（等幅・選択しやすい見た目）。
       押せるのに必ず失敗するボタンを置かないこと
       （`T-PH6-112` の「動かないものにスイッチを付けない」と同じ規律）。
     - 使えるときの挙動は**変えない**。
     - `document.execCommand("copy")` による代替は**入れないこと**（非推奨 API）。
  2. **再発を止める検査を `frontend/eslint.config.js` に入れる。**
     `no-restricted-properties` で、`frontend/src` から次を直接参照したときに
     error にする。
     - `navigator.clipboard`
     - `navigator.credentials`（WebAuthn。採らないと決定済み）
     - `navigator.mediaDevices`
     - `navigator.serviceWorker`
     - `crypto.subtle`
     - `crypto.randomUUID`（`api.ts` の既存フォールバック実装の中だけ例外を認める。
       その行に理由付きの `eslint-disable-next-line` を置く）
     メッセージには「`[SecureContext]` 専用。LAN のプレーン HTTP では存在しない。
     機能判定のうえで代替を用意すること」と書く。
     何を禁じたか分かる文言にすること（規則の名前だけでは次の人に伝わらない）。
  3. あわせて `no-restricted-properties` / `no-restricted-syntax` で
     **`innerHTML` と `dangerouslySetInnerHTML` を禁じる。**
     現状 `frontend/src` には両方とも 1 件も無い（確認済み）。
     この状態を固定するのが目的。
     Sanitizer API（`setHTML`）と Trusted Types は**導入しない**
     （守る対象が無く、Safari 未対応。`MODERN_WEB_ADOPTION.md` で却下済み）。
     T-PH6-114 で回答の Markdown 描画や作図結果の埋め込みに進むときは、
     **この規則が落ちることで気付ける**。そのときに再評価する。
  4. パスワードそのものをログ・進捗記録・コミットメッセージに書かないこと
     （既存の規律。`scripts/secret_scan.py` が見ている）。
- **Acceptance Criteria**:
  1. `ProvisionUser.tsx` に `navigator.clipboard` への**無防備な参照が無い**。
     使えない環境ではコピーボタンが出ず、仮パスワードは選択して読める形で出る。
  2. `frontend/eslint.config.js` に上記の禁止規則が入っており、
     `npm --prefix frontend run lint` が PASS する
     （既存コードに違反が残っていないこと。`api.ts` の 1 行の例外には理由が書かれている）。
  3. 禁止規則が**実際に効く**ことを確認する。確認方法を REPORT に書くこと
     （一時的に `navigator.clipboard` を書いた捨てファイルで `lint` が落ちることを見る、
     など。捨てファイルはコミットしない）。
  4. `ProvisionUser.test.tsx` に次のテストがある。
     - `navigator.clipboard` が無い環境（削除した状態）で、
       コピーボタンが**描かれない**。
     - `navigator.clipboard` がある環境では、押すと `writeText` が呼ばれ、
       「コピーしました。」が出る。
     - どちらの環境でも仮パスワードそのものは画面に出ている
       （コピーできなくても配れること）。
  5. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - 利用者の追加で仮パスワードが出た画面で、
       **押せる状態のボタンがすべて押せること**を確認する検査。
       具体的には、`enabled` なボタンを押したあとに
       「できませんでした」系の文言が出ないことを見る。
       押せるのに必ず失敗するボタンを置かない、という規律を機械で見る形にしたもの。
     - Playwright は `http://127.0.0.1:5174`（SecureContext）で走るため、
       **この検査では LAN の非 SecureContext を再現できない**。
       その限界をコメントに明記すること。
       非 SecureContext 側の確認は 4 の単体テストが担う。
     - 追加前に意味のある検査であることを確認すること（`screen-invariants` スキル）。
  6. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
     `python scripts/secret_scan.py` が 0 findings。
  7. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
     `package.json` を変更しない（新しい依存を入れないこと）。
