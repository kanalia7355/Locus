- **着手できない理由（意図的）**: `allowed_paths` と `test_cmd` を `未確定` にしてある。
  ループは未確定スコープのジョブを拾わない（`jobloop/tasks.py` の `allowed_paths`）。
  これは「決まっていないから放置」ではなく、**ここがセキュリティ境界そのもの**だから。
  抽出処理は、攻撃者が中身を選べるデータを解析する場所であり、
  境界の設計を書く前に実装を出すと、受入条件が「動いた」になってしまう。
- **先に Claude Code が書くこと（設計）**:
  1. 子プロセスに与える権限の上限: ネットワーク遮断、書込み先を 1 つの一時ディレクトリに限定、
     CPU 時間・メモリ・実時間・出力バイト数の上限、環境変数の遮断。
  2. Docker が使える場合と使えない場合の 2 系統を、**同じインタフェース**で扱う方法。
     どちらで走ったかを取り込み記録に残す（オーナー回答「docker でもローカル PC でも」）。
  3. 上限に当たったときの扱い: 失敗は「隔離」であって「取り込み成功」ではない。
     利用者に見せる理由の文言。
  4. 検査ソフトが無い環境の既定: オーナー回答により「未検査と明示して通す」を既定にできるが、
     厳格運用（未検査なら隔離）も選べる設定にする。
  5. 受入条件: **境界が破れたら落ちるテスト**をどう書くか。
     少なくとも「ネットワークに出ようとする合成プラグイン」「無限ループ」「巨大出力」
     「サンドボックス外への書込み」の 4 つが、すべて失敗として観測されること。
- **この設計が通ったら**: 本ファイルの `allowed_paths` と `test_cmd` を確定し、
  `T-PH6-106`（実際の PDF / Office / 画像 OCR 抽出）のスコープも同時に確定する。
