### 設計のうち、絶対に外せない 3 点

1. **抽出器のコードを本体プロセスで `import` しない。** 抽出は常に子プロセス。
   import した時点でパーサの脆弱性が本体の脆弱性になる。
2. **子プロセス系統で「ネットワーク遮断」「メモリ上限」を記録に主張しない。**
   実測の根拠: この機に `resource` モジュールは無く（`win32`, Python 3.13.2）、
   docker エンジンも動いていない（CLI はあるが `docker info` が接続できない）。
   さらに `ADR-0006` に「Windows のネイティブサンドボックス診断では
   loopback 接続と方針パスへの書込みが可能だった」という実測が残っている。
   **弱い方の保証しか主張しない。**
3. **docker 系統の検査は opt-in の skip にし、skip された検査を証拠にしない。**
   `tests/integration/test_live_docker_boundary.py` の作法（`LOCUS_LIVE_DOCKER`）に倣う。
   CI は docker 無しで走るので、**既定経路は子プロセス系統**。

### `loop_engine` について

docker 系統の旗と語彙は `loop_engine/docker_boundary.py` に揃えること
（`--network none` `--read-only` `--cap-drop ALL` `no-new-privileges`
`--pids-limit` `--memory` `--cpus` `--tmpfs`）。
**ただし `loop_engine` を `import` しないこと。** 保護パスでジョブから書けず、
開発ループと製品は信頼領域が違う。真似るが共有しない。
