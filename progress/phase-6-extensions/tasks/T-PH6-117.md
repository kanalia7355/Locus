# Task `T-PH6-117`: 参照範囲のポップアップを Popover API に載せ替える（アンカー配置は採らない）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`
  「`ui-atoms/viewport-aware-dropdowns`」（`GoogleChrome/modern-web-guidance`）。
- **Background**:
  - `T-PH6-111` が参照範囲を入力欄の中のチップ（`ScopePicker`）にし、
    開閉・キーボード操作・外側クリックで閉じる・フォーカスの封じ込めを**自前で**実装した。
    あの時点ではそれが正しい（`<select>` を使わないという指示があり、
    ポップアップの基本機能を自分で満たす必要があった）。
  - Popover API は **Baseline 2025-01-27**（Chrome 116+ / Edge 116+ / Firefox 125+ /
    Safari 17+）。`popover` 属性を付けるだけで、
    **外側クリックで閉じる（light dismiss）・Esc で閉じる・最前面レイヤに出す**が標準で入る。
    自前の `document` クリック購読と `z-index` の調整が消える。
  - **本ジョブを `T-PH6-111` と分けた理由**: `T-PH6-111` は実装済みでレビュー待ち。
    いま差し込むと、レビュー待ちの差分をもう一度動かすことになる。
    マージ後に、挙動を変えない載せ替えとして行う。
- **採らないもの（調査済み。探しに行かないこと）**:
  - **CSS アンカー配置（`position-area` / `position-try-fallbacks`）は採らない。**
    ガイドの記載どおり **Chrome 157+ / Edge 157+ / Safari 27+ で、Firefox は未対応**。
    社内の誰がどのブラウザで開くか決まっていない画面に、位置計算が黙って崩れる機能は
    入れられない。`@oddbird/css-anchor-positioning` ポリフィルも入れない。
  - 位置決めは、**開くときに `getBoundingClientRect()` を 1 回読んで
    `position: fixed` の座標を決める**で足りる。入力欄は画面下部に固定されている
    （`T-PH6-111`）ので、チップの座標はほぼ動かない。
  - **`role="menu"` と `aria-haspopup` を付けないこと。** ガイドが明示的に禁じている。
    参照範囲は値の選択なので `role="listbox"` が正しい。
- **Implementation Details**:
  1. `ScopePicker` のポップアップ要素に `popover="auto"` を付け、
     開閉を `showPopover()` / `hidePopover()` にする。
     チップ側は `popovertarget` で結ぶか、`onClick` から明示的に呼ぶ。どちらでもよい。
  2. **自前の外側クリック購読（`document` への `click` / `pointerdown` リスナ）を削除する。**
     light dismiss が代わる。削除後に挙動が落ちていないことを確認すること。
  3. **Esc は注意が必要。** Popover の light dismiss も Esc で閉じるが、
     `T-PH6-111` が自前の Esc 処理を持っている。**二重に閉じない**ようにし、
     どちらが閉じても「チップにフォーカスが戻る」ことを維持する。
  4. **落としてはいけないもの**（`T-PH6-111` の受入条件）:
     `aria-label`・`aria-expanded`・`role="listbox"`・選択中項目の表現・
     上下キーでの移動・Enter での決定・開いている間フォーカスが外へ出ないこと・
     `prefers-reduced-motion` でアニメーションを切ること。
     **Popover API はキーボードでの項目移動を提供しない**ので、そこは自前のまま残す。
  5. 位置は `position: fixed` で、開くときに測った座標から決める。
     画面の上端を越える場合はチップの下側へ出す（単純な 1 段の切り替えでよい）。
  6. **jsdom に Popover API は無い**（実測: `jsdom` 29.1.1 で
     `"popover" in HTMLElement.prototype === false`、`showPopover` も未定義）。
     `frontend/src/test-setup.ts` に最小限の代替実装を置き、既存の単体テストを通すこと。
     代替実装で light dismiss を“証明”しないこと（それは e2e の仕事）。
- **Acceptance Criteria**:
  1. `App.tsx` に、参照範囲のための `document` レベルのクリック購読が**残っていない**。
  2. `App.test.tsx` の `T-PH6-111` 由来のテスト（チップから値を変えて送信すると
     変更後の値がリクエストに乗る / 読み上げ名 / 上下・Enter・Esc）が
     **1 件も削除・緩和されずに PASS する**。
  3. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - チップを開き、ポップアップの外側をクリックすると閉じ、フォーカスがチップに戻る。
     - 開いた状態でポップアップが入力欄や他の要素の下に隠れていない
       （要素の矩形中心に対する `elementFromPoint` がポップアップ内の要素であること）。
     - 開いた状態で画面が横スクロールしない（既存の invariant と同じ条件を
       開いた状態でも満たす）。
     - 追加前に意味のある検査であることを確認する（`screen-invariants` スキル）。
  4. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  5. アンカー配置とポリフィルを導入していない。`package.json` に変更が無い。
  6. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
