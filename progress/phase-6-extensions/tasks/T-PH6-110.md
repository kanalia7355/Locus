# Task `T-PH6-110`: ダークモードを入れる

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。オーナー指示 2026-11-16「ダークモードにできたらいい」。
- **Background**:
  - `styles.css:7-28` の `:root` に明るい配色のトークンが 1 組だけある
    （`--color-paper` `--color-sidebar` `--color-soft` `--color-selected` `--color-ink`
    `--color-muted` `--color-line` `--color-accent` `--color-on-accent` `--color-error`
    `--color-error-paper` `--color-focus` `--color-backdrop`）。
  - 部品側は**ほぼすべてこのトークン経由**で色を取っているので、トークンを差し替えれば
    暗い配色になる。ただしトークンを使わず直接色を書いている箇所が残っていないか、
    実装前に確認すること（見つけたらトークンへ寄せる。これも作業に含む）。
- **Implementation Details**:
  1. 暗い側のトークンを**別に組む**。明るい側の単純な反転にしないこと。
     とくに `--color-accent`（ボタン背景）と `--color-on-accent`（その上の文字）は、
     暗い配色では明暗が入れ替わる。`--color-error` 系も、暗い背景で読める彩度へ落とす。
     どちらの配色でも本文と背景の対比が十分であること。
  2. 既定は**システム設定に従う**（`@media (prefers-color-scheme: dark)`）。
     加えて利用者が「ライト / システムに従う / ダーク」を選べること。
     選択は `localStorage` に保存し、次回の起動でも維持する。
     利用者の選択は、メディアクエリより**必ず優先**されること（両方向とも）。
  3. 切り替えの実装は `frontend/src/theme.ts` に純粋な形で切り出す
     （保存値とシステム設定から、適用すべきモードを決める関数）。React に依存させない。
  4. 選択 UI の置き場所は、既存の管理画面の中で最も素直なところに 1 つ。
     新しいサイドバー項目を増やさないこと（サイドバーの作り直しは `T-PH6-112`）。
  5. 画面の初期描画で**明るい配色が一瞬見えてから暗くなる**ことがないようにすること。
- **Acceptance Criteria**:
  1. `frontend/src/theme.test.ts` に次の合成テストがある。
     - 保存値なし + システムが暗い → 暗いモード
     - 保存値なし + システムが明るい → 明るいモード
     - 保存値「ライト」+ システムが暗い → **明るいモード**（利用者の選択が勝つ）
     - 保存値「ダーク」+ システムが明るい → **暗いモード**
     - 壊れた保存値（空文字・知らない値）→ システム設定に従う（例外を投げない）
  2. 暗い配色のトークンが明るい側の単純な反転ではないことが、値として確認できる。
  3. トークンを経由せず直接色を書いている箇所が残っていない（残した場合は REPORT に理由）。
  4. `npm --prefix frontend run test` と `typecheck` が PASS。既存テストに退行がない。
  5. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
