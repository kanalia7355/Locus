# Task `T-PH6-107`: 管理画面にスロットの使用中本数と総本数を出す

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `UI-006`。オーナー決定 2026-11-16「待機列を複数本に」。
- **前提**: `T-PH6-102`（`model_slot` が `{"enabled": bool, "busy": int, "total": int}` になる）。
  **`T-PH6-102` が `done` になってから着手すること**。先に走らせると、まだ存在しない
  形に合わせたテストを書くことになる。
- **Background**:
  - `frontend/src/AdminSettings.tsx` は `model_slot.busy` を **boolean** として型宣言し、
    `busy ? "実行中" : "空き"` と描画している。
  - `T-PH6-102` で `busy` は整数になる。`0` / 非 0 の分岐としては偶然正しく動くが、
    **型宣言が実態と食い違う**ので、TypeScript は嘘をついた状態になる。
    さらに「4 本中 2 本使用中」という、オーナーが決めた構成の実態が画面に出ない。
- **Implementation Details**:
  1. `frontend/src/api.ts` の `model_slot` の型を実際のレスポンス
     （`enabled: boolean` / `busy: number` / `total: number`）に合わせる。
  2. `AdminSettings.tsx` の表示を「使用中 N / 全 M 本」が読み取れる形に変える。
     文言は既存の日本語の調子に合わせる（`実行中` / `空き` の語を活かしてよい）。
     `total` が 1 のときは、いまと同じ「実行中 / 空き」の見え方を保つこと
     （既定構成の画面を不必要に変えない）。
  3. 既存の `AdminSettings.test.tsx` のモックを新しい形に更新し、
     次を検証するテストを足す。
     - `total: 1` のとき、従来と同じ表示になる
     - `total: 4, busy: 2` のとき、使用中本数と総本数の**両方**が画面に出る
     - `busy: 0` が「空き」として扱われる（`0` を falsy として取り違えないこと）
  4. 併せて、スロット数を変更した管理操作の監査記録に**選んだ本数が残らない**という
     レビュー指摘（`T-PH6-102` の Low）がある。これはサーバ側の話なので
     本タスクでは扱わない。REPORT に「未対応」と書くだけでよい。
- **Acceptance Criteria**:
  1. `model_slot.busy` の型が `number` になっており、`boolean` を前提にした箇所が残っていない。
  2. 上記 3 ケースのテストがあり、表示を壊すと落ちる。
  3. `npm --prefix frontend run test` と `npm --prefix frontend run typecheck` が PASS。
  4. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
