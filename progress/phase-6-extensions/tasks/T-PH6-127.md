# Task `T-PH6-127`: 画面の検査を 1 本だけ見るのをやめる

## TASK DEFINITION (Assigned by Orchestrator)

- **なぜこの票があるか**: `T-PH6-116` が止まった原因がこれ。
  コントローラの画面ゲートは `npm run test:appearance` を走らせるが、その中身は
  `playwright test e2e/appearance.spec.ts` で、**`e2e/` の 1 本しか見ていない**。
  結果、`frontend/e2e/workspace.spec.ts` と `frontend/e2e/a11y.spec.ts` は
  誰にも実行されず腐る。
- **実際に腐っていた証拠**（2026-11-22 に私が実測）:
  `workspace.spec.ts:596` が `.main` の `scrollTop > 0` を要求しているが、
  `T-PH6-111` がスクロール領域を `.messages` に移したので `.main` はもうスクロールしない。
  **クリーンな HEAD で落ちる**。`T-PH6-111` がマージされた時点で赤くなっていたのに、
  ゲートが見ていないので誰も気付かなかった。
- **Background**:
  - `appearance.spec.ts` だけを選んだのは、画面不変条件を足した `T-PH5-10x` 当時に
    他の 2 本が重かったため。いまは 3 本とも同じフィクスチャ（`tests/e2e_server.py`）で
    走るので、分ける理由が無い。
  - ゲートを 3 本に広げると、**腐っている表明が全部一度に出てくる**。
    それが目的である（腐りを見つけるためのジョブ）。
    ただし `T-PH6-116` が `workspace.spec.ts` の 1 か所を直すので、**それの後に走ること**
    （`depends_on` に入れてある）。
- **Implementation Details**:
  1. `jobloop/gates.py` の `frontend_gates` が走らせる script を
     `test:appearance` から **`test:e2e`** に変える（`playwright test` 全体）。
     ゲートの名前も実態に合わせること（`frontend-test:appearance` のままにしない）。
  2. `frontend/package.json` の `test:appearance` は**消さないこと**。
     人が 1 本だけ回したいことはあるし、既存の文書と skill が名前で参照している。
  3. 3 本を実行して**落ちた表明を直す**。直し方の原則は `T-PH6-116` と同じ:
     - **性質を落とさない**。実装の写し（どの要素がスクロールするか）ではなく、
       守りたい性質（本文はスクロールし、上の帯は動かない）を表明する形に言い直す。
     - 落ちた理由が**製品の不具合**なら、表明は直さず**不具合を報告すること**
       （このジョブの許可パスに `frontend/src` は入っていない。直すのは別ジョブ）。
     - テストの削除・`test.skip`・`test.fail`・幅や閾値の緩和は**禁止**。
  4. どの表明をなぜ直したかを**1 件ずつ**報告すること。
     「3 本緑になった」だけでは、何を緩めたか分からない。
