# Task `T-PH6-140`: 画像（PNG / JPEG / GIF / WebP）を受け入れる

## SCOPE — レビュアーはここを先に読むこと（2026-11-28 23:17 当番）

**これは `T-PH6-106` から分けた票である。削った仕事ではない。**
オーナーは 2026-11-28 23:16 に「Claude や ChatGPT などで添付できる形式
すべて」を受け入れると決めた。画像はその中にある。

**入場条件**: `T-PH6-138` の (2)、**画像の本文をどうするか**が決まること。
これはライブラリの選択ではなく製品の決定である:

- **OCR をしない**（当番の推奨）: 添付として受け入れ、本文は空のまま、
  出典には「画像」として残す。検索には出ないが、**嘘の本文を作らない。**
- **OCR をする**: `pytesseract` は **python の外の実行ファイル `tesseract`**
  を要求する。`T-PH6-135` の docker と同じ形の「機械の用意」が増え、
  入っていない機械では**静かに空の結果**になる。
  **「入っていないことを検知して、入っていないと言う」ところまでが
  この票の仕事になる** —— `DOCKER_GUARANTEES` が `strong` を観測した
  終了コードにしか付けないのと同じ理由である。

`allowed_paths` と `test_cmd` は、決まってから当番が確定させる。

## この票がやること（下書き。`T-PH6-138` の後に確定させる）

1. `backend/app/formats.py` の表に `.png` `.jpg` `.jpeg` `.gif` `.webp` を足す。
   `kind` は `image`、バイト上限は **5 MiB（`5242880`）を既定**とする
   （当番が決めた既定値。オーナーが別の数を言えばそれに従う）。
2. 本文の扱いを、決まったほうに合わせて実装する。
3. 出典の表示が画像でも成り立つことを確かめる —— `引用箇所 p.N chunk M` の
   形は文書のためのものなので、**画像で何を見せるかを決めて検査に書くこと。**

## Acceptance Criteria（下書き）

1. 5 つの拡張子すべてで upload が通り、`GET /api/formats` が受け入れると
   答えること。**拡張子を表から読んで回す検査**にすること。
2. **本文が無い画像を「取り出せた」と言わないこと。** 空の本文が
   成功として記録されないことを実行結果で示すこと。
3. OCR をする場合のみ: **`tesseract` が入っていない機械で、
   「入っていない」と言うこと。** 静かに空を返してはいけない。
   `skip` したので通った、は証拠ではない。
4. 画像でないものに `.png` の名前を付けた入力で、プロセスが死なないこと。
5. **抽出は子プロセスの中で動く。** 本体プロセスが画像ライブラリを
   import していないことを検査で表明すること。
6. 既存の検査を削除・skip・緩和しない。変更が `allowed_paths` 内に収まる。
   `pyproject.toml` は保護パスなので触らない。
