# Task `T-PH6-113`: プロジェクト切替が何をするのか分かるようにする

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。オーナー指摘 2026-11-16
  「検証用プロジェクトってプルダウンは何のためにあるのか解説が欲しい」。
- **Background**:
  - 上部の帯にプロジェクトのプルダウン（`App.tsx:952`）がある。切り替えると
    参照できる資料・会話履歴・自分の役割が**まるごと入れ替わる**強い操作なのに、
    画面にはプロジェクト名しか出ておらず、何が起きるのか分からない。
  - 実際の処理（`App.tsx:956-966`）は、会話を新規化し、資料一覧と履歴を捨てて
    チャット画面へ戻す。**入力中の下書きや開いていた会話が失われる**可能性がある操作。
  - 研究テーマが 1 つしかない利用者は、この操作を一度も使わない。
- **Implementation Details**:
  1. プルダウンに読み上げ名とは別に、**何が切り替わるのかの説明**を付ける。
     ホバーとフォーカスで出る短い説明（基準文書が許している範囲の tooltip）。
     文面の方針: 「資料・会話・あなたの役割が切り替わります」。
     常設の案内文は置かない（`UI_IMPLEMENTATION_BASELINE.md` の決定事項）。
  2. **選べるプロジェクトが 1 つだけのときは、プルダウン自体を出さない**。
     代わりにプロジェクト名をただの文字として表示する。
     操作できない選択肢を操作できる形で見せない。
  3. 切り替えで失われるものがある場合（下書きが残っている、生成中の回答がある）は、
     切り替える前にその旨を確認する。確認なしで消さないこと。
     確認の文面は、何が失われるかを具体的に書くこと。
- **Acceptance Criteria**:
  1. `App.test.tsx` に次の合成テストがある。
     - プロジェクトが 1 件のとき、プルダウンが描画されない（名前は出る）
     - プロジェクトが 2 件以上のとき、プルダウンが出て説明が読み上げから辿れる
     - 下書きがある状態で切り替えようとすると確認が出て、取り消すと**下書きが残る**
     - 確認を承諾すると従来どおり切り替わる
  2. 既存の切り替え動作（資料・履歴・会話の入れ替え）が変わっていない。
  3. `npm --prefix frontend run test` と `typecheck` が PASS。
  4. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
