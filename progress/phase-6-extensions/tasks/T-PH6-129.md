# Task `T-PH6-129`: docker 経路を「動くと嘘をつかない」状態にする

## TASK DEFINITION (Assigned by Orchestrator)

- **なぜこの票があるか**: `T-PH6-104` から docker 経路を切り出したもの。
  同じ指摘が**3 回のレビューで 3 回**挙がり（うち 1 回は実装者自身の報告）、
  **私が 2 回命じて 2 回なされなかった**。3 回目を命じない理由は怠慢だからではなく、
  **この機では「動くこと」を検証できない**からである。
  `DOCUMENT_EXTRACTION_BOUNDARY.md` §5 に実測が残っているとおり、
  この機に docker エンジンは動いていない（CLI 28.5.1 はあるが
  `docker info` がパイプに繋がらない）。
  「コンテナで隔離が効くことを示せ」はこの機にいる限り誰も満たせないので、
  受入条件を**「動くと主張していないことを示せ」に書き換えた**。
  **`T-PH6-104` の受入条件を落としたのではなく、ここへ移した。**

- **実測済みの欠陥（3 件。すべて読めば分かる）**:
  1. **ホストの `sys.executable` をコンテナの実行コマンドとして渡している**
     （`sandbox.py` の `_run_docker`、`[..., image, sys.executable, "-c", script]`）。
     既定イメージは `ubuntu:22.04` で、そこに `C:\...\python.exe` は存在しない。
     **構造的に起動できない。** エンジンがあっても exec エラーになる。
  2. **`FileNotFoundError` の退避が `content` を落としている**（`:240-245`）。
     これは `T-PH6-104` で直す（重複して直さないこと）。
  3. **opt-in の実測が製品経路を通っていない。**
     `tests/integration/test_live_sandbox_docker.py` は `docker run` を手組みしていて、
     `_run_docker` も `extract_with_sandbox(..., use_docker=True)` も呼んでいない。
     通ったとしても**製品が動く証拠にならない**。

- **Implementation Details**:
  1. **argv の組み立てを関数に出す**（例 `_docker_argv(image, interpreter, script)`）。
     こうすると**エンジン無しで argv を検査できる**。これが本票の鍵である。
  2. **インタプリタの約束を明示する。** `sys.executable` をやめ、
     イメージとインタプリタの対を**引数か定数で明示**する
     （python を含むイメージなら `python3` 等）。
     ホスト側の絶対パスが argv に入らないことを検査で固定する。
  3. **`DOCKER_GUARANTEES`（`network`/`memory`/`cpu` が `strong`）は、
     docker が実際に走って終了コードを観測した場合だけ返す。**
     退避したとき・起動に失敗したときは**子プロセス系統の弱い保証**を返す。
     §5 の作法（弱い方しか主張しない）をここにも通す。
  4. **opt-in の実測を製品経路に繋ぐ。** 手組みの `docker run` をやめ、
     `extract_with_sandbox(..., use_docker=True)` を呼ぶ形にする。
     `LOCUS_LIVE_DOCKER=1` の門はそのまま残す（既定では skip される）。
  5. **記録に正直に書く**: docker の隔離はこの機では未実証である。
     検査名・docstring・保証の文字列のどれにも「検証済み」と書かないこと。

- **Acceptance Criteria**（**どれも docker エンジンを必要としない**）:
  1. `use_docker=True` を**エンジンが無いこの機で**呼んだとき、
     結果の `sandbox` が `"docker"` にならず、`guarantees` の
     `network`/`memory`/`cpu` に `strong` が**入っていない**ことを検査が表明している。
  2. 組み立てた argv に**ホストの絶対パスが現れない**ことを検査が表明している
     （`sys.executable` を直接使っていないこと）。エンジンを起動せずに確かめること。
  3. `tests/integration/test_live_sandbox_docker.py` が
     `extract_with_sandbox(..., use_docker=True)` または `_run_docker` を
     **実際に呼んでいる**。`LOCUS_LIVE_DOCKER` 未設定では skip される
     （skip は証拠ではない、と記録に書くこと）。
  4. **検査が落ちることを確かめた**: 3-(3) の分岐を一時的に「常に strong」に戻すと
     受入条件 1 の検査が FAIL することを手で確認し、**報告に結果を書く**。
  5. `T-PH6-104` が入れた §8.1〜8.5 の検査を**1 件も消していない**。
  6. 変更が allowed_paths 内に収まっている。

- **やってはいけないこと**:
  - docker エンジンを入れようとしないこと（この票の範囲外）。
  - `T-PH6-104` が直す `content` の受け渡しを重複して直さないこと。
  - 「skip したので通った」と報告しないこと。
