# Task `T-PH6-118`: `color-scheme` を宣言し、初期描画のちらつきを `<meta>` で止める

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`T-PH6-110` 受入条件 5。
  `MODERN_WEB_ADOPTION.md`「`visual-design/dark-mode`」
  （`GoogleChrome/modern-web-guidance`）。
- **Background**:
  - `T-PH6-110` は配色トークンと `theme.ts` の切り替え規則を担当するが、
    受入条件 5「画面の初期描画で明るい配色が一瞬見えてから暗くなることがない」を
    **CSS と React だけでは満たせない**。JS バンドルが評価されるまでに最初の描画が走る。
    正攻法は `frontend/index.html` の `<head>` に `<meta name="color-scheme">` と
    その直後のインラインスクリプトを置くことで、これは `T-PH6-110` の許可パス外。
    そのため本ジョブに切り出した。
  - あわせて `styles.css` に **`color-scheme` の宣言が無い**（確認済み）。
    これが無いと、トークンを暗くしてもスクロールバー・`input`・`textarea`・
    チェックボックスなどブラウザが描く部分が明るいままで、暗い画面に白い枠が残る。
    `color-scheme` は 2022 年以降広く利用可能。
  - `frontend/index.html` は 2 行に圧縮された 1 ファイルで、現状
    `<meta charset>` `<meta name="viewport">` `<meta name="referrer">` `<title>` のみ。
    `T-PH6-109` が `<title>` を変更するので、**そのマージ後に着手すること**。
- **Implementation Details**:
  1. `frontend/index.html` の `<head>` に次を置く。順序を守ること
     （スクリプトは `<meta>` の**直後**。`defer` も `type="module"` も付けない。
     遅延すると最初の描画に間に合わず、ちらつきが残る）。
     ```html
     <meta name="color-scheme" content="light dark" />
     <script>
       document.querySelector('meta[name="color-scheme"]').content =
         localStorage.getItem("locus-color-scheme") ?? "light dark";
     </script>
     ```
     保存キーは `T-PH6-110` の `theme.ts` が使うものと**同一にすること**
     （`theme.ts` 側の定数を正とし、ここは同じ文字列を書く。
     インラインスクリプトからモジュールは参照できないので、
     `theme.test.ts` に「キー名が一致している」ことを確かめるテストを足す）。
     `localStorage` の読み出しは例外を投げうる（プライベートモード等）ので
     `try` で囲み、失敗時は `"light dark"` に落とす。
  2. `styles.css` の `:root` に次を足す。基底を `light dark` に保つこと
     （JS が動かなくても両方の配色に対応していると宣言できる）。
     ```css
     :root {
       color-scheme: light dark;
     }
     :root:has(> head > meta[name="color-scheme"][content="dark"]) {
       color-scheme: dark;
     }
     :root:has(> head > meta[name="color-scheme"][content="light"]) {
       color-scheme: light;
     }
     ```
     著者 CSS の `color-scheme` は `<meta>` を上書きするため、
     この写し戻しが無いと利用者の選択が効かない（ガイドの指摘）。
  3. `theme.ts` が返す値を **`"light" | "dark" | "light dark"`** の 3 値にし、
     適用は `<meta>` の `content` を書き換える形にする
     （クラス付与にしないこと。`light-dark()` は使用中の `color-scheme` しか見ない）。
     保存値がシステム設定と同じ場合は保存を消す、という扱いは `T-PH6-110` の
     受入条件（利用者の選択がメディアクエリより必ず優先）と矛盾するので**採らない**。
     3 択はそのまま 3 値として保存する。
  4. 暗い配色で**ブラウザが描く部分**を整える。
     - `accent-color` をトークンから与える（広く利用可能）。
     - `scrollbar-color` を与える。本体とつまみの対比を最低 3:1 にする。
       2025-12 に newly baseline と新しいので、未対応では既定のスクロールバーが
       出るだけ（悪化しない）。**アニメーションさせないこと**
       （WebKit のちらつき不具合。ガイドの注意）。
  5. `--color-backdrop` のような半透明値が暗い配色で成立しているか確認する。
     明るい配色の値をそのまま使うと、暗い背景の上でほぼ見えなくなる。
- **Acceptance Criteria**:
  1. `frontend/index.html` に `<meta name="color-scheme">` と、その直後の
     同期インラインスクリプトがある。`defer` / `type="module"` が付いていない。
  2. `styles.css` の `:root` に `color-scheme` の基底宣言と、
     `<meta>` の値を写し戻す 2 つの規則がある。
  3. `theme.test.ts` に次のテストがある。
     - `theme.ts` の出力が `"light" | "dark" | "light dark"` の 3 値である。
     - インラインスクリプトが使う保存キーの文字列が `theme.ts` の定数と一致する
       （`index.html` を読み込んで文字列を照合する、でよい）。
     - 保存値の読み出しが例外を投げても既定に落ちる。
  4. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - `colorScheme: "dark"` のブラウザ文脈で入場し、
       本文の背景色が明るい側の値（`#fff`）**ではない**こと。
     - ダークを選んだ状態で再読み込みし、**最初の描画から**暗いこと。
       `page.goto` の直後（React のマウント前）に
       `getComputedStyle(document.documentElement).colorScheme` が `dark` であることを
       確かめる形で測る。これがちらつきの有無の機械的な代用になる。
     - 追加前に、現状でこの検査が落ちることを確認する（`screen-invariants` スキル）。
  5. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  6. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
     `oklch` と `contrast-color()` は導入しない（`MODERN_WEB_ADOPTION.md` で却下済み）。
