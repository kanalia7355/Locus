# Task `T-PH6-119`: ルートの `font-size: 14px` を撤去し、OS の文字サイズ設定に従う

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`
  「`accessibility/respect-os-text-scale`」（`GoogleChrome/modern-web-guidance`）。
- **Background**:
  - `frontend/src/styles.css:26` に **`:root { font-size: 14px }`** がある。
    これは `respect-os-text-scale` ガイドが名指しで禁じている書き方で
    （「DO NOT explicitly set the root `font-size` in your stylesheet」）、
    **利用者がブラウザや OS で設定した文字サイズを無効化する**。
    画面を拡大すれば読めるが、文字サイズだけを上げたい利用者には効かない。
    WCAG 1.4.4（文字サイズの変更）の観点でも素の不具合。
  - 研究室で使うツールであり、画面を見る時間が長い。これは装飾の話ではない。
  - 作業量は本物: `styles.css` は `px` 指定が **227 箇所**、`rem` が **2 箇所**。
    機械的な置換で済む部分と、意図して `px` のままにすべき部分
    （枠線 1px、影、`1px solid` など）が混ざる。
  - **先行ジョブの後に置く理由**: `T-PH6-110`（トークン）・`T-PH6-111`（入力欄固定）・
    `T-PH6-112`（サイドバー作り直し）・`T-PH6-115`（注意書き）が
    すべて `styles.css` を触る。この全面置換を先にやると全部と衝突する。
- **Implementation Details**:
  1. `:root` から `font-size: 14px` を**削除する**。`html` にも書かない。
     `env(preferred-text-scale)` も使わない（`<meta name="text-scale">` と併用すると
     二重に拡大される。ガイドの注意）。
  2. 既定の 16px を基準に、**見かけの大きさを現状と揃える**。
     14px 相当は `0.875rem`。ただし「全部を `0.875rem` にする」のは誤り
     （それでは基準を 14px に固定し直したのと同じ）。本文は `1rem` にし、
     小さい文字（`font-size: 12px` 等）を相対値へ落として情報の階層を保つ。
     **結果として本文がいまより少し大きくなるのは正しい**。
     見た目を 1px も変えないことを目標にしないこと。
  3. 文字サイズ・余白・行間（`padding` / `margin` / `gap` / `line-height` /
     `max-width` / `min-height`）は `rem`（または `em`）にする。
     `line-height` は**単位なし**にする（計算後の文字サイズに比例させるため）。
  4. **`px` のままで正しいもの**（変換しないこと）:
     枠線の太さ、`outline-width`、影の広がり、`border-radius`、
     1 物理ピクセルを意図した区切り線。これらは文字サイズに追従すべきでない。
     判断した結果を REPORT に書くこと。
  5. メディアクエリの区切り幅を `px` から **`em`** にする
     （`@media (min-width: 48em)` のように）。文字を大きくした利用者に対して、
     幅の分岐が意図どおり早く切り替わる。
     既存の区切り幅と `appearance.spec.ts` の `WIDTHS`（1280 / 768 / 360）の
     対応関係を崩さないこと。
  6. 高さを固定して文字を切る箇所を潰す。固定 `height` と狭い `max-height` を外し、
     縦に伸びられるようにする（ガイドの指示）。
  7. 最後に `frontend/index.html` の `<head>` へ
     `<meta name="text-scale" content="scale" />` を置く。
     Chrome 146+ / Edge 146+ のみ対応で Firefox・Safari は無視するだけ。
     **`rem` 化を済ませた後でのみ意味を持つ**ので順序を守ること。
- **Acceptance Criteria**:
  1. `styles.css` に `:root` または `html` に対する `font-size` 宣言が**無い**。
  2. `styles.css` の `font-size` 宣言すべてが相対単位である
     （検査可能な形にすること。grep で確認して REPORT に数を書く）。
  3. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - ブラウザの既定文字サイズを 2 倍相当にした文脈
       （`page.addInitScript` で `document.documentElement.style.fontSize` を
       外から与えるのではなく、Playwright の `deviceScaleFactor` ではなく、
       `--force-device-scale-factor` でもなく、
       **`page.emulateMedia` では代替できない**ため、
       `context` 作成時のブラウザ設定か、`html` への `font-size: 32px` 注入で代用する。
       どの手段で測ったかをコメントに書くこと）で、
       本文の算出文字サイズが**実際に大きくなる**こと。
       いまは `:root` の `14px` が勝つので変わらない。これが RED になる検査。
     - 同じ 2 倍の状態で、既存の 3 幅（1280 / 768 / 360）すべてで
       **横スクロールが発生しない**こと（既存 invariant の強化版）。
     - 同じ 2 倍の状態で、入力欄と送信ボタンが画面内にあること
       （文字を大きくすると入力欄が画面外へ押し出されるのが典型的な崩れ方）。
     - 追加前に RED を確認すること（`screen-invariants` スキル）。
  4. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  5. REPORT に、`px` のまま残した箇所とその理由を列挙する。
  6. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
     `App.tsx` を触らない（インラインスタイルで `px` が出てくる場合は
     REPORT に記録して次のジョブへ回す）。
