# Task `T-PH6-111`: 入力欄を画面下部に固定し、参照範囲をその中のドロップダウンにする

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。オーナー指示 2026-11-16「参照範囲の設定は、チャット入力欄に
  claude や opencode のようにすっきりしたデザインで」。
- **Background**:
  - いま参照範囲は、会話の**上**に「参照範囲 [プルダウン]」として独立した行で置かれている。
    画面の一番上の目立つ位置を、ほとんど変えない設定が占めている。
  - Claude や opencode は、この種の設定を**入力欄の内側の小さなチップ**に置く
    （opencode の `composer` 内モデルチップ）。送信操作の近くにあり、かつ主張しない。
  - 追加の指摘（2026-11-17、実物を操作して）: 入力欄が**文書の末尾に置かれていて
    一緒にスクロールする**。会話が伸びると、入力するたびに下まで送る必要がある。
    チャット画面を開いている間は、入力欄は常に画面下部にあってほしい。
  - 同じく、参照範囲は OS 標準の `<select>` ではなく、
    **モデル選択バーと同じ形の滑らかなドロップダウン**にしてほしい。
- **Implementation Details**:
  1. **入力欄をチャット画面の下部に固定する**。会話がどれだけ伸びても、
     入力欄は常に見えていること。会話側だけがスクロールする。
     固定したことで最後の発言が入力欄の裏に隠れないこと（会話末尾に余白を確保する）。
     狭い画面・モバイル幅でも成立すること。
  2. 参照範囲の選択を、入力欄（コンポーザ）の下段、添付の `+` と送信ボタンの間へ移す。
     **OS 標準の `<select>` を使わず**、ボタン＋ポップアップで自前に組む。
     開閉には短いアニメーションを付ける（`prefers-reduced-motion` では無効にする）。
     見た目は角丸の小さなチップ。枠線は細く、既定では控えめな色。
     自前にする以上、`<select>` が無償で提供していたものを自分で満たすこと:
     キーボード操作（上下で移動、Enter で決定、Esc で閉じる）、
     読み上げ（`role="listbox"` / `aria-expanded` / 選択中の項目）、
     外側クリックで閉じる、開いている間フォーカスが外へ出ない。
  3. **機能は変えない**。選べる値（`all` / `shared` / `personal`）、送信時に渡す値、
     権限が無いときの扱いは現状のまま。
  4. **絵文字を使わない**（オーナー指示 2026-11-17）。記号が要るなら線画の SVG。
  3. 読み上げ名（`aria-label`）を必ず残すこと。チップにしたことで
     「何の選択なのか」が読み上げで分からなくなってはいけない。
  4. キーボードで到達・操作できること。フォーカス表示を消さないこと。
  5. 入力欄を光らせる・色付きの強調枠を付ける、といった装飾は加えない
     （`docs/planning/UI_IMPLEMENTATION_BASELINE.md` の決定事項）。
- **Acceptance Criteria**:
  1. 会話の上にあった参照範囲の行が無くなり、入力欄の中から選べる。
  2. `App.test.tsx` に、チップから参照範囲を変えて送信すると、
     **変更後の値がリクエストに乗る**ことを確認するテストがある。
  3. 読み上げ名とキーボード操作（上下・Enter・Esc）のテストがある。
  4. 会話が画面高を超えて伸びても入力欄が見えていることを確認するテストがある
     （会話側がスクロールし、入力欄は動かない）。
  5. 最後の発言が入力欄に隠れないことを確認するテストがある。
  4. `npm --prefix frontend run test` と `typecheck` が PASS。既存テストに退行がない。
  5. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
