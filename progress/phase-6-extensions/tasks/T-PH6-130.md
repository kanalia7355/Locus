# Task `T-PH6-130`: 出力上限を事後ではなく実行中に効かせる

## TASK DEFINITION (Assigned by Orchestrator)

- **なぜこの票があるか**: `T-PH6-104` の 18:23 のレビュー（`opencode/beam-free`）が
  挙げた Low を切り出したもの。設計変更を伴うので別票にした。
  **`T-PH6-104` の受入条件を落としたのではなく、ここへ移した。**

- **指摘（そのまま写す。消していない）**:
  `backend/app/sandbox.py` の `_run_subscript` は、`output_bytes` を
  **`subprocess.run` が標準出力・標準エラーを全部メモリに読み終えた後**に数えている。
  つまり悪意ある抽出器は、**時間切れになる前に親プロセスのメモリを食い潰せる**。
  上限は事後に適用されるだけなので、あふれそのものは止められていない。
  最小修正として示されたのは `subprocess.Popen` ＋逐次読み出しで、
  上限を超えた時点で**殺す**こと。

- **なぜ放置しないか（これがこの票の本題である）**:
  保証の記録は `output_bytes` を **`verified`** と書く。
  だが実際に守られているのは「**超えたら後から失敗にする**」であって
  「**超えさせない**」ではない。**`T-PH6-104` が直したのと同じ型の嘘**である
  （あの票は「環境を落とした」と記録しながら落としていなかった）。
  `DOCUMENT_EXTRACTION_BOUNDARY.md` §5 の作法は
  **弱い方の保証しか主張しない**ことなので、取れる道は 2 つだけである:
  **(a) 実行中に効かせて `verified` を本物にする**か、
  **(b) 主張を弱める**か。**(a) を推奨する。**
  (b) を採るなら、記録に出る文字列を変え、なぜ (a) にしなかったかを書くこと。

- **Implementation Details**:
  1. `_run_subscript` を `subprocess.Popen` に替え、標準出力・標準エラーを
     **逐次**読む。読んだ量が `output_limit` を超えたら
     **その場で木ごと殺す**（`T-PH6-104` の時間切れ処理が `kill_tree` 相当を
     持っているなら同じ道具を使う。新しい殺し方を 2 本目として作らない）。
  2. 既存の振る舞いを変えないこと:
     - 上限超過は `success=False`、`guarantees["output_bytes"] = "truncated"`、
       **本文を出さない**（これは現状どおりで、検査もある）。
     - 時間切れ・異常終了・正常終了の既存の分岐と記録の文字列は変えない。
  3. **メモリが実際に守られていることを、合成の抽出器で表明する。**
     上限より**はるかに大きい**量を出し続ける抽出器を使い、
     **親が読み込んだ量が上限＋小さな余裕を超えないこと**を表明する
     （例: 読み取り総量を観測できる形にして上限の数倍を超えないことを見る）。
     「結果が失敗になった」だけでは**事後でも通る**ので、それは証拠にならない。

- **Acceptance Criteria**:
  1. 上限を超える出力を出す抽出器に対し、**親が読み込んだ総量が上限に対して
     有界であること**を検査が表明している（失敗したことだけを見る検査は不可）。
  2. 既存の `output_bytes` 系の検査（上限超過で `truncated`・本文なし）が
     **1 件も消えておらず**、通っている。
  3. `guarantees["output_bytes"]` の主張が実装と一致している
     （実行中に効かせたなら `verified` のまま。弱めたなら文字列を変え、理由を報告に書く）。
  4. **検査が落ちることを確かめた**: 逐次読み出しを一時的に元の
     「全部読んでから数える」形に戻すと受入条件 1 の検査が **FAIL** することを
     手で確認し、**その失敗メッセージを報告に書く**。
  5. 時間切れの既存動作に退行がない（`tests/test_sandbox_boundary.py` 全件 PASS）。
  6. 変更が allowed_paths 内に収まっている。

- **やってはいけないこと**:
  - docker 経路に触らないこと（`T-PH6-129` の仕事）。
  - 殺し方を新しく作らないこと。既にある木ごと殺す道具を使う。
  - 検査を消して通すこと。
