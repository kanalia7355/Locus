# Task `T-PH6-105`: チャット行の投影関数を切り出す（UI 方針・第 1 段）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針（`docs/plans/UI_OPENCODE_RESEARCH.md` §2 #3、§3.2）。
  オーナー決定 2026-11-16「chatgpt や claude のような UI」。
- **Background**:
  - `frontend/src/App.tsx` は 1900 行を超え、チャット描画は `messages.map` の
    直接描画になっている。ストリーミング中の更新で会話全体が再描画される。
  - OpenCode は「メッセージ列 → 表示行」の**純粋な投影関数**を置き、安定キーで
    行単位にメモ化している（`session-ui/src/timeline/projection.ts`）。
  - **本タスクは `App.tsx` を変更しない**。まず投影関数を純粋な単体として作り、
    テストで固定する。`App.tsx` の差し替えは次のジョブにする。
    1900 行のファイルの描画を一度に書き換えると、レビューで差分が読めなくなるため。
- **Implementation Details**:
  1. 新規 `frontend/src/chatRows.ts` に、会話のメッセージ配列を「表示行」の配列へ
     変換する純粋関数を書く。副作用・React への依存・`Date.now()` の使用は禁止
     （同じ入力から必ず同じ出力が出ること）。
  2. 行の種類は、現在 `App.tsx` が実際に描き分けているものに合わせる。
     実装前に `App.tsx` のチャット描画を読み、**実在する種類だけ**を列挙すること。
     存在しない種類（ツール実行など）を勝手に足さない。
  3. 各行は**安定キー**を持つ。同じメッセージは、回答が後から確定しても
     同じキーのままであること。キーは `message.id` を基礎にする。
  4. 権限失効でマスクされた回答（`answer_hidden`）、出典、モデル名、
     生成中・待機中の状態は、既存の表示と同じ意味で行に載せる。
     **バックエンドに無い状態を作らない**。
  5. 型は既存の `frontend/src/api.ts` の型を import して使う。新しい型を二重定義しない。
- **Acceptance Criteria**:
  1. `frontend/src/chatRows.test.ts` に次の合成テストがある。
     - 空の会話 → 空の行配列
     - 同じメッセージ列を 2 回与えると**同一のキー列**になる（安定キー）
     - 回答が未確定 → 確定へ変わっても、その行のキーが変わらない
     - `answer_hidden` の回答は本文・モデル名・出典が行に載らない
     - 出典つきの回答は、出典が行から辿れる
  2. 関数が純粋であること（同じ入力で同じ出力）がテストで確認されている。
  3. `App.tsx` は変更していない（許可パスに入っていない）。
  4. `npm --prefix frontend run test` が全件 PASS。
  5. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
