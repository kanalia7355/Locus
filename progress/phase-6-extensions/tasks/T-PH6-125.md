# Task `T-PH6-125`: ダイアログの見た目と light dismiss を仕上げる

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`「`ui-components/dialog`」
  （`GoogleChrome/modern-web-guidance`）。
- **このジョブが存在する理由**: `T-PH6-116`（出典モーダルを `<dialog>` へ移す）は
  3 回とも 1800 秒の時間切れで止まった。**1 回の試行に収まらない量を 1 票にしていた**のが
  原因なので、2026-11-19 の裁定で「置き換えと既存の挙動の維持」までを `T-PH6-116` に残し、
  上乗せ分をこの票に切り出した。`T-PH6-116` が入ってからでないと衝突する。
- **Background**:
  - `T-PH6-116` は既存のトークン `--color-backdrop` をそのまま使い、
    背景の暗転を**移行前と同じ見た目**で残した。崩さないことが目的だったので、
    暗転の濃さ・ぼかし・角丸・影といった見た目には手を付けていない。
  - 背景クリックで閉じる挙動は、`closedby` に頼らず JS のフォールバックで実装されている
    （Safari が `closedby` 未対応のため）。属性で宣言できる分はまだ宣言していない。
  - 入場アニメーションは `T-PH6-116` の受入条件から明示的に外してある。
- **Implementation Details**:
  1. **`closedby="any"` を足す。ただし JS のフォールバックを消さないこと。**
     Safari は未対応で、属性だけにすると背景クリックで閉じられなくなる。
     両方あるときに**二重に閉じない**ことをテストで固定すること
     （属性が効くブラウザで `close()` が 2 回走っても状態が壊れないこと）。
  2. `::backdrop` の見た目を整える。`--color-backdrop` を使い、**新しい色を導入しない**。
     ぼかしを入れる場合は `backdrop-filter` の有無で見た目が破綻しないこと。
  3. 入場アニメーションは `@starting-style` + `transition-behavior: allow-discrete`。
     退場側は Firefox / Safari が `overlay` 未対応なので即時で構わない。
     `styles.css` の `prefers-reduced-motion` 一括停止がそのまま効くことを確認すること
     （**新しい `@media (prefers-reduced-motion)` ブロックを足さない**）。
  4. `@supports` や `CSS.supports()` でこれらの機能を判定しないこと
     （全ブラウザが対応を名乗るため判定が意味を持たない。ガイドの注意）。
- **Acceptance Criteria**:
  1. `closedby="any"` が付き、かつ背景クリックの JS フォールバックが**残っている**。
  2. `App.test.tsx` に、背景クリックと `closedby` の両方が効いても
     状態が壊れないテストがある。
  3. `frontend/e2e/appearance.spec.ts` に次の検査を追加する。
     - 入場アニメーションの**後**にフォーカスが初期位置（「閉じる」）にあること
       （アニメーション中にフォーカスが迷子にならない）
     - `prefers-reduced-motion: reduce` でアニメーションが走らないこと
     - 追加前に、現状でこれらの検査が意味を持つことを確認すること
       （`screen-invariants` スキルの手順。まず測る）
  4. `npm --prefix frontend run test` / `typecheck` / `lint` が PASS。
     `npm --prefix frontend run test:appearance` が**全件** PASS。
  5. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
