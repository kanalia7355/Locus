# Task `T-PH6-121`: チャット列を容器クエリで分岐させる（サイドバーの開閉を幅判定に反映する）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`
  「`css/size-aware-styling`」（`GoogleChrome/modern-web-guidance`）。
- **Background**:
  - `styles.css` の幅の分岐は `@media` だけで書かれている。
    `@media` が見るのは**ビューポートの幅**で、
    **サイドバーを開いているときの実際のチャット列の幅を知らない**。
  - 具体的な帰結: ビューポート 1280px でサイドバーが開いていると本文は 1000px 前後だが、
    「1280px 用」の分岐が当たる。サイドバーを畳むと本文は 1280px 近くになるが、
    分岐は変わらない。つまり**本文に当たっている指定は、本文の幅と対応していない**。
    これは「幅で崩れる」系の不具合が将来また出る構造的な原因であり、
    `appearance.spec.ts` の 3 幅の検査は（サイドバーの状態を固定して測るので）
    これを見つけられない。
  - 容器クエリは **Baseline 2023-02**（Chrome 105 / Edge 105 / Firefox 110 / Safari 16）。
    ポリフィル不要。未対応ブラウザは `@media` の指定に落ちるので段階的に入れられる。
  - **`T-PH6-112` の後に置く理由**: サイドバーの作り直しで列の構造そのものが変わる。
    先にやると作り直しと衝突する。
- **Implementation Details**:
  1. チャット列の親（`.main` またはチャット領域を包む要素）に
     `container-type: inline-size` と `container-name` を付ける。
     名前を付けること（無名の容器は、入れ子が増えたときにどれに当たっているか
     読めなくなる）。
  2. **本文の幅に依存する分岐を `@media` から `@container` に移す。**
     対象は、本文の読み幅（`max-width`）、発言の左右余白、
     入力欄の中の操作列の折り返し、メッセージ内の表の扱い。
  3. **`@media` のまま残すもの**（移さないこと）:
     サイドバーを畳むかどうかの判定そのもの、
     画面全体の縦の構成（モバイル幅で 1 列にする等）。
     これらはビューポートの性質であって容器の幅ではない。
     どちらに入れたかを REPORT に書くこと。
  4. 未対応ブラウザ向けに `@supports (container-type: inline-size)` で包むかは任せる。
     包まない場合、未対応ブラウザでは既存の `@media` 指定が残って
     いまと同じ見た目になること（＝悪化しないこと）を確認すること。
  5. 容器クエリ単位（`cqi` 等）を**使わないこと**。
     文字サイズの扱いは `T-PH6-119` が `rem` で統一するので、
     ここで別の単位系を混ぜると両方が読めなくなる。
     本ジョブは分岐の条件だけを移す。
  6. 見た目を変えないこと。これは分岐の根拠を正す作業で、意匠の変更ではない。
- **Acceptance Criteria**:
  1. チャット列の親に名前付きの `container-type: inline-size` がある。
  2. 本文の読み幅と発言の余白の分岐が `@container` で書かれている。
  3. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - ビューポート幅を 1280px に固定したまま、**サイドバーを畳んだ状態と
       開いた状態で、本文の読み幅（発言要素の幅）が異なる**こと。
       いまは `@media` だけなので両者が同じになる。これが RED になる検査。
     - サイドバーを畳んだ状態でも、既存の 3 幅すべてで横スクロールが起きないこと
       （既存 invariant をサイドバーの両状態で回す）。
     - 追加前に RED を確認すること（`screen-invariants` スキル）。
  4. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  5. REPORT に、`@container` へ移した分岐と `@media` に残した分岐の一覧と理由を書く。
  6. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
