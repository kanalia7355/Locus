# Task `T-PH6-109`: 製品名を Locus にし、上部の帯が流れて消えないようにする

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。オーナー指摘 2026-11-16（実物を操作しての指摘）。
- **Background**:
  1. **名前**: 画面に「研究資料室」が 2 か所ある（`App.tsx:171`、`App.tsx:951`）。
     オーナー指示で製品名は **Locus** に統一する。`App.tsx:171` は
     「研究資料室 <span>Locus</span>」という併記なので、併記をやめて Locus だけにする。
  2. **上部の帯**: `styles.css:199-205` のシェルが `min-height: 100dvh` のグリッドで、
     `.topbar` はその 1 行目。本文が伸びると**ページ全体**がスクロールし、
     上部の帯（製品名・プロジェクト切替・利用者名・設定）が画面外へ流れて消える。
     設定画面のように縦に長い画面で特に目立つ。
- **Implementation Details**:
  1. シェルの高さを `min-height: 100dvh` から**ビューポート高に固定**し、
     スクロールは本文側（主要コンテンツ領域）だけで起こるようにする。
     `.topbar` は常に見えていること。`.sidebar` は `position: fixed; inset: 64px auto 0 0`
     で既に追従しているので、本文側の変更と整合させること。
  2. 狭い画面（モバイル幅）でも本文がはみ出さないこと。既存の
     `e2e/workspace.spec.ts` の「sidebar, long names, mobile widths and reduced motion」
     を壊さないこと。
  3. 名前の変更は表示文字列のみ。識別子・API・テスト ID は変えない。
- **Acceptance Criteria**:
  1. 画面に「研究資料室」が 1 つも残っていない（`App.tsx` を grep して 0 件）。
  2. 本文を長くスクロールさせても上部の帯が見えたままであることを、
     テストで確認する（シェルがページ全体をスクロールさせない構造になっていること、
     または E2E でスクロール後も帯が可視であること）。
  3. `npm --prefix frontend run test` と `typecheck` が PASS。既存 E2E に退行がない。
  4. 変更は許可パス内に収まる。既存テストの削除・緩和は禁止。
