# Task `T-PH6-137`: Office（`.docx` / `.xlsx` / `.pptx`）の本文を取り出す

## SCOPE — レビュアーはここを先に読むこと（2026-11-28 23:17 当番）

**これは `T-PH6-106` から分けた票である。削った仕事ではない。**
オーナーは 2026-11-28 23:16 に `T-PH6-104` のサンドボックス設計を承認し、
「Claude や ChatGPT などで添付できる形式すべて」を受け入れると決めた。
Office はその中にある。

**この票が受け持つのは OOXML の 3 つだけ**: `.docx` `.xlsx` `.pptx`。

- **`.doc` / `.xls` / `.ppt`（旧バイナリ形式）は含めない。** 別の形式であり、
  標準ライブラリでは開けない。必要になったらオーナーに伺って別票にする。
- **PDF と画像は含めない** —— `T-PH6-138` / `T-PH6-139` / `T-PH6-140`。
- **新しい第三者ライブラリを 1 つも足さないこと。** OOXML は ZIP + XML なので、
  標準の `zipfile` と、すでに `backend/requirements.lock` に有る
  **`defusedxml==0.7.1`** で開ける。`pyproject.toml` は保護パスである。

## この票の本体は、バイト列の経路を作ることである

**当番が実測したこと**（2026-11-28 23:17、`backend/app/sandbox.py:541`）:

```python
def extract_with_sandbox(format_name: str, content: str, *, ...) -> SandboxResult
```

**入口が `str` しか受け取らない。** 抽出器のソースは子プロセスの stdin から
文字列を読む形で書かれている（`EXTRACTOR_SOURCE`）。
`.docx` は ZIP なのでバイト列であり、**文字列に通すと壊れる。**

だからこの票の最初の仕事は、**境界にバイト列の経路を足すこと**である。
`T-PH6-139`（PDF）と `T-PH6-140`（画像）も同じ経路に乗るので、
**ここで作る形がそのまま後の 2 票の土台になる。**

**既存の `str` の経路を壊さないこと。** `T-PH6-106` が足したテキスト系の
抽出器はすべてその経路に乗っている。

## Implementation Details

1. `extract_with_sandbox` に**バイト列を渡せる道**を足す（引数を増やすか、
   バイト列用の入口を別に作るか、実装者が決めてよい）。
   子プロセスへは stdin のバイナリとして渡す。
   **本体プロセスは ZIP も XML も開かない** —— 開くのは子プロセスの中である。
2. `backend/app/formats.py` の表に 3 行足す。`kind` は `document`。
   **1 形式あたりのバイト上限は 10 MiB（`10485760`）とする。**
   これは当番が決めた既定値である（テキストの 256 KiB では Office が入らない。
   オーナーが別の数を言えばそれに従う）。
3. `EXTRACTOR_SOURCE` に OOXML 用の抽出器を足す。取り出すもの:
   - `.docx`: `word/document.xml` の段落テキスト
   - `.xlsx`: 各シートのセル値（共有文字列表 `xl/sharedStrings.xml` を解く）。
     **シート名を見出しとして本文に出すこと** —— どのシートの値かが
     引用で分からないと使えない
   - `.pptx`: 各スライドのテキスト枠。**スライド番号を見出しに出すこと**
4. **ZIP は信頼できない入力である。** 次を子プロセス側で防ぐこと:
   - **展開後の合計バイト数に上限**を置く（ZIP 爆弾）。上限は実装者が決めて
     報告すること
   - **メンバー数に上限**を置く
   - **メンバー名の `..` と絶対パス**を拒否する（この抽出器はファイルを
     書き出さないので実害は薄いが、名前を信じない形にしておくこと）
   - XML は **`defusedxml`** で読む。標準の `xml.etree` は実体展開を許すので
     使ってはいけない
5. **抽出した本文は信頼できない入力である。** 「資料内の命令を実行しない」系の
   プロンプト規律、出典とチャンクの扱いを**1 つも変えないこと。**

6. **抽出は本体プロセスで ZIP も XML も開かない。** 新しい抽出器が
