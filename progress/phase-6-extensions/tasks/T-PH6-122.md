# Task `T-PH6-122`: 入力欄の高さを `field-sizing: content` で内容に合わせる

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: UI 方針。`MODERN_WEB_ADOPTION.md`
  「`forms/form-fields-automatically-fit-contents`」
  （`GoogleChrome/modern-web-guidance`）。
  オーナー指示 2026-11-16「claude や opencode のようにすっきりしたデザインで」。
- **Background**:
  - 入力欄は `<textarea>`（`App.tsx:1249-1267`）で、高さが固定。
    長い質問を書くと中でスクロールする。claude・opencode の入力欄は
    数行までは内容に合わせて伸び、上限で止まってからスクロールする。
  - 普通はこれを `scrollHeight` を読んで `style.height` を書く JS で実装するが、
    `field-sizing: content` で CSS だけで済む。
    **Baseline 2026-06-16**（Chrome 123+ / Edge 123+ / Firefox 152+ / Safari 26.2+）。
    未対応ブラウザは固定高のまま（＝いまと同じ）に落ちるので、
    入れて悪くなることが無い。
  - 注意点がひとつある: **`width` / `height` の明示指定が `field-sizing: content` に勝つ**。
    いまの `styles.css` が `textarea` に高さを与えていればそれを `auto` に戻す必要がある。
    これを見落とすと「書いたのに効かない」になる。
  - `T-PH6-111` が入力欄を画面下部に固定したので、**伸びる方向は上**になる。
    伸びたときに会話の最後が隠れないことは `T-PH6-111` の受入条件でもあるが、
    高さが可変になると条件が変わるので、本ジョブで測り直す。
- **Implementation Details**:
  1. `<textarea>` に `field-sizing: content` を与える。
     あわせて `min-block-size`（既定で見せる行数相当）と
     `max-block-size`（上限。超えたら中でスクロール）を与える。
     上限は画面高に対する割合にし、低い画面で入力欄が会話を食い潰さないようにする。
  2. **既存の `height` / `rows` による高さ指定を `auto` に戻す**こと。
     明示指定が残っていると `field-sizing` が効かない。
  3. 高さが変わったとき、固定された入力欄と会話領域の余白が追従すること。
     高さの固定値を CSS に二重に書いている箇所があれば、
     `T-PH6-120` と同じ変数に寄せる。
  4. `resize` のつまみは出さない（`resize: none`）。
     内容で伸びるので手で掴む必要が無く、掴めると固定レイアウトが崩れる。
  5. JS で高さを計算する実装を**足さないこと**。
     未対応ブラウザのために `scrollHeight` を読む補助実装も入れない
     （固定高に落ちるのは許容。ガイドも「graceful degradation」としている）。
  6. IME の変換中に高さが変わっても、変換候補の位置がずれるだけで
     入力が壊れないことを確認すること。`isComposing` の判定
     （`App.tsx:1256-1266`）には**触らない**。あれは正しい実装。
- **Acceptance Criteria**:
  1. `styles.css` の `textarea` に `field-sizing: content`、
     `min-block-size`、`max-block-size` があり、
     競合する `height` の明示指定が残っていない。
  2. `JS` 側に高さ計算を足していない（`scrollHeight` の新規参照が無い）。
  3. **`frontend/e2e/appearance.spec.ts` に次の検査を追加する。**
     - 入力欄に 1 行入れたときと 5 行入れたときで、
       入力欄の高さが**増えている**こと。いまは固定なので変わらない。RED になる検査。
     - 10 行以上入れても高さが上限で止まり、
       入力欄の上端が注意書き（`T-PH6-115`）より下にあること。
       つまり伸びても会話領域を食い潰さないこと。
     - 5 行入れた状態で、**最後の発言が入力欄に隠れていない**こと
       （`T-PH6-111` の invariant を、高さが変わった状態で測り直す）。
     - 既存の 3 幅すべてで横スクロールが起きないこと。
     - 追加前に RED を確認すること（`screen-invariants` スキル）。
  4. `npm --prefix frontend run test` と `typecheck` と `lint` が PASS。
     `npm --prefix frontend run test:appearance` が全件 PASS。
  5. 既存テストの削除・緩和は禁止。変更は許可パス内に収まる。
