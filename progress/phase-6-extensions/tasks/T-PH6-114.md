# Task `T-PH6-114`: python を実行して作図する（`UI-007` / `D-ANALYSIS`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `UI-007`、`D-ANALYSIS`。
- **オーナー決定 2026-11-17**（`OWNER_DECISIONS.md` に記録）:
  1. **出どころ**: 回答の文章の隣に、根拠となった引用資料をラベルで出す。**絵文字は使わない**。
  2. **作図**: **B を採用** —「AI が python コードを動かして作図するのがいい」。
     ただし「**隔離部屋が完成したら取り組むこと**」。
  3. **資料に根拠のない質問**: 答えてよい。あわせて常時表示の注意書きを出す（`T-PH6-115`）。
- **着手できない理由（意図的）**: `depends_on: T-PH6-104`。
  コード実行は、ファイル解析より踏み込んだ境界になる。解析は「攻撃者が選んだ**データ**を
  読む」だが、作図は「モデルが書いた**命令**を実行する」。隔離部屋が実在し、
  その境界が破れたら落ちるテストで固定されるまで、このジョブは出さない。
- **確定時に受入条件へ入れること**:
  1. 実行するのは**モデルが生成したコードだけ**。利用者の資料は読み取り専用で渡し、
     原本を書き換えられないこと。
  2. 出力は**画像 1 枚と標準出力のみ**。それ以外の成果物を外へ出さない。
  3. ネットワークは遮断。実行時間・メモリ・出力サイズの上限は、
     作図用に `T-PH6-104` とは別枠で設ける（図の生成は解析より重い）。
  4. 実行が上限に当たった・失敗した場合は、**図が無いことを明示**する。
     「それらしい図」を代わりに出さない。
  5. 生成されたコードは利用者が**見られる**こと（何を計算したのか確認できないと、
     図を信用する根拠がない）。
  6. 出どころのラベル: 図が添付データ由来なのか共有資料由来なのか、
     文章のどの部分が資料に基づきどの部分がモデルの知識なのかを、部分ごとに示す。
  7. 境界が破れたら落ちるテスト。少なくとも「ネットワークへ出ようとするコード」
     「終わらないコード」「巨大な出力を出すコード」「サンドボックス外へ書こうとするコード」
     「資料の原本を書き換えようとするコード」の 5 つが、すべて失敗として観測されること。
     本物のマルウェアは使わない（合成のみ）。
