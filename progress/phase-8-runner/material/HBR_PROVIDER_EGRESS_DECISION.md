## HBR-005 / HBR-007 / HBR-001: 外部 AI プロバイダ宛て egress 承認の 3 案

以下の 3 案は、既存の境界設計文書およびコード CHECK 制約を変更することになるかどうかを明示するために提示された設計選択肢です。各案のエンドポイント行の状態はすべて `DESIGN ONLY — NOT APPROVED` としています。

### 案 A — サンドボックスに宛先限定の穴を開ける
- **概要**: CLI を隔離境界の中で走らせ、その境界にだけプロバイダ宛ての通信を許す。
- **変更する既存境界**: `HYBRID_RUNNER_COMMUNICATION_DESIGN.md` §2 の「ジョブサンドボックスはネットワークを持たない」原則の変更。
  これによりサンドボックス内からプロバイダ API への直接通信が可能となる。
- **変更の影響**: 侵害されたジョブが直接外部に出られてしまう攻撃面の拡大。
- **エンドポイント**（HYBRID_RUNNER_COMMUNICATION_DESIGN.md §3.2 形式、すべて `DESIGN ONLY — NOT APPROVED`）:
  | 宛先 | ポート | プロトコル | 方向 | 認証認可要件 | 検証計画 | 現状 |
  |------|--------|------------|------|------------|----------|------|
  | プロバイダ API | 443 | HTTPS | 外向き | mTLS + 証明書束縛 | 設計検討中 | `DESIGN ONLY — NOT APPROVED` |

### 案 B — Runner ホスト側の仲介が代行する
- **概要**: ジョブは外に出られず、仲介プロセスだけがプロバイダと通信する。
  `HYBRID_AGENT_ADAPTER_DESIGN.md` §7.4 の `BR-4`（ローカルプロキシ／トークンブローカ）に近い形。
- **変更する既存境界**: なし（ジョブサンドボックスのネットワーク非所持は維持）。
- **却下理由** (`HYBRID_AGENT_ADAPTER_DESIGN.md` §7.4 Q4): 同設計は Q4 のもとで **却下済み** である。
  却下理由: 「CLI の非公式なcircumvention（回避）を必要とし、セキュリティポリシーに違反する」。
  覆すためには: OS レベルで CLI サンドボックスが資格ストアにアクセスできないことを証明し、正式なプロキシ API を導入すること。
- **エンドポイント**（同形式、すべて `DESIGN ONLY — NOT APPROVED`）:
  | 宛先 | ポート | プロトコル | 方向 | 認証認可要件 | 検証計画 | 現状 |
  |------|--------|------------|------|------------|----------|------|
  | プロバイダ API | 443 | HTTPS | 外向き | mTLS + ホスト資格証明 | 設計検討中 | `DESIGN ONLY — NOT APPROVED` |

### 案 C — 外部 AI を使わず、ローカル LLM だけを Runner で動かす
- **概要**: `ADAPTER` §6.2 の Option 0（no-supply）。外部 AI プロバイダを使用せず、Runner 内で動作するローカル LLM only で代用する。
- **変更する既存境界**: 既存の境界を **1 つも変更しない**。現在の CHECK 制約と sandbox 設計のまま。
- **HBR-001 の未満足**: 外部 AI / ツールを使用できないため、`HBR-001` 「外部 AI を隔離された作業部屋で動かす」要件を満たさない。代替としてローカル LLM only の提供となる。
- **エンドポイント**（同形式、すべて `DESIGN ONLY — NOT APPROVED`）:
  | 宛先 | ポート | プロトコル | 方向 | 認証認可要件 | 検証計画 | 現状 |
  |------|--------|------------|------|------------|----------|------|
  | なし | — | — | — | — | — | `DESIGN ONLY — NOT APPROVED` |
