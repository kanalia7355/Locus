## 1. 分類値の束と順序

登録済みの `backend/app/agents/registry.py` （36 行）の値を 1 対 1 で固定する。

| 英語値 | 日本語相当 | 意味 |
|---|---|---|
| `none` | なし（未分類） | **分類が無い状態**。最下位ではなく「拒否を意味する状態」である。 |
| `public` | 公開 | 公開範囲で扱える最も低い分類。 |
| `personal` | 個人 | 個人レベルの範囲。 |
| `research_shared` | 研究共有 | 研究コミュニティ内で共有。 |
| `confidential` | 機密 | 最も制限の強い分類。 |

- `none` は「分類が無い」状態であり、5 値の並びにおける最下位ではなく、**どこにも属さず問い合わせ・処理そのものを拒否する状態**であることを明記する。
- 昇順（より広い範囲からより狭い範囲へ）: `public < personal < research_shared < confidential`
- 継承の `inherit-max` 規則では、この順序に従って「最大値」を決定し、より低い値への降格は許さない。

## 2. 誰が、いつ付けるか

- **責任主体**: ドキュメント/チャンクの**取り込み元（投入者）**が分類を決定する。管理者が上限を締める場合があるが、初期値は投入者が責任を持って選択する。
- **タイミング**: 取り込み経路の**最初の関門**（`ingestion` ゲートの直前）で分類を決定し、以降の経路で継承・参照する。
- **既定値の考慮**: 既定値を `none` とする場合、それが「未分類を黙って通す」ことにならない理由を明記する。
  - `none` は「明示的に分類が未設定」を表し、これに基づいて処理を継続してよいパスは存在しない。すべての 8 経路で `none` に対する明確な deny/allow の線引きが必要。
  - 既定値として `none` を採用するなら、関門で `none` が検出された際常に deny するというポリシーを文書化し、既存データ移行計画とセットでオーナー承認を得ること。

## 3. 派生の継承

チャンク・回答・引用・成果物は、出典の**最大分類**を継承する（inherit-max、降格不可）。

### 3.1 継承の式

複数の出典 $s_1, s_2, \dots, s_n$ があるとき、派生分類 $C_{der}$ は:

$$
C_{der} = 
\begin{cases}
\textbf{deny} & \text{if any } s_i \text{ has classification } = \text{``none''} \\
\max_{\text{order}}(C_{s_1}, C_{s_2}, \dots, C_{s_n}) & \text{otherwise}
\end{cases}
$$

- `none` が 1 件でも含まれていれば、その経路全体で**拒否**する。
- それ以外の場合、5 値の昇順 `public < personal < research_shared < confidential` に従い、source 分類のうち最大のものを採用する。
- 降格（派生先が継承元の最大値より低くなること）は絶対に起きない。

### 3.2 合成データでの検証例

- 派生元に `confidential` と `public` が混ざれば結果は `confidential`。
- 派生元に `none` が 1 件混ざれば結果は拒否（分類値としての `none` は出ない）。
- 派生元が `public` だけなら結果は `public`。
- 派生元が `confidential` だけなら結果は `confidential`。

### 3.3 継承グラフの単調性

- `inherits` による有向グラフに循環はない。
- 各経路の派生分類は、その経路が継承するすべての源の `max` を**下回らない**（降格しない）。
  採用値はその `max` そのものである。§3.1 と同じことを単調性の言葉で言い直している。
- 合成データで降格が起きないことを表明する。

## 4. 既存データの移行

現在 `documents` テーブル（`backend/app/service.py` 450 行目）には分類列が存在しない。fail-closed をそのまま当てると**既存の全文書が拒否され、現行の検索と回答が停止する**。これを避けるための 2 案の移行案。

### 4.1 案 A: 移行期間の明示的 `unclassified` 状態

- `none` の代わりに一時的に `unclassified` という分類値を導入し、既存文書をこれにマッピングする。
- 移行期間中は一部の経路で `unclassified` を許容し、逐次的に適切な分類に更新させる。
- **影響範囲**:
  - **壊れる機能**: 既存の検索クエリが `unclassified` を含むドキュメントを返すようになり、検索結果に含まれる範囲が広がる可能性あり。検索フィルタの更新が必要。
  - **新規実装**: `unclassified` という分類値の管理コード、移行スクリプトが必要。
  - **緩やかな移行**: 既存機能を止めずに段階的に移行できる。

### 4.2 案 B: パス別の線引き（許容経路／拒否経路）

- `none` をそのまま維持し、8 経路のうち「分類ありきで動く経路」と「未分類でも動く経路」を明示的に線引きする。
- 例: `retrieval` 経路では `none` を許容し、検索結果に含める。`answer` 経路では `none` を拒否し、質問に対する回答を生成しない。
- **影響範囲**:
  - **壊れる機能**: `answer`、`citation`、`export`、`runner_artifact` 経路では、`none` 分類のデータに対する現在の処理がすべて停止する。これらの経路で `none` を持つ文書に対する回答・引用・エクスポートができなくなる。
  - **新規実装**: 経路ごとの `none` 許容フラグやポリシー定義が必要。
  - **明確な責任**: どの経路で `none` を許容するかが明確になり、オーナーが意図的な判断を下せる。

### 4.3 両案の比較まとめ

| 項目 | 案 A（明示的 `unclassified`） | 案 B（パス別線引き） |
|---|---|---|
| 移行のしやすさ | ◳ 既存処理を変えずに済むが、`unclassified` という新値が必要 | △ 経路ごとの判断が必要で設計が複雑 |
| 既存機能への影響 | 緩やか（徐々に分類を埋めていく） | 突然：`answer` などの経路で停止する |
| 運用の明確さ | `unclassified` 値の意味が統一しにくい | 経路によって動作が異なり混乱の可能性 |
| オーナー決断の必要性 | `unclassified` という新分類を導入するか | どの経路で `none` を許容するかの線引き |

- どちらを採るかはオーナー判断として `未決` に残すが、**両案の影響範囲は以上の通り書く**。

## 5. 関門の位置（§3.2 E6 の配置）

`HYBRID_STEP2_AGENT_REGISTRY_DESIGN.md` §3.2 E6（プロンプト・添付の組み立て**前**に関門を置く）を、実際のコード上の各処理の**直前**に配置する。以下の 8 経路全てについて、実在する関数の手前に配置する。

| 経路 ID | ゲート配置場所（関数名） | 所在ファイル |
|---|---|---|
| `ingestion` | `send()` 関数の冒頭、添付文書読み込み前 | `backend/app/service.py` |
| `chunking` | `_document()` 関数の冒頭、文書を DB から読み込む直前 | `backend/app/service.py` |
| `retrieval` | `_can_read()` 関数の冒頭、文書の持出し権限チェック前 | `backend/app/service.py` |
| `answer` | `send()` 関数内の answer 生成直前、モデルへのプロンプト組み立て前 | `backend/app/service.py` |
| `citation` | `_citations()` メソッドの冒頭、参照文献のリスト生成前 | `backend/app/service.py` |
| `export` | runner_artifacts 持ち出し前（レポジトリ層） | `backend/app/agents/registry.py` |
| `runner_input` | `chat_jobs` dispatch 直前、ランナーへの入力組み立て前 | `backend/app/service.py` |
| `runner_artifact` | `runner_artifacts` 持ち出し直前、成果物の永続化前 | `backend/app/agents/registry.py` |

- どの経路でも `on_unknown` は常に `deny` とする。未分類（`none`）が検出された場合、その経路の処理は即座に中断しエラーとする。
- 関門はすべて**プロンプト・コンテキスト組み立ての前**に配置され、添付の組み込みも含む。
