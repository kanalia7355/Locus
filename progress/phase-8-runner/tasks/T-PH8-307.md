# Task `T-PH8-307`: 使い捨てラボで、本物の境界にプローブを当てる（`HBR-004` / `HBR-010`）

## この票は入場条件が揃うまで動かせない。器である

**`T-PH8-305` から分けた票である。削った仕事ではない。**
オーナーは 2026-11-28 23:16 に「いい感じにしてほしい」と設計を委ねたが、
**次の 2 つは設計の問題ではなく、オーナーしか与えられないものである。**

### 1. 使い捨ての検証環境と、そこで脱出試験を走らせる承認

`HYBRID_ISOLATION_PROFILES.md` §6 冒頭が
**「隔離された使い捨てラボ・合成データのみ・外部経路なし」**を要求し、
**「オーナーの作業機や統合ブランチを動かしている機械で走らせてはならない」**
と書いてある。

**この機械はその両方である** —— オーナーの作業機であり、`jobloop` の
統合ブランチが動いている機械である。だから**ここでは走らせられない。**
`T-PH6-135`（docker の実機確認）と同じ形の「機械の用意」である。

**要るもの**: どの実機を使うか（使い捨てであること）、そこで敵対的な
プローブを走らせてよいという承認、そして**その実機の記述をこの票に
書いてから** `todo` に倒すこと。

### 2. 残余リスクの受諾

`HYBRID_ISOLATION_PROFILES.md` §2.1 末尾・§8 が、
**受諾が無い候補は全テストが通っても活性化できない**と定めている。
受けるリスクは候補ごとに違う（`T-PH8-304` の
`material/HBR_ISOLATION_SELECTION.json` に 4 候補分が記録済み）:

- **共有カーネル／ハイパーバイザ**: 境界はホストのカーネルか
  ハイパーバイザに依存する。そこが破られれば境界も破られる。
- **ローカル管理者**: ホストの管理者は境界を無効化できる。
  主張できる境界の外に居る。
- **L-D / L-S のみ**: Linux のファイルによる保管は、ホスト管理者に対する
  保護を主張できない（`HYBRID_RUNNER_TRUST_DESIGN.md` §3.3）。

**リスクを受けるのはオーナーであって当番ではない。**

### 3. プロファイルの選定（`T-PH8-304` の `selected`）

4 候補（`W-D` Windows デスクトップ / `W-S` Windows サーバ /
`L-D` Linux デスクトップ / `L-S` Linux サーバ）のどれを配備対象にするか。
**4 候補の証跡は相互に流用できない**（§3 冒頭）ので、
選ばれていない候補のためのプローブは 1 本も意味を持たない。

**当番の推奨は `W-D`** —— 製品が動いているのはこの形である。
`T-PH8-305` に、Opencode が Windows で `AssignProcessToJobObject`
（Job Object）を使っているという実測と合わせて書いた。

**`selected` を当番が埋めてはいけない。** `T-PH8-304` の受入条件が
`selected: null` / `independent_reviewer: null` を要求して通っているので、
当番が埋めると受入条件を事後に書き換えることになる。
