# Task `T-PH8-305`: 隔離境界を攻撃する合成プローブ・ハーネス（`HBR-004` / `HBR-010`）

## TASK DEFINITION (Assigned by Orchestrator)

- **Requirement IDs**: `HBR-004`（OS が強制する隔離）、`HBR-010`（モジュール／トランスポート分離）。
  根拠: `docs/plans/HYBRID_ISOLATION_PROFILES.md` §6、
  `docs/plans/HYBRID_ISOLATION_ENGINEERING_DETAIL.md` §3.1〜§3.3、
  `docs/security/HYBRID_AGENT_THREAT_MODEL.md` の `T-E3` `T-E4`。

- **着手できない理由（意図的）**: `allowed_paths` と `test_cmd` を `未確定` にしてある。
  ループは未確定スコープのジョブを拾わない（`jobloop/tasks.py` 66〜68 行）。
  これは「決まっていないから放置」ではなく、**ここがセキュリティ境界そのもの**だからである。
  このジョブは、敵がコードを自由に選べる状況を前提に境界を叩く仕組みを作る。
  境界の選定と残余リスクの受諾が先に無いまま実装を出すと、受入条件が「動いた」に退化する。

- **先に確定していなければならないこと（これが揃うまで `未確定` を外さない）**:
  1. **どのプロファイルを作るのか**（`T-PH8-304` の `selected` が埋まること）。
     4 候補の証跡は相互に流用できない（`HYBRID_ISOLATION_PROFILES.md` §3 冒頭）。
     対象が決まらないと、テスト 1 本も意味を持たない。
  2. **残余リスクの受諾**（共有カーネル／ハイパーバイザ／ローカル管理者）が記録されること
     （同 §2.1 末尾・§8）。受諾が無い候補は、全テストが通っても活性化できない。
  3. **使い捨ての検証環境の用意と、そこで敵対的テストを走らせる承認**。
     同 §6 冒頭が「隔離された使い捨てラボ・合成データのみ・外部経路なし」を要求している。
     **オーナーの作業機や統合ブランチを動かしている機械で走らせてはならない。**
     どの実機を使うかを `REPORT` 対象として先に決める。
  4. **実行する負のプローブの範囲**。同 §6 末尾が「脱出試験は承認された使い捨て環境に限り、
     比例的であること」を要求している。範囲を書面で確定する。
  5. **独立レビュー担当**（`HYBRID_ISOLATION_PROFILES.md` §7 項目 4。現在未任命）。
     検証者は実装者・構成者と別人でなければならない。
  6. **資源上限の数値**（CPU・メモリ・プロセス数・ディスク・出力バイト・実時間）。
     `HYBRID_ISOLATION_ENGINEERING_DETAIL.md` §2.4 が「数値を一切決めない」としており、
     計測後のオーナー判断である。上限が無いままでは `RES` 族が書けない。

- **確定後に作るもの（受入条件の骨格。いま実装しない）**:
  テスト ID は `HYBRID_ISOLATION_ENGINEERING_DETAIL.md` §3.2 の族名をそのまま使う。
  **各族に正のコントロールを必ず付ける**（同 §3.1 手順 2。正のコントロールが落ちた場合、
  対応する負の結果は無効であって合格ではない）。
  1. `FS` — 合成の悪意あるジョブから、兄弟ワークスペース・利用者プロファイル・OS/サービス状態・
     資格情報の場所・ポリシー/レシートのファイル・ランタイムのソケットへの読み書きを試みる。
     パス走査、シンボリックリンク／再解析ポイント、ハードリンク、大文字小文字と Unicode の別名、
     マウント差し替え、開いたハンドルの競合を含める。**どれか 1 つでも通ったら失敗**。
  2. `PROC` — 無関係なプロセスの列挙・デバッグ・シグナル、特権トークンの取得、
     プロセスグループ／ジョブ／名前空間からの脱出、子孫のデタッチを試みる。
     停止後に子孫が 1 つでも生き残っていたら失敗。
  3. `NET` — 境界の中から TCP/UDP/QUIC・DNS・IPv4/IPv6・ループバック経由のホスト・
     リンクローカル／メタデータ・社内レンジ・プロキシ環境変数・継承経路・生ソケット・
     名前付きパイプを試みる。**ホスト側の捕捉と突き合わせる**。クライアント側のエラーだけでは
     遮断の証明にならない（同 §3.2 `NET` 行、`HYBRID_RUNNER_COMMUNICATION_DESIGN.md` §5.1 項目 7）。
     観測できなかったプローブは合格ではなく失敗として扱う。
  4. `RES` — CPU・メモリ・プロセス数・ディスク・出力・実時間の圧迫（子プロセスの増殖と
     疎で巨大なファイルを含む）。上限到達後にプロセスが継続していたら失敗。
  5. `XFER` — 入力バンドルの改変・重複・欠落・部分staging、コピー中のクラッシュ、
     終了確認前のキャンセル、古いワークスペースの再利用。
     マニフェスト不一致で成果物が解放されたら失敗。
  6. `CLEAN` — タイムアウト・強制停止・部分的な後片付け・ホスト再起動・監視喪失。
     残骸が不明なまま次のジョブが受け付けられたら失敗。
  7. `B6` — 合成のレシートらしきものと**テスト用 Runner を存在させた状態**で、
     dispatch が明示的に拒否されることを確認する。
     「Runner が無いから拒否された」は合格の証明にならない（同 §3.2 `B6` 行）。
  8. 失敗・ブロック・スキップは合格に丸めない（同 §3.3）。スキップは台帳に残す。

- **この設計が通ったら**: 本ファイルの `allowed_paths`（`runner/` 配下と `tests/` 配下の
  正確な範囲）と `test_cmd` を確定し、同時に `T-PH8-309`（Runner 登録）と
  `T-PH8-310`（OS 資格情報ストアの保護実証）のスコープも確定する。

- **やってはならないこと（確定後も変わらない）**:
  - 実データ・実資格情報・実プロバイダ・実エンドポイントを使う。
  - 検証環境の外、または使い捨てでない機械でプローブを走らせる。
  - 境界の一部が実証できない場合に、ホスト直接実行へ退避する経路を作る
    （`HYBRID_ISOLATION_PROFILES.md` §9「no-VM downgrade path」）。
  - 既存の Docker QA（`loop_engine/docker_boundary.py`、`tests/integration/test_live_docker_boundary.py`）
    の結果を製品 Runner の隔離証拠として引く。後者は `LOCUS_LIVE_DOCKER=1` が無ければスキップされ、
    スキップは合格ではない。
