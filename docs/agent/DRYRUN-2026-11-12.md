## ドライラン中に直したもの（ハーネス心臓部）

- `codex exec` に `--full-auto` は無い（対話モード側のフラグ）→ runner から除去
- 長いプロンプトを引数で渡すと Windows の npm シム経由で空白で割れて化ける → `codex exec -` で stdin 渡しに変更。あわせて子プロセスの stdin は必ず閉じる（codex は引数プロンプト時でも stdin を読むため）
- quota 判定の誤検出: 正常終了した実行の要約文に "usage limit" 等が混ざると誤判定した → 異常終了のときだけ quota と判定し、判定時は出力末尾を証跡として note に残す
- 差分検出: 内容ハッシュ併用、BOM 耐性、読めなくなったファイルの可視化（上記 #1）
- 手動 `/harness-poll` は結果を必ず表示する（当初は差分ゼロ時に無表示だった）

## 実機で判明した仕様

- agy の `--model` は effort 込みの正式名が必須（例: `Claude Sonnet 5.5 (Medium)`）。TODO-05 はこれで解消し、runners/agy.ts はサフィックス合成済み（未指定時は Medium）
- agy headless の Available models に **Gemini 4 Carbon が無い**（対話画面には出る）。MODEL_ROTATION の light 候補の見直しが必要
- agy の対話画面にプロンプトを貼ると、そのセッションのモデルで動く（`--model` は効かない）。今回はそれで実装モデルが割当（Flash）とずれたが、ワーカーが REPORT に実績を正直に記録し、Luna がそれを読んでレビュアーを選んだため、サイクルとしては正しく回った
- QA 統計は「割当モデル基準」で計上された（Luna の判断、PROGRESS.md §4 に明記）。この方針を正式採用するかは人間の確認待ち
- `.pi/extensions/harness/tsconfig.json` は型検証用のため repo では削除可（VS Code の `'node' の型定義が見つかりません` はこれが原因で、実行には無関係）
