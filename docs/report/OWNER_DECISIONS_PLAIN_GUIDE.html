同時実行枠（スロット）を増やすときの機材負荷

残る弱点・注意点

同時に動かせる枠（スロット）の数 N を増やすと、それに比例してメモリやGPU（画像や計算を処理する部品）の消費量が増えます。実際に動かせる N の上限は、導入するパソコンやサーバーの実機の性能によって決まります。

開発側が代わりにやること

N は設定で変えられる値のままとし、起動するときに実際の機材性能を測って、設定値 N が限界を超えている場合は警告を出すようにします。

二段階認証（MFA）を省く代わりに取る安全策

残る弱点・注意点

二段階認証（MFA）は 2026-11-09 の記録では「本番で必須」とされていましたが、2026-11-16 のオーナー判断で「不要」に変わったため、要件（IAM-005）は「実装しない」扱いに改めます。ただし、IDとパスワードだけの仕組みでは、パスワードが漏れた瞬間にすべての資料を見られてしまう弱点が残ります。

開発側が代わりにやること

パスワードだけでも最低限の安全を保つため、次の4つを標準の設定（既定）にします。

  • パスワードの最低限の強さ（短すぎたり簡単すぎたりするものを防ぐ）
  • ログインに何度も失敗したときの一時ロック
  • 既存の must_rotate（アカウント発行時や管理者によるリセット後の初回ログイン時に、必ずパスワードを変えさせる仕組み。定期的な変更を強制するものではありません）
  • 誰がいつログインしたかの履歴を管理者が見られる機能
申し送り 6 phase-6-extensions

作図機能（B: コード実行）で「AIが書いた命令」を実行するときの追加制限

残る弱点・注意点

作図のためにプログラムの命令を動かす処理（コード実行）は、ファイルの解析よりもさらに危険に踏み込んだ境界になります。ファイル解析が「攻撃者が選んだデータを読む」だけなのに対し、作図は「モデル（AI）が書いた命令そのものを実行する」ためです。

開発側が代わりにやること

T-PH6-104 で作ったファイル解析用の隔離境界をそのまま使い回すのではなく、作図用（T-PH6-114 の合格条件）として次の制限を追加する前提で進めます。

  • 実行するのは生成されたコードだけにし、利用者の元の資料は「読み取り専用（書き換え禁止）」で渡す
  • 外に出せる結果は「画像1枚」と「文字の出力（標準出力）」だけに限定する
  • ネットワーク（外部との通信）は遮断する
  • 実行できる時間とメモリの量は、作図用に別の枠を設ける
