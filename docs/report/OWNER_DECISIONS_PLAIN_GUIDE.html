申し送り（報告）

この資料で使われている言葉の意味と、今後の進め方

以下の「申し送り」は、オーナーに新しく何かを決めてもらうものではありません。オーナーの決定どおりに開発を進めるものの、その代わりこういう弱点が残るため、こういう工夫で補うという開発チームからの報告です。

  • 【回答】：オーナーが答えたそのままの言葉。
  • 【解釈】：プログラムを作るときに従うルール。
  • 【解禁】：決まったことで進められるようになる作業の番号（要件 ID）。
  • 【申し送り】：開発側がそのままでは不安だと感じている点や、確認しておいてほしい点。

進め方の約束：

  • 今回決まった項目だけを PROGRESS.md（進捗を記録するファイル）の作業（ジョブ）として登録します。まだ決まっていない項目は作業にしません。
  • 【申し送り】はオーナーの決定をひっくり返すものではありません。決定どおりに作ったときに残る弱点を補うための工夫を書いているだけなので、もしオーナーから「その工夫は不要」と言われれば外します。

通行証の有効期限（TTL）を長くすることについて

残る弱点

TTL（通行証が使える有効期限）を長く設定するほど、もしその通行証が外に漏れてしまったときに、悪い人に使われ続けてしまう時間も長くなります。

  • いつでも通行証を無効にできる仕組み（取消 / revoke）。
  • いつ誰がその通行証を使ったかの記録（利用履歴）。

なお、あとから「有効期限をもっと短くしてほしい」と指示があれば、設定ですぐに変えられます。

申し送り（報告）

研究室内のネットワーク（LAN）だから安全という前提について

開発側の見解と残る弱点

「同じ建物や研究室のネットワーク（LAN）の中だから攻撃は起きない」という考え方について、開発側は安全とは言い切れないと考えています。同じネットワークの中であっても、ウイルスなどに感染して乗っ取られたパソコン（踏み台になった端末）、外から持ち込まれたパソコン、同じネットワークにつながっている別の部署などから攻撃が届く可能性があるためです。

開発側が取る補いの工夫

対策にどれだけお金や手間（コスト）をかけるかはオーナーが決めることなので、大がかりでお互いを厳しく確認し合う仕組み（重い相互認証）は入れずに進めます。その代わり、費用がほとんどかからず効果がある次の2つだけを入れて弱点を補います。

  1. Runner（実際の作業を動かすコンピュータやプログラム）を登録するときに使う、1回限りの合言葉。
  2. リース（一時的な利用許可や割り当て）の利用記録（誰のどの利用許可が、いつ、どの Runner で使われたかの記録）。

この2つは、あとから本人確認をもっと厳しくしたくなったときの土台にもなります。

申し送り（報告）

危険なデータを入れたときの被害の範囲について

残る弱点

「危ないデータを入れるのは本人の責任」という考え方は、被害がその人だけに収まる場合にしか成り立ちません。Locus はみんなで一緒に使う道具（共有ツール）なので、悪い仕掛けのあるファイルが開かれた瞬間に、データを保存している中心のコンピュータ（サーバ側）、つまり全員の資料にまで被害が広がるおそれがあります。

開発側が取る補いの工夫

ファイルを隔離された安全な箱（サンドボックス）の中で開く仕組みを取り入れることで、この弱点を補います。その安全な仕組みがあることを前提として、多くの種類のファイルを「広く許容」する形で開発を進めます。

申し送り（報告）

同時に動かせる枠（スロット）の数と機械の性能について

残る弱点

同時に動かせる作業の枠（スロット）の数（N）を増やすと、それに比例してメモリや画像・計算用の部品（GPU）の消費量も増えます。実際に動かせる上限は、このシステムを置くコンピュータの性能によって決まります。

開発側が取る補いの工夫

N は固定にせず設定で変えられる値のままにしておきます。そして、システムを起動するときに実際の機械の性能を測り、設定された N が性能を超えている場合は警告を出すようにします。

申し送り（報告）

ログイン時の二段階確認（MFA）をなくすことについて

これまでの経緯と今回の変更

ログイン時の追加の本人確認（MFA：パスワードだけでなく別の確認も行う仕組み）は、2026年11月9日の記録では「本番運用で必須」と整理されていました。今回の回答で「不要」に変わったため、IAM-005（該当する機能の番号）の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

残る弱点

ID とパスワードだけでログインする形にすると、パスワードが外に漏れただけで、すべての資料を見られてしまうという弱点が残ります。

開発側が取る補いの工夫

弱点を補うため、次の4つを初期設定（既定）として入れます。

  • 推測されにくいパスワードを必須にすること（パスワードの最低強度）。
  • 何度もログインに失敗したら、一時的にログインできなくすること（失敗回数による一時ロック）。
  • 最初からある must_rotate という仕組み（新しく発行したときと、管理者がリセットしたあとの最初のログイン時に、必ずパスワードを変更させる仕組み。定期的に何度も変更を強制するものではありません）。
  • いつ誰がログインしたかの履歴を、管理者が確認できるようにすること（ログイン履歴の管理者可視化）。
