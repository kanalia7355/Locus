2-1. 通行証の有効時間（TTL）が長いときの弱点と対策

段階：phase-6-extensions

残る弱点

TTL（通行証が有効な時間）が長いほど、もし通行証が外に漏れてしまったときに「漏れた通行証が不正に使われうる時間」も長くなります。

開発側が入れる対策

通行証を途中で無効にする仕組み（取消 / revoke）と、いつ誰が使ったかの記録（利用履歴）を残すことを必須にして弱点を補います。なお、オーナーから「有効時間を短くしてほしい」と指示があれば、設定でいつでも変えられます。

目次に戻る
申し送り

2-2. 研究室内のネットワーク（LAN 内）の安全性と対策

段階：phase-6-extensions

残る弱点

「LAN 内（研究室など同じ建物や組織内のネットワークの中）だから攻撃は起きない」という前提には、開発側としては同意していません。LAN 内であっても、乗っ取られた端末（踏み台になった端末）、外から持ち込まれた端末、同じ LAN につながっている別の部署からアクセスされる可能性はあります。

開発側が入れる対策

ただし、費用（コスト）をどこまでかけるかの判断はオーナーの役割なので、手間やコストが重い「本格的な相互認証（お互いを厳しく確認し合う仕組み）」は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の 2 つだけを入れます。

  • Runner（作業を実際に動かすプログラムや機械）を登録するときに使う、1回限りの合言葉
  • リース（一時的な利用許可）の利用記録（誰のどの利用許可が、いつ、どの Runner で使われたか）

この 2 つは、後から本人確認を強めたくなったときの土台にもなります。

2-3. 危険なファイルを開いたときの被害範囲と隔離部屋（サンドボックス）

段階：phase-6-extensions

残る弱点（考え方の注意点）

「危ないデータを入れるのは入れた本人のせい」という考え方は、被害がその本人だけに閉じる場合にしか成り立ちません。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、サーバ側（つまり全員の資料）へ被害が広がるおそれがあります。

開発側が入れる対策

その危険を埋めるために、被害が外へ漏れない隔離部屋（サンドボックス）を採用します。この隔離部屋があることを前提として、「いろいろなファイルを広く受け入れる（広く許容）」という仕組みを作ります。

2-4. 同時に動かせる枠（スロット）の数と機械の性能

段階：phase-6-extensions

残る弱点

同時に作業できる枠（スロット）を増やすと、パソコンの作業机の広さにあたる記憶装置（メモリ）や、計算や画像を高速に処理する装置（GPU）の消費量も、数に比例して増えます。実際に動かせる上限の数 N は、ソフトを置く実機（実際のパソコンやサーバ）の性能によって決まります。

開発側が入れる対策

N は設定された値のままにしておき、ソフトを立ち上げるとき（起動時）に実機の余裕を測って、上限を超えている場合は警告を出すようにします。

2-5. 二段階認証（MFA）をやめて ID とパスワードだけにする場合の対策

段階：phase-6-extensions

経緯と残る弱点

MFA（パスワード以外の確認も組み合わせる二段階認証など）は、2026-11-09 の記録では「本番では必須」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、要件 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

ID とパスワードだけにする場合、パスワードが外に漏れると、そのまま全員の資料が見られてしまうという弱点が残ります。

開発側が入れる対策

代わりに、次の 4 つを標準（既定）の仕組みとして入れます。

  • パスワードの最低限の強さ（決められた強さを満たすこと）
  • ログインに一定回数失敗したときに一時的に使えなくする仕組み（一時ロック）
  • 既存の must_rotate（新しく発行したときと、管理者がリセットした後の最初のログイン時に、必ずパスワードを変えさせる仕組み。定期的に何度も変えさせるものではありません）
  • ログイン履歴を管理者が確認できるようにすること（可視化）

2-7. 作図のために AI が書いたプログラムを動かすときの安全対策

段階：phase-6-extensions

残る弱点（安全面の違い）

B（プログラムを動かして図を作ること / コード実行）は、ファイルを読み取って調べるだけ（ファイル解析）よりも、安全面の境目（境界）がさらに踏み込んだものになります。ファイル解析は「攻撃者が選んだデータを読む」だけなのに対し、作図は「AI モデルが書いた命令を実際に動かす」ことになるためです。

開発側が入れる対策

T-PH6-104 で決めた安全の境目をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進め、これらを T-PH6-114 の合格条件（受入条件）に落とし込みます。

  • 動かすのは AI が作ったプログラム（生成されたコード）だけにし、利用者の元の資料は「見るだけ（読み取り専用）」で渡す
  • 外に出せる結果は「画像 1 枚」と「画面への文字出力（標準出力）」だけに限る
  • 外部との通信（ネットワーク）は遮断する
  • 動かせる時間と使えるメモリ（記憶装置）の上限は、作図用として別枠で決める
