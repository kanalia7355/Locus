3. 研究室などの同じネットワーク内（LAN内）の安全性

申し送り

段階：phase-6-extensions

「同じネットワーク内（LAN内）だから攻撃は起きない」という前提には、プログラムを作る側としては同意していません。同じネットワーク内であっても、乗っ取られたパソコン（踏み台になった端末）や外部から持ち込まれた端末、同じネットワーク内の別部署からのアクセスによって攻撃が届く可能性はあります。

ただし、どこまで費用や手間をかけるかはオーナーの判断であるため、手間のかかる重い確認の仕組み（相互認証）は入れずに決定どおり進めます。その代わり、費用がほぼゼロで効果がある次の2つだけを入れます。

  • 貸し出し権限（リース）の利用記録（誰のどの権限が、いつ、どの機械で使われたか）

これらを入れておくことで、後から本人確認を強めたくなったときの土台にもなります。

4. 危ないファイルを受け入れる前提と、被害を閉じ込める工夫

申し送り

「危ないデータを入れるのは本人の責任」という考え方は、被害が本人だけにとどまる場合にしか成り立ちません。Locusはみんなで共有する道具であるため、悪意のあるファイルが開かれた瞬間に、被害が本体側（サーバ＝全員の資料）にまで広がるおそれがあります。

そのため、隔離された安全な箱（サンドボックス）を使って被害を閉じ込めることでその差を埋め、その前提の上で「いろいろなファイルを広く受け入れる」方針を実装します。

6. 二段階の確認（MFA）を不要にした場合の弱点と代わりの対策

申し送り

段階：phase-6-extensions

二段階の確認（MFA：多要素認証）は、2026年11月9日の記録では「本番では必須」と整理されていましたが、今回のオーナーの判断（2026年11月16日）で「不要」に変わったため、要件（IAM-005）の扱いを「実装しない」に改めます。

  • 何度もログインに失敗したときの一時的なロック

8. AIが作ったプログラムを動かして図を作る機能（B：コード実行）の安全対策

申し送り

段階：phase-6-extensions

プログラムを動かして図を作る機能（B：コード実行）は、これまでのファイル解析よりも危険に踏み込んだ境界になります。ファイル解析は「攻撃者が選んだデータを読むだけ」ですが、作図は「AI（モデル）が書いた命令そのものを実際に動かす」ためです。

そこで、T-PH6-104 の安全ルールをそのまま使い回すのではなく、作図用（T-PH6-114 の合格条件）として次の4つの対策を追加する前提で進めます。

  • 動かすのはAIが作ったプログラムだけにして、利用者の元の資料は書き換えられない読み取り専用で渡す。
  • 出力してよいものは、画像1枚と文字の結果（標準出力）だけに限る。
  • 外部との通信（ネットワーク）は遮断する。
  • 動かせる時間とメモリの上限は、作図専用の別枠として決める。
