申し送り 1：通行証の有効期限（TTL）が長いことへの対策

1. ひとことで言うと

通行証の有効期限（TTL）を長くすると漏れたときの危険も長くなるため、あとから無効にする仕組みと利用記録を必ず入れて補う、という報告です。

2. いまどうなっているの

オーナーの決定に沿って進める状態ですが、有効期限の長さについて開発側から弱点と対策を申し送りしています。

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません。

4. 選べるやり方

選択肢は示されていません。ただし、有効期限を短くしたいという指示がオーナーからあれば、いつでも設定で変えられるようになっています。

5. 開発側の意見

通行証をあとから無効にできる仕組み（取消 / revoke）と、利用履歴の記録を必須にして補う方針で進めます。理由は、有効期限（TTL）が長いほど、万が一通行証が外に漏れたときに悪用されてしまう時間も長くなるためです。

6. 決める前に知っておくこと

  • 有効期限（TTL）が長いほど、漏れた通行証が使えてしまう時間も長くなるという弱点が残ります。
  • 対策として「あとから無効にする仕組み（取消 / revoke）」と「使った記録の保存（利用履歴の記録）」を入れますが、短縮したい場合はいつでも設定で変更できます。

1. ひとことで言うと

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません。

4. 選べるやり方

選択肢は示されていません。

5. 開発側の意見

費用がほぼゼロで効果がある次の 2 つだけを入れて進めます。理由は、同じネットワーク（LAN）内であっても攻撃は起こりうるため、最低限の備えをしておき、後から本人確認を強くしたくなったときの土台にするためです。

入れる対策 内容（やさしい説明）
1. Runner 登録時の一回限り合言葉 作業を実行するパソコン（Runner）を登録するときに、1回だけ使える合言葉で確認します。
2. リースの利用記録 一時的な利用権（リース / lease）について、「誰の、どの利用権が、いつ、どの実行パソコン（Runner）で使われたか」を記録します。

6. 決める前に知っておくこと

  • 開発側は「同じネットワーク（LAN）内だから攻撃は起きない」という前提には同意していません。
  • ネットワーク内であっても、乗っ取られた端末（踏み台になった端末）、外から持ち込まれた端末、同じネットワーク内の別部署からのアクセスは起こりえます。
  • 重い相互認証（お互いに相手が本物か厳しく確かめ合う仕組み）を入れないため、その分の弱点は残ります。

申し送り 3：共有ツールで危険なファイルを受け入れるときの対策

1. ひとことで言うと

このシステムはみんなで使う共有ツールなので、安全な隔離場所（サンドボックス）を使うことを前提に「いろいろなファイルを広く受け入れる」仕組みを作る、という報告です。

2. いまどうなっているの

危険なデータを外に漏らさないための隔離場所（サンドボックス）を使う前提で、「広く許容（いろいろなデータを受け入れること）」の仕組みを作っています。

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません。

4. 選べるやり方

選択肢は示されていません。

5. 開発側の意見

隔離された安全な実行場所（サンドボックス）を採用し、その前提で「広く許容」を実装します。理由は、共有ツールでは 1 人が危険なファイルを開くだけで、全員の資料がある場所（サーバ側）まで被害が及ぶ危険を埋めるためです。

6. 決める前に知っておくこと

  • 「危ないデータを入れるのは本人の責任」という考え方は、被害が本人だけに収まるときにしか成り立ちません。
  • Locus（このシステム）は共有ツールであるため、悪意のあるファイルが開かれた瞬間に、全員の資料が入っている中心のコンピュータ（サーバ側）へ被害が広がるおそれがあります。

申し送り 4：同時に動かせる枠（スロット）の数と機械の性能

1. ひとことで言うと

同時に動かせる枠の数（N）を増やすとコンピュータの負担も増えるため、数は設定で変えられるようにし、動かすときに性能を測って超えていたら警告する、という報告です。

2. いまどうなっているの

同時に動かせる枠の数（N）を固定せず、設定値のままにして動かす方針で進めています。

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません。

4. 選べるやり方

選択肢は示されていません。

5. 開発側の意見

枠の数（N）は設定で変えられるようにしたまま、起動するときに実際の機械の性能を測り、上限を超えていたら警告を出すようにします。理由は、実際に設置するコンピュータ（配備先の実機）の性能によって N の上限が決まるためです。

6. 決める前に知っておくこと

  • 同時に動かせる枠（スロット）を増やすと、それに比例してメモリ（作業用の記憶容量）や GPU（計算を行う部品）の消費量が増えます。
  • 実際に使うコンピュータの性能を超える設定にすると、警告が出ることになります。

申し送り 5：追加の本人確認（MFA）を使わない場合のパスワード対策

1. ひとことで言うと

追加の本人確認（MFA）を使わない代わりに、パスワードの最低限の強さや一時ロックなど 4 つの安全対策を標準にする、という報告です。

2. いまどうなっているの

2026年11月9日の記録では追加の本人確認（MFA）を「本番で必須」と整理していましたが、2026年11月16日のオーナー判断で「不要」に変わったため、機能番号 `IAM-005` は「実装しない」扱いに改めました。

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません。

4. 選べるやり方

選択肢は示されていません。

5. 開発側の意見

ID とパスワードだけのログインにする代わりに、次の 4 つを標準の決まり（既定）として入れます。理由は、パスワードが漏れたときにすべての資料を見られてしまう弱点を少しでも補うためです。

  1. パスワードの最低限の複雑さ（最低強度）を決めること。
  2. ログインに決まった回数失敗したら、一時的に入れなくすること（一時ロック）。
  3. 既存の `must_rotate`（新しく発行したときと、管理者がリセットした後の最初のログインで必ずパスワードを変えさせる仕組み。定期的な変更を強制するものではない）を使うこと。
  4. いつ誰がログインしたかの履歴を、管理者が確認できるようにすること。

6. 決める前に知っておくこと

  • ID とパスワードだけの場合、もしパスワードが外に漏れると、それだけで全ての資料を見られてしまうという大きな弱点が残ります。

申し送り 7：プログラムを動かして図を作る機能（B）の安全対策

1. ひとことで言うと

プログラムを動かして図を作る機能（B）はファイルを読み取るより危険が大きいため、作図専用の厳しい安全ルールを追加して進める、という報告です。

2. いまどうなっているの

作図用の安全ルールを、作業番号 `T-PH6-114` の完了基準（受入条件）に落とし込んで進める前提になっています。

3. 決めないとどうなるの

この項目は決めてもらうものではなく報告です。どの作業が待っているかについては、元の文に書かれていないため、ここは分かりません（ただし追加条件は `T-PH6-114` の完了基準に使われます）。

4. 選べるやり方

選択肢は示されていません。

5. 開発側の意見

作業番号 `T-PH6-104` の安全の境界をそのまま使い回すのではなく、作図用として次の 4 つを追加する前提で進めます。理由は、ファイル解析が「攻撃者が選んだデータを読む」だけなのに対し、作図は「AI（モデル）が書いた命令を実行する」ため、より踏み込んだ安全の境界が必要になるからです。

追加する安全ルール 内容（やさしい説明）
実行対象と原本の保護 動かすのは作られたプログラム（生成されたコード）だけにし、利用者の元の資料は見るだけで書き換えられない状態（読み取り専用）で渡します。
出力の制限 外に出せる結果は「画像 1 枚」と「文字の結果（標準出力）」だけに限ります。
通信の遮断 外部との通信（ネットワーク）はすべて遮断します。
時間とメモリの別枠管理 動かしてよい時間とメモリの量は、作図専用の別枠で制限します。

6. 決める前に知っておくこと

  • プログラムを動かすやり方（コード実行）は、ただファイルを読み取る場合よりも危険度が高くなります。
  • 上記の 4 つの条件は、`T-PH6-114` の完了基準（受入条件）に組み込まれます。
