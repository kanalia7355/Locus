2. 通行証の有効期限（TTL）が長いことへの対策

オーナーの決定どおりに作りますが、有効期限（TTL：通行証が使える時間）を長くするほど、「万が一その通行証が外に漏れたときに、悪い人に使われてしまう時間」も長くなるという弱点が残ります。

そのため開発側では、この弱点を補うために次の2つを必ず入れる方針で進めます。

  • 取消（revoke）：危ないときに、その通行証を途中で使えなくする仕組み。
  • 利用履歴の記録：いつ誰がその通行証を使ったかを記録する仕組み。

なお、有効期限を短くしたいという指示があれば、いつでも設定で変えられるようにしておきます。

3. 研究室内のネットワーク（LAN）の安全性と、最低限入れる2つの対策

「研究室内のネットワーク（LAN）だから攻撃は起きない」という前提について、開発側（実装側）としては安全だとは考えていません。同じネットワーク内であっても、次のような経路で侵入や攻撃が起きる可能性があるためです。

  • ウイルスなどに感染して乗っ取られた（踏み台になった）端末からのアクセス
  • 外から持ち込まれた端末からのアクセス
  • 同じネットワークにつながっている別の部署からのアクセス

ただし、安全対策にどれだけ費用や手間をかけるかの判断はオーナーの役割ですので、決定どおり重たい相互認証（お互いに証明書などを出し合って厳重に本人確認する仕組み）は入れずに進めます。

4. 共有ツールとしての安全対策（サンドボックス）

「危ないデータを入れるのは入れた本人の責任」という考え方は、被害がその本人の中だけで収まる場合にしか成り立ちません。

Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、その被害がサーバ側（＝全員の資料が入っている場所）にまで広がるおそれがあります。

その危険をなくすために「サンドボックス（他の場所へ悪影響が出ないように隔離された箱）」を使います。この隔離があることを前提として、オーナーの決定どおり「いろいろなファイルを広く受け入れる」仕組みを作ります。

5. 同時に動かせる数（スロット数 N）とパソコンの性能

同時に作業できる枠（スロット）の数 N を増やすと、それに比例してメモリ（作業用の記憶容量）や GPU（画像処理や計算用の部品）の消費量が増えます。

実際に動かせる上限は、このシステムを置く実機の性能によって決まります。そのため、N は設定で変えられるままにしておき、システムを起動するときに実際の空き容量などを測って、性能を超えそうな場合は警告を出すようにします。

8. グラフなどを作る機能（コード実行）に対する特別な安全枠

「B（コード実行＝作図など）」は、単なるファイル解析よりもさらに踏み込んだ危険があります。

  • ファイル解析：攻撃者が選んだ「データ」を読むだけ。
  • 作図（コード実行）：AIモデルが書いた「命令（プログラム）」を実際に動かす。

そのため、T-PH6-104 で作る安全な仕組みをそのまま使い回すのではなく、作図用には次の条件を追加する前提で進めます。これらは T-PH6-114 の合格条件（受入条件）に組み込みます。

  • 実行するのは生成されたコードだけにし、利用者の資料原本は「読み取り専用（書き換え禁止）」で渡す。
  • 出力してよいものは「画像 1 枚」と「文字の画面出力（標準出力）」だけに限定する。
  • ネットワーク（外部への通信）は遮断する。
  • 実行できる時間の上限とメモリの量は、作図専用の別枠で制限する。
