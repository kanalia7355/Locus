1. 通行証の有効期限（TTL）が長い場合の弱点と補い方

オーナーの決定どおりに作るとどうなるか

通行証の有効期限（TTL：使える時間の上限）を長くしたまま作ると、もし通行証が外に漏れたときに「他人に使われてしまう時間」も長くなるという弱点が残ります。

開発側が取る補いの対策

その弱点を補うため、「後から無効にできる仕組み（取消：revoke）」と「使った履歴の記録」を必ず入れる方針で進めます。なお、有効期限を短くしたいという指示があれば、いつでも設定で変更できます。

申し送り 段階: phase-6-extensions

2. 研究室などの LAN 内でも油断できない点と、費用をかけない対策

オーナーの決定どおりに作るとどうなるか

「LAN 内（建物や組織の内側のネットワーク）だから攻撃は起きない」という前提には、作る側としては同意していません。LAN の中でも、乗っ取られて踏み台になった端末、外から持ち込まれた端末、同じ LAN につながっている別部署からのアクセスは起こり得ます。

ただし、費用や手間をどこまでかけるかはオーナーの判断であるため、重い相互認証（お互いを厳しく確認し合う仕組み）は入れずに進めます。

開発側が取る補いの対策

費用がほぼかからず効果のある次の 2 つだけを入れます。これらは後から本人確認を強めたいときの土台にもなります。

  1. Runner（実際の作業を動かす側の機械やプログラム）を登録するときの、1 回限りの合言葉
  2. リース（一時的な利用許可：lease）の利用記録（誰のどのリースが、いつ、どの Runner で使われたか）
申し送り 段階: phase-6-extensions

3. 危ないデータを受け入れる理由と、隔離箱（サンドボックス）の前提

オーナーの決定どおりに作るとどうなるか

「危ないデータを入れるのは本人のせい（自己責任）」という考え方は、被害が本人の手元だけで終わる場合にしか成り立ちません。Locus はみんなで共有して使うツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（つまり全員の資料）へ広がるおそれがあります。

開発側が取る補いの対策

サンドボックス（プログラムを隔離された安全な箱の中で動かして外へ影響を出さない仕組み）を採用したのは、その危険の差を埋めるためです。この隔離の仕組みがあることを前提として、「広く受け入れる」方針で作ります。

申し送り 段階: phase-6-extensions

4. 同時に動かす数（スロット）と、機械の性能による限界

オーナーの決定どおりに作るとどうなるか

スロット（同時に動かせる作業の枠）の数 N を増やすと、メモリ（作業用の記憶領域）や GPU（画像や計算を高速に処理する部品）の消費量もそれに比例して増えます。実際に動かす先の機械の性能によって、動かせる上限の N が決まります。

開発側が取る補いの対策

N は設定値のままにしておき、プログラムを起動するときに実際の機械の性能を測って、上限を超えている場合は警告を出すようにします。

申し送り 段階: phase-6-extensions

5. 二段階認証（MFA）をなくす代わりに、パスワードを守る仕組み

オーナーの決定どおりに作るとどうなるか

二段階認証（MFA：パスワードに加えて別の確認手段を使う仕組み）は、2026-11-09 の記録では「本番では必須」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」へ改めます。

ID とパスワードだけの仕組みにすると、パスワードが外に漏れたときに、そのまま全員の資料が見られてしまうという弱点が残ります。

開発側が取る補いの対策

二段階認証を入れない代わりに、次の 4 つを標準のルール（既定）にします。

  • パスワードの最低限の強さ（短すぎたり単純すぎたりするものを防ぐ決まり）
  • 連続で失敗したときの一時ロック
  • 既存の must_rotate（新しく発行したときと、管理者がリセットした後の初回ログインで必ず変更させる仕組み。定期的な変更を強制するものではありません）
  • ログイン履歴を管理者が見られるようにすること
申し送り 段階: phase-6-extensions

7. 作図のためにプログラムを実行するときの安全対策

オーナーの決定どおりに作るとどうなるか

選択肢 B（プログラムのコードを実行すること）は、ファイルを読み取って解析するよりも踏み込んだ危険の境界になります。解析は「攻撃者が選んだ『データ』を読む」だけですが、作図は「AI モデルが書いた『命令』を実行する」ためです。

開発側が取る補いの対策

T-PH6-104 の安全の境界をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進め、これらを T-PH6-114 の合格条件（受入条件）に落とし込みます。

  • 実行するのは生成されたコードだけにし、利用者の資料の原本は「読み取り専用（書き換えできない状態）」で渡す
  • 出力は画像 1 枚と画面への文字出力（標準出力）だけに限る
  • ネットワーク（外部との通信）は遮断する
  • 実行できる時間と使えるメモリの量は、作図用に別枠で決める
申し送り 段階: phase-6-extensions
