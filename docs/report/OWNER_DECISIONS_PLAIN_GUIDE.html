通行証が使える期間（TTL）を長くすると、もし通行証が外に漏れたときに「不正に使われてしまう時間」もそのぶん長くなる弱点が残ります。

そのため開発側では、後から通行証を無効にできる仕組み（取消 / revoke）と、いつ使われたかの利用履歴を残す仕組みを必ず入れて補う方針で進めます。なお、期間を短くするよう指示をもらえれば、いつでも設定で変えられます。

申し送り phase-6-extensions

3. 研究室内のネットワーク（LAN）での安全対策

「研究室内のネットワーク（LAN）の中だから攻撃は起きない」という考え方に対して、開発側としては同意していません。LAN の中であっても、乗っ取られたパソコン（踏み台）・外から持ち込まれた端末・同じ LAN につながっている別部署の端末からアクセスされる危険は起こりえます。

ただし、費用をかけるかどうかの判断はオーナーの役割なので、手間やコストが大きい厳重な確認（重い相互認証）は入れずに進めます。その代わり、費用がほぼかからずに効果がある次の2つだけを入れます。

  • 作業を実行する機械（Runner）を登録するときに使う、1回限りの合言葉
  • 一時的な利用許可（リース）の履歴記録（誰のどの許可が、いつ、どの機械で使われたか）

これらは、将来さらに本人確認を強めたくなったときの土台にもなります。

4. 危ないデータを受け入れる場合の隔離（サンドボックス）

「危ないデータを入れるのは本人の責任」という考え方が成り立つのは、被害が本人だけに収まる場合だけです。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、サーバ側にある全員の資料へ被害が広がる危険があります。

そのため、外に影響が出ない隔離された安全な箱（サンドボックス）を使うことでその弱点を埋め、それを前提として「いろいろなファイルを広く受け入れる」仕組みを作ります。

5. 同時に動かす数（スロット）と機械の性能の上限

同時に動かせる枠（スロット）を増やすと、それに比例して作業用の記憶場所（メモリ）や計算用の部品（GPU）の消費量が増えます。

上限の数（N）は実際に動かす機械の性能によって決まるため、N は設定値のままで作っておき、ソフトを起動するときに実際の機械の性能を測って、上限を超えていたら警告を出すようにします。

6. 二段階の本人確認（MFA）を使わない場合のパスワード対策

2026-11-09 の記録では二段階の本人確認（MFA）は「本番で必須」とされていましたが、今回の回答で「不要」に変わったため、機能番号 IAM-005 は「実装しない（オーナー判断 2026-11-16）」に改めます。

  • 管理者がログイン履歴を見られる仕組み

8. 作図などのためにプログラムを実行させる場合の安全対策

選択肢 B（プログラムを実行させること）は、単なるファイル読み込み（解析）よりも危険な境界になります。解析は「攻撃者が選んだデータを読む」だけですが、作図は「AIが書いた命令を実際に動かす」ことになるためです。

そのため、T-PH6-104 の安全対策をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進めます（これらは T-PH6-114 の完了条件に入れます）。

  • 動かすのはAIが作ったプログラムだけにし、利用者の資料原本は書き換えできない状態（読み取り専用）で渡す
  • 外に出せる結果は、画像1枚と文字の出力（標準出力）だけに限る
  • 外部との通信（ネットワーク）は遮断する
  • 動かせる時間と記憶場所（メモリ）の上限を作図用に別枠で決める
