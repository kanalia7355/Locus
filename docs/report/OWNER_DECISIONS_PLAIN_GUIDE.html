段階: phase-6-extensions

ひとことで言うと

みんなが使うツールで危険なファイルが開かれると全員の資料に被害が広がるおそれがあるため、外に影響が出ない隔離された箱（サンドボックス）を使う前提で「多くのファイルを受け入れる」方針を作ります。

いまどうなっているの

「危ないデータを入れるのは本人のせい」という考え方は、被害が本人の手元だけに収まる場合にしか成り立ちません。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（つまり全員の資料）へ広がる可能性があります。

決めてもらう項目ではありません。その危険の差を埋めるためにサンドボックス（他の場所から切り離された安全な実行場所）を採用し、それを前提として「広く許容（多くの種類を受け入れる）」を実装します。

選べるやり方

決めてもらう項目ではないため、選択肢は示されていません。

決める前に知っておくこと

「広く許容」は、サンドボックスによってサーバ全体への被害を防げることを前提としています。

いまどうなっているの

決めてもらう項目ではありません。N は設定された値のままにしておき、起動するときに実際の性能を測って、上限を超えていたら警告を出すように作ります。

6. 二段階確認（MFA）を無くしたあとのパスワードの守り方

段階: phase-6-extensions

ひとことで言うと

二段階確認（MFA）を「不要」とする決定に従って実装を取りやめますが、パスワードが漏れると全員の資料が見られてしまうため、4 つの防御策を標準で入れます。

いまどうなっているの

MFA（ID とパスワードに加えて、別の方法でも本人確認をする仕組み）は、2026-11-09 の記録では「本番で必須」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、要件番号 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

決めないとどうなるの

決めてもらう項目ではありません。ID とパスワードだけの場合、パスワードが外に漏れるとそのまま全ての資料が見られてしまうため、代わりに次の 4 つを標準（既定）の仕組みとして入れます。

  1. パスワードの最低限の強さ（最低強度）のルール
  2. ログインに一定回数失敗したときの一時ロック（しばらくログインできなくする仕組み）
  3. すでにある must_rotate（アカウント発行時と、管理者がリセットした後の初回ログインで必ずパスワードを変更させる仕組み。定期的な変更を強制するものではありません）
  4. ログイン履歴を管理者が見られるようにすること
選べるやり方

決めてもらう項目ではないため、選択肢は示されていません。

決める前に知っておくこと

ID とパスワードのみの運用では、パスワードの流出がそのまま全資料の閲覧につながるリスクが残ります。

7. AI が作ったプログラムを実行して図を描く機能（B）の安全ルール

段階: phase-6-extensions

ひとことで言うと

図を描くためにプログラムを実行する機能（B）は、ファイルの中身を読むだけの機能より危険が大きいため、作図専用の 4 つの制限を追加して作ります。

いまどうなっているの

B（コード実行による作図）は、ファイル解析よりも踏み込んだ危険な境界になります。ファイル解析は「攻撃者が選んだデータを読む」だけなのに対し、作図は「AI モデルが書いた命令をそのまま実行する」ためです。

決めないとどうなるの

決めてもらう項目ではありません。ファイル解析用の安全境界（T-PH6-104）をそのまま使い回すのではなく、作図用に次の 4 つを追加する前提で進めます。これらは T-PH6-114 の合格条件（受入条件）に入れます。

  1. 実行するのは生成されたプログラムだけにし、利用者の元の資料は「読み取り専用（書き換え不可）」で渡す
  2. 出力は画像 1 枚と文字の出力（標準出力）だけに限る
  3. 外部などへの通信（ネットワーク）は遮断する
  4. 動かせる時間と使えるメモリの上限は、作図用に別の枠を設ける
選べるやり方

決めてもらう項目ではないため、選択肢は示されていません。

決める前に知っておくこと

命令を実行する仕組みは、データを読み取るだけの仕組みよりも安全面の対策を強くする必要があります。
