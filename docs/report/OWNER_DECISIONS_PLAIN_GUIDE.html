申し送り 1 / phase-6-extensions

通行証の使える期限（TTL）が長いことへの対策

報告の要点： 通行証が使える期限（TTL）を長くすると、もしその通行証が外に漏れたときに悪用されうる時間も長くなるという弱点が残ります。

開発側が取る対策： 途中での取り消し（revoke：通行証を無効にすること）と、いつ使われたかの利用履歴の記録を必ず残す形で補って進めます。

変えたいとき： 期限を短くしたいという指示があれば、いつでも設定で変えられるようにします。

申し送り 2 / phase-6-extensions

職場などのネットワーク内（LAN 内）の安全性と本人確認の工夫

報告の要点： 開発側としては「職場や研究室のネットワーク（LAN）の中だから攻撃は起きない」という前提には賛成していません。内部のネットワークであっても、乗っ取られて踏み台になったパソコンや、外から持ち込まれた端末、同じネットワーク内の別部署からのアクセスは起こりえます。

オーナー判断の尊重と対策： ただし、どれくらい費用や手間をかけるかはオーナーが決めることなので、負担の重い「お互いに確認し合う仕組み（相互認証）」は入れずに進めます。その代わり、費用がほとんどゼロで効果のある次の 2 つだけを入れます。

  1. Runner（作業を実際に動かすプログラムや機械）を登録するときの一回限りの合言葉
  2. lease（リース：一時的な利用権）の利用記録（誰のどの利用権が、いつ、どの Runner で使われたか）

この 2 つは、あとから本人確認を強くしたくなったときの土台にもなります。

申し送り 3 / phase-6-extensions

危ないデータを受け入れる場合の隔離（サンドボックス）の前提

報告の要点： 「危ないデータを入れるのは本人の責任」という考え方は、被害がその本人だけに収まるときにしか成り立ちません。Locus はみんなで共有して使う道具なので、悪い仕組みが仕込まれたファイルが開かれた瞬間に、被害がサーバ側（つまり全員の資料がある場所）へ広がるおそれがあります。

開発側が取る対策： その危険を埋めるために「サンドボックス（隔離された安全な箱の中で動かす仕組み）」を使います。この安全な箱を使うことを前提として、「広く受け入れる」仕組みを作ります。

申し送り 4 / phase-6-extensions

同時作業の枠（スロット数 N）と機械の性能のバランス

報告の要点： 同時に動かせる作業の枠（スロット）を増やすと、メモリ（作業用の記憶場所）や GPU（画像や計算を高速に処理する部品）の消費も同じ割合で増えます。上限の数（N）は、実際にこのシステムを置く機械の性能で決まります。

開発側が取る対策： N は設定で変えられるようにしたままにし、システムを起動したときに実際の機械の性能を測って、上限を超えていたら警告を出すようにします。

申し送り 5 / phase-6-extensions

追加の本人確認（MFA）をやめたことによるパスワード周りの対策

報告の要点： MFA（多要素認証：パスワードに加えて別の確認も求める仕組み）は、2026年11月9日の記録では「本番で必ず必要」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、IAM-005（該当する要件の番号）の扱いを「実装しない（オーナー判断 2026年11月16日）」へ改めます。

残る弱点と対策： ID とパスワードだけになると、パスワードが漏れただけで全部の資料を見られてしまう弱点が残ります。そこで、代わりに次の 4 つを標準で入れます。

  • パスワードの最低限の強さ（簡単すぎるものを防ぐ）
  • 一定回数間違えたら一時的に入れなくする仕組み（一時ロック）
  • 既存の must_rotate（新しく発行したときや管理者がリセットしたあとの初回ログインで、必ずパスワードを変更させる仕組み。定期的な変更を強制するものではありません）
  • ログイン履歴を管理者が確認できる仕組み

申し送り 7 / phase-6-extensions

図を作るためのプログラム実行（B）に設ける安全制限

報告の要点： 「B（コード実行：プログラムを動かして図を作ること）」は、ファイルの中身を解析する作業よりも危険度が高い境界になります。解析は「攻撃者が選んだデータを読む」だけなのに対し、図を作る作業は「AI（モデル）が書いた命令そのものを実行する」ためです。

開発側が取る対策： T-PH6-104（別の作業番号）で使った安全の枠組みをそのまま使い回すのではなく、図を作る作業用に次の制限を追加する前提で進めます。これらは T-PH6-114（作図作業の番号）の合格条件（受入条件）に落とし込みます。

  • 実行するのは新しく作られたプログラム（コード）だけにし、利用者の元の資料は「読むだけ（書き換え不可）」で渡す
  • 外に出せる結果は「画像 1 枚」と「文字の出力（標準出力）」だけに限る
  • ネットワーク（外部との通信）はつなげない（遮断する）
  • 動かせる時間と使えるメモリ（作業用の記憶場所）は、図を作る作業専用の別枠にする
申し送り 8 / phase-6-extensions

ルール文書（CLAUDE.md と AGENTS.md）の食い違い

報告の要点： ルールを書いたファイルである CLAUDE.md と AGENTS.md には、いま「別の担当AIを同時にいくつも動かさない（サブエージェント駆動開発・並列エージェント起動を行わない）」とはっきり書かれており、今回の指示と食い違っています。

開発側からの提案： 実際のやり方に合わせて両方のファイルを書き換えることを提案します（ルールの文面変更にはオーナーの承認が必要なため、ここでは提案にとどめています）。食い違いをそのままにしておくと、次に別の担当者が読んだときにどちらが正しいのか分からなくなります。
