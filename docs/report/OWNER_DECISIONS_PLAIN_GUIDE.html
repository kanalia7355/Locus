2. 通行証の有効期限（TTL）が長いときの弱点と対策

決定どおりに作りますが、利用の許可証（通行証）の有効期限（TTL）を長くするほど、「万が一その通行証が外に漏れたときに、悪用され得る時間」も長くなるという弱点が残ります。

この弱点を補うため、「通行証を途中で無効にする機能（取消／revoke）」と「いつ使われたかの利用履歴を残す機能」を必ず入れる方針で進めます。なお、有効期限を短くしたいという指示があれば、いつでも設定で変えられるようにしておきます。

3. 同じネットワーク内（LAN内）でも攻撃は起こり得るという点と最小限の対策

「同じ施設内のネットワーク（LAN）の中だから攻撃は起きない」という前提には、開発側としては危険が残ると考えています。同じネットワークの中でも、ウイルス等に乗っ取られて踏み台にされたパソコンや、外から持ち込まれた端末、同じネットワーク内の別部署からのアクセスは起こり得るためです。

ただし、対策にどれだけの費用や手間をかけるかを決めるのはオーナーの役割なので、仕組みが重くなるおたがいの厳重な確認（相互認証）は入れずに進めます。その代わり、費用がほとんどかからず効果がある次の2つだけは入れます。

  • 作業を実行する機械（Runner）を登録するときの一回限りの合言葉
  • 一時的な利用許可（リース／lease）の利用記録（誰のどの許可が、いつ、どの機械で使われたか）

これらは、後から本人確認をさらに強くしたくなったときの土台にもなります。

4. 危ないファイルを開いたときの被害範囲と隔離の箱（サンドボックス）

「危ないデータを入れるのは本人の自己責任」という考え方は、被害がその人ひとりだけにとどまる場合にしか成り立ちません。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（全員の資料が置かれている中心のコンピュータ）へ広がる恐れがあります。

そのため、外に影響が出ないように隔離された安全な実行場所（サンドボックス）を使うことでその危険を埋めることにしており、その安全な仕組みを使う前提で「いろいろなファイルを広く受け入れる」機能を作ります。

5. 同時に動かす数（スロット数）とコンピュータの性能の関係

同時に動かせる作業の数（スロット数 N）を増やすと、その数に比例してパソコンの作業用記憶領域（メモリ）や計算装置（GPU）の消費量が増えます。

実際に動かせる N の上限は、このシステムを置く実機の性能によって決まるため、N は設定で変えられる値のままにしておき、起動したときに実際の性能を測って上限を超えていたら警告を出すようにします。
