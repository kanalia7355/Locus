オーナーの決定どおりに進めますが、通行証の有効期限（TTL：使える時間）が長いと漏れたときの危険も長く続くため、途中の取り消しと利用記録を必ず入れる方針で進めます。

ここは分かりません（元の文に書かれていません）。

決める前に知っておくこと

3. 同じネットワーク内（LAN 内）の本人確認を軽くすることへの対策

ひとことで言うと

重い本人確認は入れないというオーナーの判断どおりに進めますが、研究室などの内部ネットワーク（LAN 内）でも攻撃の危険はゼロではないため、費用がほぼかからない 2 つの記録・合言葉だけを入れます。

いまどうなっているの

「LAN 内だから攻撃がない」という前提には開発側として同意していませんが、費用（コスト）をかけるかどうかの判断はオーナーの役割であるため、重い相互認証（お互いに相手が本物か確かめ合う仕組み）は入れずに進めます。

決めないとどうなるの

ここは分かりません（元の文に書かれていません）。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

  • LAN の中であっても、乗っ取られた端末（踏み台になった端末）、外から持ち込まれた端末、同じ LAN にいる別の部署からのアクセスは起こりえます。
  • その弱点を補うため、費用がほぼゼロで効果がある次の 2 つだけは入れます。
    1. Runner（実際の作業を動かす機械やプログラム）を登録するときの「一回限りの合言葉」
    2. リース（lease：一時的な利用許可）の利用記録（誰のどの利用許可が、いつ、どの Runner で使われたか）
  • この 2 つは、あとから本人確認を強めたくなったときの土台にもなります。

4. 危険なデータを広く受け入れることと安全対策（サンドボックス）

ひとことで言うと

共有ツールである Locus で危険なファイルを開くと全員の資料に被害が及ぶおそれがあるため、安全な隔離空間（サンドボックス）を使う前提で「広く受け入れる（広く許容）」仕組みを作ります。

いまどうなっているの

決定どおり「広く許容（いろいろなファイルを広く受け入れること）」を実装しますが、その前提としてサンドボックス（危険な動きをしても外に広がらない隔離された部屋のような仕組み）を採用します。

決めないとどうなるの

ここは分かりません（元の文に書かれていません）。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

  • 「危ないデータを入れるのは本人の責任」という考え方は、被害が本人だけに閉じる場合にしか成り立ちません。
  • Locus はみんなで共有して使う仕組みなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（＝全員の資料がある場所）にまで広がる可能性があります。
  • サンドボックスを取り入れるのは、その危険を埋めるためです。

6. 二段階の本人確認（MFA / IAM-005）を使わない場合のパスワード対策

ひとことで言うと

MFA（多要素認証：パスワードに加えて確認コードなどを使う本人確認）が不要になったため IAM-005 は実装せず、代わりにパスワードの強さやロックなどの対策を標準で入れます。

いまどうなっているの

2026-11-09 の記録では MFA は「本番必須」と整理されていましたが、今回の回答で「不要」に変わったため、IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

決めないとどうなるの

ここは分かりません（元の文に書かれていません）。

選べるやり方

決める前に知っておくこと

  • ID とパスワードだけの場合、パスワードが外に漏れると、そのまま全員の資料を見られてしまう弱点が残ります。
  • その弱点を補うため、次の 4 つを標準のルール（既定）にします。

8. プログラムを動かして図を作る機能（B：コード実行 / T-PH6-114）の安全ルール

ひとことで言うと

図を作るためにプログラムを動かす機能（B：コード実行）は危険度が一段高いため、既存の安全ルール（T-PH6-104）をそのまま使い回さず、作図用の厳しい条件を追加して T-PH6-114 の合格条件に入れます。

いまどうなっているの

T-PH6-104 の境界（どこまで許すかの線引き）をそのまま使うのではなく、作図用に追加の制限を設ける前提で進めます。

決めないとどうなるの

ここは分かりません（元の文に書かれていません）。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

  • ファイルを読み取って調べる（ファイル解析）は「攻撃者が選んだデータを読む」ことですが、作図は「モデル（AI）が書いた命令を実行する」ことになるため、より踏み込んだ安全の境界が必要です。
  • そのため、作図用として次の条件を追加し、T-PH6-114 の受入条件（合格基準）に落とします。
    • 実行するのは生成された（自動で作られた）プログラム（コード）だけにし、利用者の資料の原本は「読み取り専用（書き換えできない状態）」で渡す
    • 外に出す結果（出力）は「画像 1 枚」と「標準出力（プログラムが出す文字の情報）」に限る
    • ネットワーク（外部との通信）は遮断する
    • 実行できる時間とメモリ（記憶領域）の上限は、作図用に別の枠を用意する
