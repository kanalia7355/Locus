1. 通行証の有効期限（TTL）と漏れたときのリスク

段階：phase-6-extensions

残る弱点と開発側の対応

通行証が使える有効期限（TTL）を長く設定するほど、万が一その通行証が外に漏れてしまったときに「不正に使われてしまう時間」も長くなります。

この弱点を補うため、あとから通行証を取り消して使えなくする仕組み（revoke）と、利用履歴の記録を必ず入れる方針で進めます。もし有効期限を短くしたいという指示があれば、いつでも設定で変えられるようにします。

2. 学内・研究室内のネットワーク（LAN）の安全性について

段階：phase-6-extensions

残る弱点と開発側の対応

「学内や研究室内のネットワーク（LAN）だから攻撃は起きない」という考え方に対して、開発側（実装側）としては賛成していません。同じネットワークの中であっても、ウイルスなどに感染して乗っ取られた端末（踏み台になった端末）、外から持ち込まれた端末、同じネットワークにつながる別部署の端末から攻撃が届くことは起こりえます。

ただし、どこまで費用や手間をかけるかの判断はオーナーの役割なので、重い仕組み（お互いに証明書で確認し合う強い認証）は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の2つだけは入れます。

  • 1. 作業を動かす機械やプログラム（Runner）を登録するときに使う、1回限りの合言葉
  • 2. 一時的な利用許可（リース：lease）の記録（誰のどの許可が、いつ、どの Runner で使われたか）

これらは、あとから本人確認を強めたくなったときの土台にもなります。

3. 危ないデータを受け入れることと、共有ツールとしてのリスク

段階：phase-6-extensions

残る弱点と開発側の対応

「危ないデータを入れるのは本人のせい」という考え方が成り立つのは、被害が本人だけに収まる場合だけです。いま作っているツール（Locus）はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（みんなの資料を保存して動かす中心のコンピュータ、つまり全員の資料）へ広がるおそれがあります。

その危険を埋めるために、サンドボックス（万が一危険な動きをしても外に被害が出ないように隔離する安全な箱）を使います。その前提の上で、ファイルを「広く許容する」仕組みを作ります。

4. 同時に動かせる数（スロット数 N）と機械の性能について

段階：phase-6-extensions

残る弱点と開発側の対応

同時に動かせる作業の枠（スロット）を増やすと、それに比例してメモリ（作業中にデータを一時的に置く場所）と GPU（画像処理や計算を速く行う部品）の消費量も増えます。設置する実際の機械の性能によって、動かせる数（N）の上限が決まります。

そのため、N は設定値のままにしておき、プログラムが動き出すときに実際の機械の性能を測って、もし上限を超えていたら警告を出すようにします。

申し送り

5. 二段階認証（MFA）をなくすことと、その代わりの守り

段階：phase-6-extensions

残る弱点と開発側の対応

二段階認証（MFA：パスワードだけでなくスマホの確認なども使う本人確認）は、2026-11-09 の記録では「本番で必須」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、要件番号 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に変更します。

ID とパスワードだけでログインする形にすると、パスワードが外に漏れたときにそのまま全員の資料が見られてしまう弱点が残ります。

代わりに、次の4つを標準の守りとして入れます。

  • パスワードの最低限の強さ（文字数や複雑さの基準）
  • ログインに何度も失敗したときの一時ロック
  • すでに決まっている must_rotate（アカウント発行時と、管理者がリセットしたあとの最初のログインで必ずパスワードを変えさせる仕組み。定期的な変更を強制するものではありません）
  • 管理者がログインの履歴を見られるようにすること

7. AIが書いたプログラムを動かして図を作る機能（B：コード実行）の安全策

段階：phase-6-extensions

残る弱点と開発側の対応

B（コード実行：プログラムを動かすこと）は、ファイルを読み取って解析する機能よりも、さらに踏み込んだ危険な境界になります。ファイルの解析は「攻撃者が選んだデータを読む」だけですが、図を作る機能は「AIモデルが書いた命令をそのまま実行する」ためです。

そのため、作業番号 T-PH6-104 の安全の仕組みをそのまま使い回すのではなく、図を作る機能向けに次の制限を追加する前提で進めます。これらは作業番号 T-PH6-114 の合格条件（受入条件）に入れます。

  • 実行するのは生成されたプログラムだけにし、利用者の元の資料は「読み取り専用（書き換え不可）」で渡す
  • 外に出せる結果は「画像1枚」と「文字の結果（標準出力）」だけに限る
  • 外部との通信（ネットワーク）は遮断する
  • 動かしてよい時間とメモリ（作業領域）は、図を作る機能専用の別枠にする
申し送り

8. 開発のルール文書（CLAUDE.md と AGENTS.md）の食い違い

段階：phase-6-extensions

残る弱点と開発側の対応
