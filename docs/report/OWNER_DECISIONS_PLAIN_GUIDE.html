2. 研究室内ネットワーク（LAN）の安全確認を軽くする代わりに入れる対策

ひとことで言うと

研究室内ネットワーク（LAN：建物内だけのネットワーク）だから安全だという前提には同意していませんが、コスト判断に従い重い確認は入れず、軽い対策2つだけを入れて進めるという報告です。

いまどうなっているの

コストの判断はオーナーの役割であるため、開発側は重い「相互認証（つなぐ側と受ける側の双方が厳しく相手を確認する仕組み）」は入れずに進めます。

決めないとどうなるの

これは決めてもらう項目ではなく、報告です。この項目で待っている作業については元の文に書かれていないため、ここは分かりません。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

研究室内ネットワーク（LAN）の中であっても、次のような経路からのアクセスや攻撃は起こりえます。

  • 踏み台（ウイルスなどに感染して攻撃の中継地点にされた端末）
  • 外部から持ち込まれた端末
  • 同じネットワーク内の別部署からの到達

そのため、開発側では費用がほぼゼロで効果がある次の2つだけを入れます。

  • 1. Runner（実際の作業を動かす仕組み）を登録するときの一回限りの合言葉
  • 2. リース（lease）（作業のために一時的に貸し出す利用枠）の利用記録（誰のどの枠が、いつ、どの Runner で使われたか）

この2つは、あとから本人確認を強めたくなった場合の土台にもなります。

3. 危険なファイルを受け入れる前提と安全な箱（サンドボックス）

ひとことで言うと

Locus はみんなで使う共有ツールなので、万が一危ないファイルが開かれても全員の資料に被害が広がらないよう、隔離する安全な箱（サンドボックス）を使う前提で「広く受け入れる」仕組みを作るという報告です。

いまどうなっているの

サンドボックス（外に被害が漏れないように隔離して動かす安全な箱）を採用することを前提に、「広く許容（いろいろなファイルを広く受け入れる）」を実装する方針です。

決めないとどうなるの

これは決めてもらう項目ではなく、報告です。この項目で待っている作業については元の文に書かれていないため、ここは分かりません。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

「危ないデータを入れるのは本人のせい」という考え方は、被害が本人の手元だけに閉じる場合にしか成り立ちません。Locus は共有ツールのため、悪意のあるファイルが開かれた瞬間に、サーバ側（みんなのデータをまとめて置く中心のコンピュータ＝全員の資料）へ被害が及ぶおそれがあります。サンドボックスの採用は、その差を埋めるためのものです。

4. 同時に動かす枠（スロット数 N）の決め方と警告

ひとことで言うと

同時に処理できる枠の数（スロット数 N）は設定で決められるままにし、起動したときに実際の機械の性能を超えていれば警告を出すようにするという報告です。

いまどうなっているの

スロット数 N は設定値のままにしておき、起動時に実際の機械で性能を測って、上限を超えていたら警告を出す形で進めます。

決めないとどうなるの

これは決めてもらう項目ではなく、報告です。この項目で待っている作業については元の文に書かれていないため、ここは分かりません。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

スロットを増やすと、それに比例してメモリ（作業のために一時的にデータを置く場所）や GPU（画像処理や計算を高速に行う部品）の消費量も増えます。N の上限は、実際に設置して動かすコンピュータ本体の性能によって決まります。

5. 多要素認証（MFA）を不要にした代わりに守るパスワードの仕組み

ひとことで言うと

多要素認証（MFA：パスワードに加えてスマホの確認コードなどで本人確認する仕組み）を「不要」とする判断に合わせ、IAM-005 は作らない扱いに改め、代わりにパスワードを守る標準の仕組みを入れるという報告です。

いまどうなっているの

MFA は 2026-11-09 の記録では「本番必須」と整理されていましたが、今回の回答で「不要」に変わったため、要件 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」へ改めます。

決めないとどうなるの

これは決めてもらう項目ではなく、報告です。この項目で待っている作業については元の文に書かれていないため、ここは分かりません。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

ID とパスワードだけでログインする形になると、パスワードが外に漏れただけで全員の資料を見られてしまうおそれがあります。そのため、開発側では代わりに次の4つを標準（既定）にします。

  • パスワードの最低限の強さを求めること
  • ログインに失敗した回数によって一時的にロックすること
  • 既存の must_rotate（アカウント発行時と、管理者がリセットした後の初回ログインで必ずパスワードを変更させる仕組み。定期的な変更を強制するものではありません）
  • ログイン履歴を管理者が確認できるようにすること

7. 作図のためにプログラムを動かすときの安全ルール

ひとことで言うと

作図のためのプログラム実行（B：コード実行）はファイル解析よりも危険に踏み込むため、T-PH6-104 の安全境界をそのまま使い回さず、作図専用の制限を追加して T-PH6-114 の合格条件にするという報告です。

いまどうなっているの

作図用の制限を追加する前提で開発を進め、それらを T-PH6-114 の受入条件（完成と認める合格ラインの条件）に落とし込みます。

決めないとどうなるの

これは決めてもらう項目ではなく、報告です。この項目は T-PH6-114 の受入条件に落とす形で進みます。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

ファイル解析は「攻撃者が選んだデータを読む」ことですが、作図は「AIモデルが書いた命令を実際に実行する」ことになり、より踏み込んだ境界になります。そのため T-PH6-104 の境界をそのまま使い回さず、次の4つを追加します。

  • 実行するのは作られたコードだけにし、利用者の資料原本は読み取り専用（見るだけで書き換えできない状態）で渡す
  • 出力は画像1枚と標準出力（文字を返す通常の出口）に限る
  • ネットワーク（外部との通信）は遮断する
  • 実行時間とメモリの上限は作図用に別の枠を設ける
