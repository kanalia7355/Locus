6. ログイン時の多要素認証（MFA）を省き、IDとパスワードだけにすることについて

ひとことで言うと

決めてもらう項目ではなく、多要素認証（MFA）が不要になった決定に従い、代わりにパスワード漏れのリスクを減らす4つの仕組みを標準にするという報告です。

いまどうなっているの

開発が止まっている理由の記載はありません。2026-11-09 の記録では「本番必須」とされていた多要素認証（MFA：パスワードに加えてスマホの確認などを使うログイン方法）が今回の回答で「不要」に変わったため、要件 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めました。

決めないとどうなるの

この決定を待っている特定の作業は、元の文には書かれていません（ここは分かりません）。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

  • IDとパスワードだけでログインする場合、パスワードが漏れるとそのまま全資料を見られてしまう弱点が残ります。
  • そのため、代わりに次の4つを標準（既定）にします。

7. 作図機能でプログラムを動かすときの安全の区切り（境界）について

ひとことで言うと

決めてもらう項目ではなく、作図機能（B：コード実行）はAIが書いた命令を実際に動かすため危険度が高く、ファイル解析用とは別に作図専用の厳しい制限を追加して進めるという報告です。

いまどうなっているの

開発が止まっている理由の記載はありません。T-PH6-104 の安全の仕切り（境界）をそのまま使い回すのではなく、作図用の制限を追加する前提で進めており、これらは T-PH6-114 の合格条件（受入条件）に落とし込みます。

決めないとどうなるの

T-PH6-114 の受入条件として組み込んで進めます（決定を待って止まっている作業の記載はありません）。

選べるやり方

選択肢は示されていません。

決める前に知っておくこと

  • B（コード実行：プログラムを動かすこと）は、ファイル解析よりも踏み込んだ危険になりうる境界です。ファイル解析は「攻撃者が選んだデータを読む」だけですが、作図は「AI（モデル）が書いた命令を実行する」ためです。
  • そのため、作図用として次の制限を追加します。
    • 実行するのは生成されたコードだけにし、利用者の資料の原本は「見るだけ（読み取り専用）」で渡す
    • 出力は「画像1枚」と「文字の結果（標準出力）」だけに限る
    • 通信（ネットワーク）は遮断する
    • 実行時間とメモリの量は、作図用に別枠で制限する
