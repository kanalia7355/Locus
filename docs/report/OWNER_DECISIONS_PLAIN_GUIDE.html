2. 通行証の有効期限（TTL）を長くする場合の対策

報告

利用許可の通行証（TTL＝有効期限）を長くすると、もしその通行証が外に漏れたときに「悪用されてしまう時間」も長くなるという弱点が残ります。

そのため、決定どおりに作る代わりに、途中で「使えなくする取り消し機能（revoke）」と「利用履歴の記録」を必ず入れる方針で進めます。なお、有効期限を短くしたいという指示があれば、いつでも設定で変えられます。

目次に戻る

3. 研究室内ネットワーク（LAN）の安全性と最小限の対策

報告

「研究室内と同じネットワーク（LAN）の中だから攻撃はない」という前提には、安全面を作る立場として同意していません。同じネットワーク内でも、ウイルスなどで乗っ取られた端末、外からの持ち込み端末、同じネットワークにつながる別部署からのアクセスは起こりうるためです。

ただし、対策にどれだけ費用や手間をかけるかの判断はオーナーの領分であるため、重い仕組み（相互認証）は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の2つだけを入れます。

  • 作業を実行する仕組み（Runner）を登録するときの一回限りの合言葉
  • 貸し出し許可（リース）の利用記録（誰のどの許可が、いつ、どの実行機で使われたかの記録）

これらは、後から本人確認を強くすることになった場合の土台にもなります。

4. 危険なファイルを開いたときの被害範囲と隔離の仕組み

報告

「危険なデータを入れるのは入れた本人の責任」という考え方は、被害が本人だけに収まる場合にしか成り立ちません。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、サーバー側（つまり全員の資料）へ被害が広がるおそれがあります。

隔離された安全な箱（サンドボックス）を採用するのは、その危険を補うためです。この安全な箱の中で動かすことを前提として、オーナーの決定どおり「いろいろなファイルを広く受け入れる」動きを作ります。

目次に戻る

5. 同時に動かせる数（スロット数）とパソコン性能の上限

報告

同時に処理できる数（スロット数 N）を増やすと、それに比例して記憶場所（メモリ）や計算用の部品（GPU）の消費も増えます。

実際に動かせる N の上限は、システムを置く実機の性能によって決まるため、N は設定で変えられるようにしたまま、起動したときに実際の性能を測って、無理がある数値になっていたら警告を出すようにします。

6. 二段階認証（MFA）をなしにする場合の代わりの守り

報告

二段階認証（MFA、パスワードに加えて別の確認を求める仕組み）は、2026年11月9日の記録では「本番環境で必須」と整理されていましたが、今回の回答で「不要」に変わったため、該当する機能（IAM-005）の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

IDとパスワードだけで入る形になると、パスワードが漏れたときにそのまま全員の資料が見られてしまう弱点が残ります。そのため、代わりに次の4つを標準の設定にします。

  • パスワードに最低限の複雑さを求めること
  • 何度か入力を間違えたら一時的に入れなくするロック
  • 発行時と管理者がリセットした後の初回ログインで必ずパスワードを変えさせる仕組み（既存の must_rotate。定期的な変更は強制しません）
  • いつ誰がログインしたかを管理者が確認できる履歴

7. AIが書いた命令を動かす作図機能の制限

報告

「B（プログラムの実行）」は、ファイルの解析よりも危険度が高い境界になります。解析は「誰かが用意したデータを読むだけ」なのに対し、作図は「AIが書いた命令を実際に動かす」ためです。

そのため、すでに決まっている境界（T-PH6-104）をそのまま使い回すのではなく、作図用（T-PH6-114 の合格条件）として次の4つの制限を追加する前提で進めます。

  • 動かすのはAIが作ったプログラムだけにし、利用者の元の資料は書き換えできない「読み取り専用」で渡す
  • 外に出せる結果は「画像1枚」と「文字の画面出力（標準出力）」だけに限る
  • ネットワーク（外部や他の機器との通信）は遮断する
  • 実行できる時間と記憶容量（メモリ）は作図用の別枠で制限する
