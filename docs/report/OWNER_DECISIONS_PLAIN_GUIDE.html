申し送り / 有効期限（TTL）

通行証の有効期限（TTL）が長いことへの対策

ひとことで言うと

通行証の有効期限（TTL）を長くする決定どおりに作りますが、漏れたときの危険を補う仕組みを必ず入れます。

残る弱点と、開発側が入れる対策

通行証の有効期限（TTL）が長いほど、もしその通行証が外に漏れてしまったときに、悪い人に使われてしまう時間も長くなります。

この弱点を補うため、次の 2 つを必ず入れる方針で進めます。

  • 途中で通行証を使えなくする仕組み（取消、revoke）
  • いつ誰が使ったかの利用履歴の記録

なお、有効期限を短くしたいという指示があれば、いつでも設定で変えられるようにします。

申し送り / 内部ネットワーク（LAN）

研究室の内部ネットワーク（LAN）内での安全性について

ひとことで言うと

費用がかかる厳重な本人確認は入れずに進めますが、ほぼ費用ゼロでできる最小限の対策を 2 つ入れます。

残る弱点と、開発側が入れる対策

開発側としては「研究室の内部ネットワーク（LAN）の中だから攻撃は起きない」という前提には同意していません。内部のネットワークであっても、乗っ取られたパソコン（踏み台になった端末）、外から持ち込まれた端末、同じネットワークにつながる別の部署からのアクセスは起こりえます。

ただし、どこまで費用や手間をかけるかはオーナーが判断することなので、大がかりでお金や手間がかかる相互認証（お互いに厳しく本人確認し合う仕組み）は入れずに進めます。その代わり、費用がほとんどかからずに効果がある次の 2 つだけを入れます。

  1. 計算を動かす機械（Runner）を登録するときに使う、一回限りの合言葉
  2. 利用許可証（リース、lease）の使用記録（誰のどの許可証が、いつ、どの機械で使われたかの記録）

この 2 つは、あとから本人確認を強くしたくなったときの土台にもなります。

申し送り / 共有ツールと安全な箱（サンドボックス）

危ないファイルをみんなで使う仕組みの中で開くときの守り方

ひとことで言うと

Locus はみんなで共有する道具なので、安全な箱（サンドボックス）を使うことを前提に「いろいろなファイルを広く受け入れる」仕組みを作ります。

残る弱点と、開発側が入れる対策

「危ないデータを入れるのは本人のせい」という考え方が成り立つのは、被害が本人だけにとどまるときだけです。Locus はみんなで共有して使うツールなので、悪意のあるファイルが開かれた瞬間に、データを保管している本体側（サーバ側、つまり全員の資料）にまで被害が広がるおそれがあります。

開いたファイルを隔離された安全な箱の中に閉じ込めて動かす仕組み（サンドボックス）を取り入れるのは、その危険を埋めるためです。この安全な箱を使うことを前提として、「広く受け入れる（広く許容）」仕組みを作ります。

申し送り / 同時実行数（スロット N）

同時に動かす枠の数（スロット N）と機械の性能について

ひとことで言うと

同時に動かす枠の数（N）は設定で変えられるままにし、起動するときに機械の性能を測って無理があれば警告を出します。

残る弱点と、開発側が入れる対策

同時に動かす枠（スロット）の数を増やすと、作業用の記憶場所（メモリ）や画像・計算用の部品（GPU）の消費量も比例して増えます。実際にどこまで増やせるかの上限は、システムを置く実機の性能によって決まります。

そのため、枠の数 N は決まった数値に固定せず設定値のままにしておき、起動するときに実際の機械の性能を測って、上限を超えていたら警告を出すようにします。

申し送り / 二段階認証（MFA）なし

二段階認証（MFA）なしで ID とパスワードだけにする場合の守り方

ひとことで言うと

二段階認証（MFA）は作らず ID とパスワードのみにしますが、パスワードが漏れたときの危険を減らすための 4 つの仕組みを初期設定にします。

残る弱点と、開発側が入れる対策

二段階認証（MFA）は 2026年11月9日の記録では「本番で必須」として整理されていましたが、今回の回答で「不要」に変わったため、IAM-005 という項目の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

ID とパスワードだけの仕組みでは、パスワードが外に漏れるとそのまま全員の資料を見られてしまう弱点が残ります。そのため、代わりに次の 4 つを最初から動く設定（既定）にします。

  • パスワードの最低限の強さ（最低強度）のルール
  • ログインに一定回数失敗したときの一時的な利用停止（一時ロック）
  • すでに用意されている must_rotate（アカウント発行時と、管理者がリセットしたあとの最初のログインで、必ずパスワードを変更させる仕組み。定期的な変更を強制するものではありません）
  • いつ誰がログインしたかの履歴を、管理者が見られるようにすること

申し送り / コード実行による作図

AI が書いた命令を動かして図を作るときの安全の仕組み

ひとことで言うと

AI が書いたプログラムを動かして図を作る処理（B）は危険度が一段高いため、作図専用の厳しい制限を追加して作ります。

残る弱点と、開発側が入れる対策

プログラムを動かして図を作る処理（B：コード実行）は、ファイルの中身を調べる処理（ファイル解析）よりも踏み込んだ境界になります。ファイル解析は「攻撃者が選んだデータを読む」だけですが、作図は「AI モデルが書いた命令を実際に実行する」ことになるためです。

そのため、T-PH6-104 で使う安全の境界をそのまま使い回すのではなく、作図用として次の 4 つを追加する前提で進めます。これらは T-PH6-114 の完成条件（受入条件）に入れます。

  • 実行するのは新しく作られたプログラム（コード）だけにして、利用者の元の資料は書き換えできない状態（読み取り専用）で渡す
  • 外に出せる結果は「画像 1 枚」と「画面に出る文字情報（標準出力）」だけに限る
  • 外部との通信（ネットワーク）は遮断する
  • 動かせる時間と使える記憶場所（メモリ）は、作図専用の別枠にする
