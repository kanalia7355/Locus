同じネットワーク（LAN）内の安全性への考え方と最小限の対策

申し送り（報告）
段階：phase-6-extensions

「同じ施設内ネットワーク（LAN）の中だから攻撃は起きない」という前提には、開発側としては同意していません。LAN の中であっても、乗っ取られて踏み台になった端末、外から持ち込まれた端末、同じ LAN 内の別部署からのアクセスは起こりえます。

ただし、安全対策にどこまで費用や手間をかけるかはオーナーの判断領域なので、重たい相互認証（お互いを厳重に確認し合う仕組み）は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の2つだけは入れます。

  • 作業実行機（Runner）を登録するときの一回限りの合言葉
  • 利用許可証（lease／リース）の利用記録（誰のどの許可証が、いつ、どの実行機で使われたか）

これらは、後から本人確認を強めたくなった場合の土台にもなります。

申し送り（報告）
段階：phase-6-extensions

「危ないデータを入れるのは本人の責任」という考え方は、被害がその人だけに収まる場合にしか成り立ちません。Locus はみんなで共有して使う道具なので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（つまり全員の資料）へ広がるおそれがあります。

隔離された安全な箱（サンドボックス）を使うのはその危険の差を埋めるためであり、この隔離を前提として「広く受け入れる」仕組みを作ります。

同時実行数（スロット数 N）と実機性能の関係

申し送り（報告）
段階：phase-6-extensions

同時に動かせる枠（スロット）の数 N を増やすと、メモリや画像処理装置（GPU）の消費量もそれに比例して増えます。

実際に動かせる N の上限は、設置先の機械の性能によって決まります。そのため、N は設定で変えられる値のままにしつつ、起動するときに機械の性能を実際に測って、上限を超えていたら警告を出すようにします。

作図のためのプログラム実行（B）に足す安全条件

申し送り（報告）
段階：phase-6-extensions

やり方 B（プログラムを実行して図を作る仕組み）は、ファイルを読み取って調べるだけの「解析」よりもさらに危険の境界が深くなります。解析が「相手が選んだデータを読み取る」のに対し、作図は「AIモデルが書いた命令をそのまま動かす」ためです。

そのため、T-PH6-104 の安全境界をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進めます。これらは T-PH6-114 の完了条件（受入条件）に組み込みます。

  • 実行するのは生成されたプログラムだけにし、利用者の資料原本は書き換えできない「読み取り専用」で渡す
  • 外に出せる結果は、画像1枚と文字の出力（標準出力）だけに限る
  • ネットワーク接続は遮断する
  • 動かせる時間とメモリの上限は、作図用に別枠で決める
