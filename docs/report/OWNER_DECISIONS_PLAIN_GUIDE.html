1. 通行証（アクセス権限）の有効期限について

オーナーの決定どおりに進めますが、次の弱点が残ります：

一時的な通行証の有効期限（TTL）を長くするほど、「万が一その通行証が外に漏れたときに、悪い人に使われうる時間」も長くなります。

開発側が取る補いの対策：

  • 途中で通行証を無効にできる仕組み（取消 / revoke）と、利用履歴の記録を必ず入れる方針で進めます。
  • あとから「やっぱり有効期限を短くしたい」と指示があれば、設定だけでいつでも変えられるようにします。
phase-6-extensions申し送り 2

2. 研究室内のネットワーク（LAN）の安全性について

オーナーの決定どおりに進めますが、次の前提には開発側として同意していません：

「同じ研究室内のネットワーク（LAN）の中だから攻撃は起きない」という前提は安全とは言えません。同じネットワーク内であっても、乗っ取られて踏み台にされたパソコン、外から持ち込まれた端末、同じネットワーク内の別部署からのアクセスは起こりえます。

開発側が取る補いの対策：

ただし、どこまで手間や費用をかけるかの判断はオーナーの領分であるため、手間のかかる重い相互認証（機械どうしが厳しく身元を確かめ合う仕組み）は入れずに進めます。その代わり、費用がほぼかからず効果のある次の2つだけを入れます。

  1. 作業を実行する機械（Runner）を登録するときに使う、一回限りの合言葉
  2. 貸し出し（リース）の利用記録（「誰の・どの貸し出しが・いつ・どの実行機械で使われたか」）

この2つは、あとから本人確認を強めたくなったときの土台にもなります。

3. 危険なファイルを開いたときの影響範囲について

オーナーの決定どおりに進めますが、次の弱点に注意が必要です：

「危ないデータを入れるのは本人の責任」という考え方は、被害が本人だけにとどまる場合にしか成り立ちません。このツール（Locus）はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバー側（＝全員の資料）へ広がるおそれがあります。

開発側が取る補いの対策：

専用の隔離された安全な箱（サンドボックス）を使うのは、その危険の差を埋めるためです。この隔離を前提として、「ファイルを広く受け入れる」方針を実装します。

4. 同時作業枠（スロット）の数と機械の性能について

オーナーの決定どおりに進めますが、次の点に注意が必要です：

同時に動かせる作業枠（スロット）の数 N を増やすと、パソコンの記憶容量（メモリ）や計算装置（GPU）の消費量が比例して増えます。実際に動かせる上限は、このシステムを置く実機の性能によって決まります。

開発側が取る補いの対策：

数 N は設定で変えられる値のままにし、システムを起動したときに実機の性能を測って、上限を超えている場合は警告を出すようにします。

5. 二段階認証（MFA）をなくした代わりの安全策について

オーナーの決定どおりに進めますが、次の弱点が残ります：

二段階認証（MFA：パスワードだけでなくスマホの確認コードなどでも本人確認する仕組み）は、2026年11月9日の記録では「本番環境で必須」と整理されていましたが、今回の回答で「不要」に変わりました。そのため、要件番号 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

IDとパスワードだけでログインできるようにすると、パスワードが1つ漏れただけで、そのまま全員の資料が見られてしまう弱点が残ります。

開発側が取る補いの対策（標準で入れる4つの仕組み）：

  1. パスワードの最低限の強さ（短すぎたり単純すぎたりするものを拒否する決まり）
  2. ログインに何回か失敗したときの一時ロック
  3. 既存の must_rotate（アカウント発行時や管理者がリセットした後の初回ログイン時に、必ずパスワードを変えさせる仕組み。定期的な変更を強制するものではありません）
  4. 誰がいつログインしたかの履歴を、管理者が確認できるようにすること
phase-6-extensions申し送り 6

6. 作図のためにプログラムを実行する機能の安全策について

オーナーの決定どおりに進めますが、次の大きな違いがあります：

作図のためにプログラムを動かす機能（B）は、単なるファイル解析よりもさらに危険な境界になります。ファイル解析は「誰かが選んだデータを読む」だけですが、作図は「AIモデルが書いた命令を実際に動かす」からです。

開発側が取る補いの対策：

T-PH6-104 で作る安全の境目をそのまま使い回すのではなく、作図用として次の4つの条件を追加する前提で進め、作業番号 T-PH6-114 の合格条件に組み込みます。

  1. 動かすのはAIが作ったプログラムだけにし、利用者の資料の原本は「見るだけ（書き換え不可）」で渡す。
  2. 外に出せる結果は「画像1枚」と「画面への文字出力（標準出力）」だけに絞る。
  3. 外部やほかの機械との通信（ネットワーク）は遮断する。
  4. 動かせる時間の上限と使えるメモリの上限を、作図用として別枠で設ける。
