申し送り 2 / phase-6-extensions

通行証の有効期限（TTL）を長くすることについて

オーナーの決定どおりに進めること

決められた有効期限（TTL：ログインや利用のための通行証が使える時間）の長さで開発を進めます。

残る弱点

通行証の有効期限が長いほど、万が一その通行証が外に漏れてしまったときに、悪用され続ける時間も長くなります。

開発側が取る対策と補足

弱点を補うため、通行証を途中で無効にする「取消（revoke）」の仕組みと、「誰がいつ使ったかの利用履歴」を記録する仕組みを必ず入れます。なお、有効期限を短くしたいという指示があれば、いつでも設定で変えられるようにしておきます。

申し送り 3 / phase-6-extensions

同じネットワーク（LAN）内の安全性と対策について

オーナーの決定どおりに進めること

費用や手間（コスト）をかけるかどうかの判断はオーナーの役割であるため、大がかりでお互いに本人確認をし合う仕組み（重い相互認証）は入れずに進めます。

残る弱点（開発側が同意していない点）

開発側としては、「同じ研究室や組織のネットワーク（LAN）の中だから攻撃は起きない」という前提には同意していません。同じネットワークの中であっても、乗っ取られて踏み台にされたパソコン、外から持ち込まれた端末、同じネットワークをつかう別部署からのアクセスによって攻撃される可能性はあります。

開発側が取る対策

その代わり、追加の費用がほとんどかからず効果のある次の2つだけを入れます。

  1. 作業を実行する機械（Runner）を登録するときに使う、1回限りの合言葉
  2. 一時的な利用許可（リース / lease）の使用記録（誰のどの利用許可が、いつ、どの Runner で使われたかの記録）

この2つは、後から本人確認を強くしたくなったときの土台にもなります。

申し送り 4 / phase-6-extensions

いろいろなファイルを広く受け入れることについて

オーナーの決定どおりに進めること

ファイルを厳しく制限せず「広く許容」する形で開発を進めます。

残る弱点

「危ないデータを入れるのは本人のせい」という考え方は、被害がその人だけに留まる場合にしか成り立ちません。このツール（Locus）はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、データを保管している本体（サーバ側、つまり全員の資料）へ被害が広がるおそれがあります。

開発側が取る対策

その危険を埋めるために、隔離された安全な箱の中で動かす仕組み（サンドボックス）を採用します。それを前提として「広く許容」を実装します。

申し送り 5 / phase-6-extensions

同時に動かせる枠の数（スロット数 N）について

オーナーの決定どおりに進めること

同時に処理できる枠の数（スロット数 N）は、指定された設定値のまま使えるようにします。

残る弱点

同時に動かす枠を増やすと、パソコンの記憶領域（メモリ）や画像・計算処理装置（GPU）の消費量もその数に比例して増えます。実際に動かせる上限は、ソフトを動かす実機（パソコンやサーバ）の性能によって決まります。

開発側が取る対策

ソフトを起動したときに実機の性能を実際に測り、設定された数 N が性能の上限を超えている場合は警告を出すようにします。

申し送り 6 / phase-6-extensions

2段階認証（MFA）を無しにすることについて

オーナーの決定どおりに進めること

多要素認証（MFA：パスワードに加えてスマホなどで本人確認をする仕組み）は、2026年11月9日の記録では「本番必須」と整理されていましたが、今回のオーナーの回答で不要に変わりました。そのため、要件 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

残る弱点

IDとパスワードだけでログインする場合、パスワードが外に漏れてしまうと、そのまま全員の資料を見られてしまうことにつながります。

開発側が取る対策

代わりに、次の4つを初期設定（既定）として組み込みます。

  1. パスワードの最低限の強さ（短すぎたり簡単すぎたりするものを防ぐルール）
  2. ログインに一定回数失敗したら、一時的に使えなくする仕組み（一時ロック）
  3. すでにある must_rotate の仕組み（アカウント発行時と、管理者がリセットした後の最初のログイン時に、必ずパスワードを変更させる仕組み。定期的な変更を強制するものではありません）
  4. 誰がいつログインしたかの履歴を、管理者が確認できるようにすること
申し送り 7 / phase-6-extensions

決まったことの扱いと「申し送り」の意味について

ここで決まった項目だけが、作業予定表（PROGRESS.md）の実際の作業（ジョブ）に変換されます。決まっていない項目は作業にしません。

これらの【申し送り】は、オーナーの決定をひっくり返すものではありません。決定どおりに作るうえで開発側が取る補いの対策をはっきり伝えているだけであり、オーナーから「不要」と指示されれば外します。

申し送り 8 / phase-6-extensions

AIが書いたプログラムを動かして図を作る機能（B：コード実行）について

オーナーの決定どおりに進めること

AIが書いたプログラムを動かして図を作る機能（B：コード実行）の開発を進めます。

残る弱点（これまでの作業との違い）

コード実行は、これまでのファイル解析（T-PH6-104）よりもさらに踏み込んだ危険な境界（外部との区切り）になります。ファイル解析は「攻撃者が用意したデータを読む」だけなのに対し、作図は「AIモデルが書いた命令を実際に動かす」ためです。

開発側が取る対策

ファイル解析（T-PH6-104）の安全対策をそのまま使い回すのではなく、作図用に次の4つを追加する前提で進め、作業 T-PH6-114 の完成条件（受入条件）に入れます。

  1. 実行するのはAIが作ったコードだけにして、利用者の元資料は書き換えられない形（読み取り専用）で渡す
  2. 外に出力できるものは「画像1枚」と「画面に出る文字（標準出力）」だけに限定する
  3. 外部との通信（ネットワーク）はすべて遮断する
  4. 動かせる時間と記憶領域（メモリ）の上限を、作図専用の別枠として決める
申し送り 9 / phase-6-extensions

開発ルール書（CLAUDE.md と AGENTS.md）の食い違いについて
