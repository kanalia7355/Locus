申し送り4：同時実行の枠（スロット）を増やしたときの機械への負担

残る弱点：同時に動かせる枠（スロット）の数 N を増やすと、それに比例してメモリや GPU（画像処理やAIの計算に使う部品）の消費量が増えます。動かせる上限は、実際に設置する機械の性能で決まります。

申し送り5：二段階認証（MFA）を不要とした場合のパスワード対策

残る弱点：ID とパスワードだけで入る仕組みの場合、パスワードが外に漏れると、そのまま全員の資料が見られてしまうおそれがあります。

開発側の対応：二段階認証を入れない代わりに、次の4つを標準の仕組み（既定）にします。

  • ログインに何度も失敗したときの一時ロック。
  • 既存の must_rotate（アカウント発行時と、管理者がパスワードをリセットしたあとの初回ログイン時に、必ず本人にパスワードを変えさせる仕組み。定期的な変更を強制するものではありません）。
  • 管理者がログイン履歴を確認できること。

申し送り phase-6-extensions

申し送り6：作図のためにプログラムを実行する機能の安全対策

残る弱点：B（プログラムのコードを動かして作図する機能）は、ファイルを読み取るだけの解析よりも危険な境界になります。ファイルの解析は「攻撃者が選んだデータを読む」だけですが、作図は「AIモデルが書いた命令を実際にコンピュータに実行させる」からです。

開発側の対応：T-PH6-104 の安全境界をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進め、これらを T-PH6-114 の合格条件に入れます。

  • 実行するのはAIが作ったコードだけにして、利用者の資料の原本は「読み取り専用（書き換え不可）」で渡す。
  • 外に出せる結果は、画像1枚と文字の出力（標準出力）だけに限る。
  • インターネットや外部との通信（ネットワーク）は遮断する。
