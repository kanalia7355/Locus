2. 通行証の有効期限（TTL）の長さについて

phase-6-extensions

通行証の有効期限（TTL：使える時間の長さ）を長くすると、万が一その通行証が外に漏れたときに「不正に使われてしまう時間」も長くなります。

そのため開発側では、途中で通行証を無効にする仕組み（取消 / revoke）と、使われた履歴の記録を必須にして安全性を補う方針で進めます。なお、有効期限を短くする指示があれば、いつでも設定で変えられます。

3. 研究室内のネットワーク（LAN）の安全性について

phase-6-extensions

「研究室内などの閉じたネットワーク（LAN）の中だから攻撃は起きない」という前提には、開発側として同意していません。LAN の中でも、乗っ取られた端末・外から持ち込まれた端末・同じ LAN につながっている別の部署からのアクセスは起こりえます。

ただし、費用をかけるかどうかの判断はオーナーの役割なので、手間やコストの重い「お互いを厳しく確認する仕組み（相互認証）」は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の 2 つだけを入れます。

  • 作業を実行する仕組み（Runner）を登録するときの、1 回限りの合言葉
  • 一時的な利用許可（リース）の利用記録（誰のどの許可が、いつ、どの Runner で使われたか）

これらは、後から本人確認を強めることになった場合の土台にもなります。

4. 危ないデータの受け入れと被害の範囲について

phase-6-extensions

「危ないデータを入れるのは本人の責任」という考え方は、被害が本人の範囲にとどまる場合にしか成り立ちません。Locus はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバ側（つまり全員の資料）へ広がる可能性があります。

外に影響が漏れない隔離された箱（サンドボックス）を使うのはその差を埋めるためであり、その隔離を前提にして「データを広く受け入れる」方針を実装します。

5. 同時に動かす数（スロット）を増やすことについて

phase-6-extensions

同時に動かせる作業の枠（スロット）を増やすと、メモリや GPU（画像処理や AI の計算に使う部品）の消費量もそれに比例して増えます。

実際に動かせる上限の数（N）は、設置先の機械の性能によって決まります。そのため、N は設定で変えられる値のままにしておき、起動するときに実際の性能を測って、上限を超えていれば警告を出すようにします。

6. 二段階の本人確認（MFA）を無しにしたことについて

phase-6-extensions

パスワードに加えて別の確認も求める仕組み（MFA：多要素認証）は、2026-11-09 の記録では「本番環境で必須」と整理されていましたが、今回の回答で不要に変わりました。そのため、要件 IAM-005 の扱いを「実装しない（オーナー判断 2026-11-16）」に改めます。

ID とパスワードだけの仕組みでは、パスワードが漏れるとそのまま全員の資料を見られてしまう危険が残ります。そこで代わりに、次の 4 つを標準の対策にします。

  • パスワードの最低限の強さを決める
  • ログインに何度も失敗したら一時的にロックする
  • すでにある must_rotate（発行時と、管理者がリセットした後の初回ログインで必ずパスワードを変更させる仕組み。定期的な変更の強制ではない）を使う
  • 管理者がログイン履歴を見られるようにする

8. プログラムによる作図（コード実行）の安全性について

phase-6-extensions

「やり方 B（プログラムを実行して作図すること）」は、ファイルを読み取って解析する作業よりも、安全の区切り（境界）がさらに一歩踏み込んだものになります。ファイル解析は「攻撃者が選んだデータを読む」だけですが、作図は「AI モデルが書いた命令を実際に動かす」ためです。

そのため、T-PH6-104 で作った安全の区切りをそのまま使い回すのではなく、作図用として次の条件を追加する前提で進めます。これらは T-PH6-114 の合格条件（受入条件）に組み込みます。

  • 動かすのは生成されたプログラムだけにして、利用者の資料原本は「読み取り専用」で渡す
  • 出力してよいものは、画像 1 枚と文字の出力（標準出力）だけに限る
  • ネットワーク（外部との通信）は遮断する
  • 実行できる時間と使えるメモリの量は、作図用に別の枠として制限する
