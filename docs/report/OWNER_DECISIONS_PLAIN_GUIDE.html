通行証（TTL）の有効期限が長いことについて

報告の要旨： 決定どおりの長い有効期限で作りますが、通行証が漏れたときに悪用される時間も長くなるという弱点が残ります。

  • 残る弱点： 通行証（TTL：利用許可が有効な時間）が長いほど、もし誰かに盗まれたり漏れたりしたときに、その通行証が使える時間も長くなります。
  • 開発側が入れる補いの仕組み： あとから通行証を使えなくする「取消（revoke）」の仕組みと、誰がいつ使ったかを残す「利用履歴の記録」を必須にして進めます。
  • 補足： もっと短くしたいという指示があれば、いつでも設定で変えられるようにします。

社内ネットワーク（LAN）の安全性について

報告の要旨： オーナーの判断に合わせて重い本人確認は入れずに作りますが、「社内ネットワーク内だから攻撃されない」という前提には開発側として同意していません。

  • 残る弱点： 社内ネットワーク（LAN：同じ建物や組織の中だけのつながり）の中であっても、ウイルスなどに乗っ取られて踏み台にされた端末、外から持ち込まれた端末、同じ LAN の別部署からのアクセスは起こりえます。
  • 開発側が入れる補いの仕組み： どこまでコスト（費用や手間）をかけるかはオーナーが決めることなので、重い相互認証（お互いを厳しく確認し合う仕組み）は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の2つだけは入れます。
    1. 作業を行う仕組み（Runner）を登録するときの一回限りの合言葉
    2. 貸し出し（lease：利用許可）の利用記録（誰のどの利用許可が、いつ、どの Runner で使われたか）
  • 補足： これら2つは、あとから本人確認を強めたくなったときの土台にもなります。

危ないファイルを入れたときの被害の範囲について

報告の要旨： 「いろいろなファイルを広く受け入れる」方針で作りますが、隔離された箱（サンドボックス）を使って全員の資料を守る前提で進めます。

  • 残る弱点と背景： 「危ないデータを入れるのは本人のせい」という考え方は、被害が本人だけに収まる場合にしか成り立ちません。このシステム（Locus）はみんなで使う共有ツールなので、悪意のあるファイルが開かれた瞬間に、被害がサーバー側（つまり全員の資料）へ広がるおそれがあります。
  • 開発側の進め方： その危険を埋めるために隔離された箱（サンドボックス）を採用しており、その隔離があることを前提として「広く許容」の仕組みを作ります。

同時に動かす枠（スロット数 N）と機械の性能について

報告の要旨： 同時に動かせる枠の数（スロット数 N）は設定で変えられるままにして作りますが、機械の性能を超える設定にすると動かなくなるおそれがあります。

  • 残る弱点： スロットを増やすと、それと同じ割合でメモリや画像処理装置（GPU）の消費量が増えます。安全に動かせる N の上限は、実際にシステムを置く機械の性能によって決まります。
  • 開発側が入れる補いの仕組み： N は設定値のままにしておき、システムを起動したときに実際の機械の性能を測って、上限を超えていたら警告を出すようにします。

作図のためのプログラム実行（B）の安全境界について

報告の要旨： 作図のためにプログラムを動かす機能（B）を作りますが、普通のファイル解析よりも危険に近いため、作図専用の厳しい制限を追加したうえで進めます。

  • 残る弱点と違い： ファイル解析は「攻撃者が選んだデータを読む」だけなのに対し、作図（コード実行）は「AIモデルが書いた命令そのものを実行する」ため、より踏み込んだ安全の境界が必要になります。
  • 開発側が入れる補いの仕組み： T-PH6-104 の境界をそのまま使い回すのではなく、作図用として次の条件を追加する前提で進め、これらを T-PH6-114 の受け入れ条件（完了の条件）に組み込みます。
    • 実行するのは生成されたプログラムだけにし、利用者の資料原本は書き換えられない状態（読み取り専用）で渡す
    • 外に出せる結果は、画像1枚と画面の文字出力（標準出力）だけに限る
    • ネットワーク（通信）は遮断する
    • 動かせる時間とメモリの上限は、作図用として別枠で決める
