1. 通行証の有効期限（TTL）が長いことへの対策

報告内容

一時的な通行証の有効期限（TTL：使える時間の上限）が長いほど、もしその通行証が外に漏れたときに「他人に不正に使われてしまう時間」も長くなります。

オーナーの決定どおりに進めますが、この弱点を補うため、開発側では次の2つを必須にして進めます。

  • 後から通行証を無効にできる仕組み（取消 / revoke）
  • 誰がいつ使ったかの利用履歴の記録

なお、有効期限を短くしたいという指示をいただければ、いつでも設定で変えられます。

2. 研究室の内部ネットワーク（LAN）の安全性と費用のバランス

報告内容

「研究室の内部ネットワーク（LAN）の中だから攻撃は起きない」という前提には、プログラムを作る側としては同意していません。内部ネットワークであっても、ウイルス等に乗っ取られた端末（踏み台になった端末）、外から持ち込まれた端末、同じネットワーク内の別部署からのアクセスは起こりうるためです。

ただし、どれだけ費用や手間をかけるかの判断はオーナーの役割ですので、決定どおり重い相互認証（お互いに厳しく本人確認し合う仕組み）は入れずに進めます。その代わり、費用がほぼゼロで効果がある次の2つだけを入れます。

  • 作業機（Runner）を登録するときの一回限りの合言葉
  • 一時的な利用許可（リース / lease）の利用記録（誰のどの利用許可が、いつ、どの作業機で使われたか）

これらを入れておくと、後から本人確認を強めることになった場合の土台にもなります。
