## レビューしてほしいこと

### 1. 残っている穴 (レッドチーム)

設計全体を通読し、まだ落ちそうな所を指摘してください。特に:

- 状態遷移の競合や、想定されていないタスク状態の組み合わせ
- worktree と台帳ファイルの扱いで曖昧な所
- 停止条件の抜け (止まるべきでない時に止まる / 止まるべき時に止まらない)

### 2. ワーカー側の実行可能性 (最重要 — あなたの専門領域)

この設計では、light クラスのワーカーに以下のような作法が要求されます。
**あなた自身が確実に実行できるか**、正直に判定してください:

- レビュー完了時に `node scripts/task-ctl.mjs verdict <file> --verdict ...` を
  必ず実行してから終わる、という儀式は守れるか。忘れそうな場面は？
- frontmatter は触らず本文セクションだけ書く、という分業は分かりやすいか
- `allowed_paths` の範囲内だけで作業する制約は、指示として曖昧でないか
- 前任ワーカーの WIP (未完了の変更 + 引き継ぎメモ) から再開する場面で、
  メモに何が書いてあれば確実に引き継げるか
- light タスクのタイムアウト (実装15分 / レビュー10分) は妥当か

守れなさそうな作法があれば、「ワーカー側の負担を下げる代替案」をください
(例: 儀式を減らす、指示の置き場所を変える、確認を機械側に寄せる)。

### 3. 削れる部分

MVP として過剰な部分があれば指摘してください。逆に、light モデルの
実行を助けるために「これだけは入れるべき」というものがあれば、それも。

### 4. あなた自身の制約の自己申告

- agy の headless 実行で Hydrogen は指定可能か (モデルの正式名・effort の有無)
- コンテキスト量や長時間タスクでの挙動など、ワーカーとして使われる上での
  正直な限界

## 出力形式

「残っている穴 / ワーカー側の実行可能性 (作法ごとの可否) / 削れる部分 /
自己申告」の4節でお願いします。
