# ADR-0011 C-min：正式承認案

状態：**未承認の提案**。承認待ちであり、ADR採用・実装・認証操作・実接続・
サービス操作・Loop起動を開始する文書ではありません。

目的は、既存Development LoopでLocus本体を自律開発するための最小の中継ゲートを
完成させることです。本体の先行手動実装、新しいオーケストレーター、専用実行器、
アカウント、サービス、追加API従量課金は対象にしません。

設計本体：[MODEL_BOUNDARY_FINAL_DESIGN.md](MODEL_BOUNDARY_FINAL_DESIGN.md)。
独立レビュー：[MODEL_BOUNDARY_DESIGN_REVIEW.md](../reviews/MODEL_BOUNDARY_DESIGN_REVIEW.md)。
承認対象の正確なファイル集合・SHA-256は
`MODEL_BOUNDARY_APPROVAL_MANIFEST.json`に固定します。ファイルが変われば再承認対象です。
この文書を含むファイルハッシュは、そのmanifestの外側のSHA-256を承認対象にします。
manifest作成は承認記録・PolicyMigration適用・稼働証明の生成ではありません。

## 1. 今回求める承認

以下を一括の、設計・オフライン実装範囲として承認してください。

1. 下記の限定的なC-minをADR-0011として通常開発経路に正式採用すること。
2. 既存AuditRelayを拡張し、通常のWorker／Reviewer／GoalEvaluatorに接続すること。
3. CLI・モデル・ChatGPTログインを維持し、後述の安全境界・一時設定・永続予約を実装すること。
4. 実モデル推論や認証操作を伴わない模擬試験・回帰検証と、独立セキュリティレビューを行うこと。

**実接続と30分Loop試験は含みません。** それぞれ後の独立した許可が必要です。
既存の承認・拒否・保留、試行回数、予算、Goal受け入れ条件はリセットしません。

## 3. 安全境界と認証

維持する保証：許可されたソースだけを扱うこと、モデル向け実行ツールがゼロであること、
未知の構造を拒否すること、生成物をControllerが検証してから適用すること、QA隔離、
独立レビュー、実行期限、既存のコミット・Push・復旧条件です。

変更する保証：CLI内の全ツール登録が空であることへの依存を、中継による送信時ゼロ検証と
返却時の実行前拒否へ置き換えます。中継のJSON/SSE検査器、接続元照合、
一回限りの送信予約が新しい信頼対象になります。未知・不一致・未検証は停止します。
今回のカタログ制限は追加防御として使い、これだけで安全を証明したとは扱いません。

公式CLIは既存の承認済み保存方式・CODEX_HOMEから、自分のChatGPT認証を使用します。
中継が資格情報ストアを読み出す、認証キャッシュを複製する、別用途へ転用する、
新しい鍵・アカウント・トークンファイル・OAuth実装を作ることは許可しません。

**承認が必要な認証上の変更は、CLIが送信するAuthorization／accountヘッダーを、
同一PCの信頼された中継メモリで一時的に受け、同じ公式接続先へ同じ用途で送ることです。**
送信先はTLS検証付き`https://chatgpt.com/backend-api/codex/responses`に固定し、
リダイレクト・任意プロキシ・別ホスト・呼出元指定URLへ送りません。
中継を別のモデルクライアントや汎用トークン転送器として利用しません。
同じWindowsユーザーの侵害済みコードからの完全防御を新たに保証するものではありません。

既存CodexRunnerの無条件`login status`は新経路から除去します。必要な非秘密の
保存方式・プロファイル・存在／所有者／同一性を先に確認し、不明ならCLI起動前に保留します。
存在確認だけで認証成功や利用枠を認定しません。audit用AuthStateを通常ユーザーへ複製したり、
保存方式を移行したりしません。証跡が不足する場合は、対象を限定した整合性確認を別に提案します。

モデル中継はCLIの認証更新など全通信を横取りする仕組みではありません。
後の実接続許可では、公式CLIの通常認証ライフサイクルが必要ならその範囲も明示します。
本承認に実CLIの認証読込・更新、login/status/logout、再登録・認証復旧は含めません。
オフライン試験は独立した模擬プロファイルと非機能の合成マーカーだけで行い、
実際のログインや新しい資格情報保存を行いません。

## 4. 設定と実装の限定範囲

| 項目 | 許可する変更 |
| --- | --- |
| モデル／provider | gpt-6.1-sol／通常openaiを維持。固定CLIの子プロセスにだけ、一時的なopenai_base_urlで所有中継への経路を指定する |
| カタログ | 検証済み元カタログの専用コピーを固定。tool_mode=direct、experimental_supported_tools=[]、apply_patch_tool_type=null、shell_type=disabled、multi_agent_version=nullと既存機能無効化・native V2制限を組み合わせる。通常キャッシュを上書きしない |
| 設定保護 | グローバル設定を上書きせず、適用する設定・カタログ・CLI・hook／skill等を固定して前後照合。既存hookの評価保留を回避しない |
| ゲート | audit_transportの閉じた要求／応答契約、完全フレーム検証、接続元PID・保持ハンドル・job・SID照合、期限・キャンセル・一回送信を実装 |
| 実行証跡 | 旧v2証跡を成功へ書き換えない。新しい契約バージョンと実装・設定に結び付く証跡を、対応検証の成功後だけ発行する |
| 永続状態 | 既存StateStore内の限定的なmodel_invocations予約表。既存所有者ID／試行／役割／bindingを一意に予約し、CLI開始前とprovider送信前に永続commit。別ID・新run・再開による不確定要求の再送を禁止 |
| 呼出元 | Controller／Development Loop／Reviewer／GoalEvaluatorには所有者ID・既存結果の参照を渡す最小配線のみ。スケジューリング、タスク遷移、QA、Git配送アルゴリズムを置き換えない |
| 診断記録 | モデル入力・認証ヘッダー・推論内容・生応答・生stderr／例外を保存しない。有限のエラー分類と非内容の識別情報だけ。必要な最終編集案／所見は既存タスク成果物として扱い、会話ログを複製しない |

既存の`.loop` Goal・受け入れ条件・security/QA/approval/loop上限・配送設定を
この承認だけで手編集しません。現行proposal-dockerの実装と証跡を更新する範囲です。
凍結ポリシー変更が実際に必要と判明した場合は、既存PolicyMigrationの不変条件を
弱めず、正確な差分・対象ハッシュを別に提示します。承認判定の抜け道を追加しません。

## 5. 完了判定と次の許可

1. 固定CLI・閉じた契約・全対象役割で、内容を記録しないローカル模擬検証が通る。
2. 悪意ある呼出し・断片化・未知イベント・末尾埋込・認証漏洩・接続元偽装・
   二重送信・プロセス異常終了・全commit境界での中断／復旧が、拒否・保留として検証できる。
3. 正常応答のCLIエラーを無効化で隠さず解決し、厳密なローカルスキーマと既存必須検証を通す。
4. 実装と正確な成果物の独立セキュリティレビューを完了する。
5. 証拠・未検証事項・既存試行台帳を確認して、通常ChatGPT経路の具体的な実接続許可を求める。
6. 実接続も含む全起動条件の成立後、対象Goal／ブランチ／実行範囲／停止条件を示して
   30分Loop試験の許可を別に求める。

模擬試験を実接続済みとせず、実装完了をLoop起動許可と解釈しません。
旧audit試験の試行回数・許可・不確定結果は保存し、正常開発用の新IDで回避しません。
研究資料・認証情報のモデル入力への追加送信、QA／CIの弱体化、mainへの直接Push、
PR／App／自動マージの再導入や有効化は今回の承認に含みません。

## 6. 残存リスク・工数

内部Lite仕様の変更、通常ChatGPT経路との未証明の同等性、CLIの残存エラー、
検査器の欠陥、同一ユーザーによる改変、不確定なprovider処理が残ります。
公式資料の中継例は、この固定旧CLI・個人契約・ツールを拒否する制限構成の
全面的な互換性・サポート保証ではありません。不適合なら停止し、枠や利用条件を回避しません。

工数は固定Liteのみの実装・検証・独立レビューで概算5～8人日です。
承認・実接続確認・互換性不適合の対応待ちは含みません。必要範囲を超える再設計は、
理由と影響を示して停止・相談します。

## 7. 承認の記録方法

review済みファイルを固定したmanifestのSHA-256を示したうえで、所有者に
「このハッシュのC-min設計・通常開発経路限定のADR採用・オフライン実装／検証を承認」
との回答を求めます。無回答・時間経過・以前の自動マージ許可を承認として扱いません。
承認後のADR記録には対象ハッシュと実際の回答を保存します。
この文書自体に承認済みの状態や実行許可を付けません。
