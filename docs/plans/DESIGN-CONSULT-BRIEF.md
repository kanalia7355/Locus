# 設計相談ブリーフ（Argon / Codex へそのまま渡す用）

あなたは開発システムの設計相談相手です。以下の要点と制約を踏まえ、
実現方式を提案してください。

## 目指すシステム（一文）

**技術的には自立完結し、最終的な満足度だけはユーザーが判断する開発システム。**

タスク分解 → 実装 → レビュー → QA → コミット → push → CI 確認 → マージまでを
人手なしで回し、ユーザーは「改善点の指示」と「最終的な満足度の判断」だけを行う。

## 動機

- Codex 単体で全てを回すとトークン消費が大きすぎる
- 手元には複数の CLI とモデル枠があるのに活かし切れていない:
  OpenCode の無料モデル群、agy 経由の Gemini / Claude (Google AI Pro 枠)、
  Codex (Luna 等の安いモデルを司令塔に使いたい)

## 使える資産（実在し、動作確認済みのもの）

- タスク台帳: `progress/phase-<slug>/PROGRESS.md` + `tasks/*.md`
  (Markdown + frontmatter で状態管理。この方式自体はうまく機能している)
- 規約文書: `docs/agent/PROTOCOL.md` (状態遷移と試行上限)、
  `MODEL_ROTATION.md` (重み別のモデル選択と枠切れ時の切替)、
  `CONSTRAINTS.md` (許可/禁止パス)
- GitHub: コミット、push、Actions CI をゲートに使える
- git worktree でタスクごとに作業場所を分離できる
- Superpowers skills が agy / OpenCode / pi に導入済み
- Codex のターン完了は `~/.codex/sessions/**/*.jsonl` の
  `task_complete` イベントで外部から観測できる (自作アプリ Agent Room で実績あり)
- 実行環境は Windows ホスト上の CLI 直接実行 (Docker なし、既存ログイン使用、
  skip-permissions 前提)

## 苦い経験（同じ轍を踏まないこと）

- ファイル経由で機械パースする駆動方式は、表記ゆれ・改行コード (CRLF)・
  文字コードの差異で「タスクが見えなくなる」事故を繰り返した
- Codex の goal ループ単体は過去に実装サイクルが回らず断念した
- 一定間隔ポーリング方式は、段の遷移に待ち時間が乗り、進捗が見えにくい

## 制約

- 無人で数時間回り続けること。プロセスが落ちてもファイルから再開できること
- 司令塔のコストは最小に (安いモデル + 必要最小限のコンテキスト)
- ユーザーの確認窓は GitHub (コミットが積まれていれば進捗が分かる)
- 暴走防止: 対象タスクが尽きたら仕事を捏造せず止まること
