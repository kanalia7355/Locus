# 資料抽出の実行境界（`DATA-006` / `T-PH6-104` の設計）

著者: Claude Code（オーケストレータ）。確定日 2026-11-19。
オーナー決定 2026-11-16「サンドボックス案でよい」「ウイルス対策はやれるとこでやってよい。
docker でもローカル PC でも」「危ないデータを入れるのは本人のせい」。

この文書は `T-PH6-104` の受入条件の根拠であり、ジョブはこれに従う。
`T-PH6-104` の `allowed_paths` と `test_cmd` はこの文書の §7 で確定した。

## 1. 出発点 — オーナー決定の一文には実装として同意しない

「危ないデータを入れるのは本人のせい」は、**単独利用なら**正しい。
しかし Locus は共有ツールで、資料は投入者だけのものではない。悪意あるファイルが
開かれた瞬間、被害は投入者ではなく**サーバ（＝全員の資料）**に及ぶ。
「本人のせい」で済むのは本人の被害だけ。サンドボックスはその差を埋めるために入れる。

オーナーが許可した「やれるとこでやってよい」の範囲で、**できることとできないことを
記録に書き分ける**のがこの設計の主眼である。

## 2. 何を信用しないか

抽出器（PDF パーサ、Office パーサ、OCR）は**攻撃者が中身を選べる入力**を解析する。
したがって抽出器そのものを信用しない。**抽出器が任意コード実行を取られた前提**で、
その先に何もできないことを境界で保証する。

本体プロセスは抽出器のコードを `import` しない。import した時点で、
パーサの脆弱性は本体の脆弱性になる。抽出は常に**子プロセス**で行う。

## 3. 子プロセスに与えるもの

| 項目 | 値 | 理由 |
|---|---|---|
| 入力 | 1 ファイルの**バイト列を標準入力で**渡す | パスを渡すと、そのパスの周囲を読まれる |
| 出力 | 標準出力に JSON 1 件（本文・ページ数・警告） | ファイルを書かせない |
| 書込み先 | 専用の一時ディレクトリ 1 つだけ | パーサが一時ファイルを必要とする場合の逃げ道 |
| ネットワーク | 遮断（**docker 系統のみ**。§5 を読むこと） | 情報持ち出しと二段目の取得を止める |
| 環境変数 | 空に近い最小集合 | 資格情報の持ち出しを止める |
| CPU 時間 | 上限（既定 30 秒） | 展開爆弾・無限ループ |
| メモリ | 上限（既定 512 MiB、**docker 系統のみ**） | 展開爆弾 |
| 実時間 | 上限（既定 60 秒） | スリープで居座る攻撃 |
| 出力バイト数 | 上限（既定 8 MiB） | 出力で本体のメモリを食う攻撃 |

## 4. 2 系統を同じインタフェースで

オーナー回答「docker でもローカル PC でも」。呼び出し側は 1 つの関数しか知らない。

- **docker 系統**: `--network none --read-only --cap-drop ALL`、非 root、
  `--security-opt no-new-privileges`、`--pids-limit`、`--memory`、`--cpus`、
  書込みは `--tmpfs` 1 つ。
  **語彙と旗は `loop_engine/docker_boundary.py` に揃えること**（既に実測で効いている）。
  ただし**`loop_engine` を import しないこと**: 保護パスでジョブから書けないうえ、
  開発ループと製品は信頼領域が違う。真似るが共有しない。
- **子プロセス系統**: docker が無いときの退避。実時間上限・出力上限・
  作業ディレクトリ限定・環境変数遮断で運用する。

どちらで走ったかを**取り込み記録に残す**（`sandbox: docker` / `sandbox: subprocess`）。
利用者と管理者が、その資料がどの強さの境界で処理されたかを後から確認できること。

## 5. 子プロセス系統は「ネットワーク遮断」を主張しない（最重要）

実測で分かっていること:

- **この開発機に `resource` モジュールは無い**（`win32`, Python 3.13.2 で
  `ModuleNotFoundError`）。POSIX の `setrlimit`（`RLIMIT_CPU` `RLIMIT_AS`
  `RLIMIT_FSIZE`）による CPU・メモリ上限は**Windows では使えない**。
- **docker エンジンはこの機で動いていない**（CLI 28.5.1 はあるが
  `docker info` が名前付きパイプに接続できない）。
  したがって**CI は docker 無しで走る**。これが既定経路である。
- `ADR-0006` に記録済みの実測: **Windows のネイティブサンドボックス診断は境界を
  成立させられなかった。loopback 接続と方針パスへの書込みが可能だった。**

したがって、子プロセス系統で「ネットワークを遮断した」と記録してはいけない。
子プロセス系統で言えるのは次だけ。

| 保証 | docker | 子プロセス |
|---|---|---|
| 実時間上限 | ○ | ○ |
| 出力バイト数上限 | ○ | ○ |
| 環境変数の遮断 | ○ | ○ |
| 書込み先の限定 | ○（`--read-only` + `tmpfs`） | **△ 作業ディレクトリ外への書込みを止める強制力は無い** |
| CPU 時間・メモリ上限 | ○ | **× Windows では主張しない** |
| ネットワーク遮断 | ○ | **× 主張しない（ADR-0006 で loopback が通った実測あり）** |

子プロセス系統では、抽出器の起動コードに socket を塞ぐ入口側の仕掛けを置いてよいが、
それは**Python レベルの衝立であって境界ではない**（ネイティブコードは素通りする）。
置く場合も、記録は `network: unverified` のままにすること。
**弱い方の保証しか主張しない。** これは守るべき不変条件であり、
「たぶん大丈夫」に書き換えてはならない。

### 厳格運用の選択肢

サイトが本当の境界を要求する場合に備えて、設定を 1 つ置く。
**`docker` が使えないとき、未知形式の抽出を拒否する（fail closed）**という選択。
既定は許容（オーナー回答に従う）だが、**既定が緩いこと自体を記録に出す**。

## 6. 失敗の扱い

上限超過・異常終了・JSON として読めない出力は、すべて**隔離**。
「取り込み成功・本文なし」にしない。本文が無いまま取り込むと、
利用者には「資料はあるが中身が引けない」という最も分かりにくい壊れ方として現れる。

利用者に出す理由は既存の `reason` の語彙に合わせ、**何が起きたかだけ**を述べる。
内部のパス・コマンド・スタック・抽出器の名前を出さない
（`解析に時間がかかりすぎたため隔離しました` のように）。

## 7. ウイルス検査が無い環境

オーナー回答により既定は「未検査と明示して通す」。設定で厳格運用（未検査なら隔離）も選べる。
未検査の資料は、**取り込み一覧と出典の両方で未検査と分かる**こと。黙って通さない。

## 8. 受入条件 — 境界が破れたら落ちるテスト

合成の「悪意ある抽出器」を用意し、すべて**失敗として観測される**こと。
**本物のマルウェアは使わない**（合成データのみの規則）。

docker 無しで走る CI が既定経路なので、**1〜5 は子プロセス系統で成立すること**。
docker 系統の検査は `tests/integration/test_live_docker_boundary.py` と同じ作法で
**opt-in の skip** にする（環境変数で明示的に有効化。`LOCUS_LIVE_DOCKER` の前例に倣う）。
**skip された検査を証拠として扱わないこと。**

1. **終わらない**: 無限ループの抽出器 → 実時間上限で殺され、隔離になる。
2. **出力で殴る**: 際限なく標準出力へ書く抽出器 → 出力上限で打ち切られ、隔離になる。
3. **環境変数を持ち出す**: 親の環境変数を読んで出力しようとする抽出器 →
   **渡していない**ことを、出力に現れないことで確認する。
   親側に合成の秘密めいた環境変数を置いて確認すること（**実物の資格情報は使わない**）。
4. **正常系**: 正しい抽出器は本文を返し、`sandbox` の種別が取り込み記録に残る。
5. **記録が嘘をつかない**: 子プロセス系統で走ったとき、取り込み記録が
   **ネットワーク遮断・メモリ上限を主張していない**こと。
   これは「機能が無いこと」ではなく「記録が実態と合っていること」を固定する検査で、
   §5 の不変条件そのものなので**必ず書くこと**。
6. **親が落ちない**: 子プロセスが異常終了しても本体プロセスは生きている。
7. **外に出ようとする**（docker 系統、opt-in）: ソケットを開こうとする抽出器 →
   接続できず、隔離になる。
8. **外に書く**（docker 系統、opt-in）: サンドボックス外の既知パスへ書こうとする抽出器 →
   **ファイルの不在で**書けていないことを確認する。

### 確定したスコープ

- `allowed_paths`: `backend/app/sandbox.py`, `backend/app/service.py`,
  `tests/test_sandbox_boundary.py`, `tests/integration/test_live_sandbox_docker.py`
- `test_cmd`: `python -m pytest tests/test_sandbox_boundary.py tests/test_api.py -q`
  （`tests/test_document_formats.py` は `T-PH6-103` が作るファイルなので入れない。
  形式の表と実行境界は別の関心事で、ここで依存を作る理由が無い。）
- 実際の PDF / Office / 画像 OCR ライブラリは `T-PH6-106`。
  本ジョブは**境界だけ**で、抽出器はテスト用の合成プラグインしか登場しない。
- `backend/app/main.py` は許可しない（API の追加はこのジョブの仕事ではない）。
