# Locus ハイブリッドAIエージェント基盤 要件概要

## 目的
研究室の機密情報を保護しつつ、ユーザーが許可された範囲でCodex・Claude Code・ローカルLLMを利用できる統合ワークスペースを実現する。

## アーキテクチャ
- **Locus Server（Control Plane）**：ユーザー認証、権限・ポリシー管理、ワークスペース管理、ジョブ配送、監査。
- **Server Runner**：研究室内のRAG／GraphRAG、ローカルLLM、機密データ処理を隔離実行。
- **Desktop Runner**：ユーザーPC上の公式CLIを起動し、個人ワークスペースの処理を隔離実行。
- **Agent Adapter**：Codex CLI、Claude Code、ローカルLLMの差異を吸収する共通インターフェース。
- **Locus UI**：チャット、モデル・実行先選択、プロバイダー設定、ワークスペース管理、管理者設定。

## 必須要件
1. **ハイブリッド実行**：ワークスペース単位でServer／Desktop Runnerを選択できる。
2. **管理者統制**：外部AI・実行先・ネットワーク・データ送信範囲を組織ポリシーで制限する。ユーザー設定はその範囲内のみ有効。
3. **データ分類**：公開／個人／研究室共有／機密を区別。分類不明・外部送信禁止のデータは送信拒否。派生データやRAG検索結果にも分類を継承する。
4. **実行隔離**：ファイルアクセス、マウント、コマンド実行、ネットワーク接続をOS・コンテナ等で強制制御する。プロンプトだけに依存しない。
5. **個人認証**：公式CLIの対応するログイン方式を利用し、認証情報を原則として利用者の端末に保持。サブスク利用の可否・制限・利用規約はプロバイダーごとに検証する。独自APIへの認証転用は前提にしない。
6. **監査**：利用者、ワークスペース、実行先、モデル、権限判定、操作、外部送信の記録を残す。ログ自体の機密性も保護する。
7. **安全な通信**：Runnerからの認証済み接続を基本とし、ジョブ・成果物・ログの送受信をポリシー検査する。
8. **UI**：OpenCode風の設定画面でプロバイダー、モデル、認証状態、実行先、権限を管理できる。

## 既存Locusとの整合
- 既存のLoop Controller、QA、独立レビュー、Git操作、CIを可能な範囲で再利用する。
- **ADR-0011／C-minのゼロツール境界は維持**し、ファイル編集・ツール実行を伴うAgent Runtimeは別モジュールとして設計・監査する。
- 既存の実行承認・安全ゲートを迂回しない。Phase完了後の監査、main反映、バージョン更新、次Phase移行は承認ポリシーに従う。

## 実装順序
1. 現行コード・ADR・Phase計画の照合と脅威モデル策定。
2. Agent Registry／共通AdapterとWorkspace Policyの実装。
3. Desktop／Server Runnerの認証、隔離、通信制御、監査の実装。
4. Codex CLIを用いた個人ワークスペースのE2E検証。
5. Claude Code・ローカルLLMの対応可否確認とAdapter追加。
6. モデル・プロバイダー設定UIと既存RAG／Loopへの段階的統合。

## 完了条件
- 許可されたワークスペースでのみエージェントが実行できる。
- 機密・分類不明データの外部送信が技術的に遮断される。
- サーバー／ローカル双方で認証・隔離・監査が機能する。
- 既存Locusの安全境界と主要機能に回帰不具合がない。
- 自動テスト、セキュリティレビュー、E2E試験が成功する。
