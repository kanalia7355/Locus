# ローカルモデルの検出

管理者の「モデル・同時利用」から、検出する場所を選び、検出を実行します。
起動時や画面表示だけではフォルダー走査・Ollamaへの接続を行いません。
対象はブラウザーを操作する端末ではなく、Locusサーバー上のモデルです。

- Ollama：固定の `http://127.0.0.1:11434/api/tags` で登録名とサイズを取得します。
- Hugging Face：サーバーの `HF_HUB_CACHE`、または `HF_HOME/hub`、未指定なら
  サーバー実行ユーザーの `.cache/huggingface/hub` を検出候補として提示します。
- 追加フォルダー：サーバー起動環境の `LOCUS_MODEL_ROOTS` に、絶対パスのJSON配列を
  最大3件設定できます。Windowsでの設定例は次のとおりです。

```powershell
$env:LOCUS_MODEL_ROOTS='["C:\\Models"]'
```

管理画面は許可場所のIDだけを送信します。任意のサーバーパスや接続URLを渡すAPI、
ブラウザー端末のモデルファイルを送信する機能はありません。
追加フォルダーは、管理者が確認したローカルディスクのモデル専用場所にしてください。
WindowsではUNC・ネットワークドライブ・ディレクトリのreparse pointを拒否します。
ファイルリンクは、許可場所内への参照だけをメタデータ確認に使います。

GGUFファイルとSafetensorsのあるフォルダーを候補として表示します。設定・重み・
トークン・Pythonファイルの内容は読みません。拡張子や登録名の発見は、形式の妥当性、
全シャードの存在、ライセンス、モデルの動作確認を意味しません。

候補の選択は現在の画面内での確認用です。保存・取り込み・ダウンロード・モデルの
読み込み・推論を有効にしません。既定のチャットは原文検索です。
別操作の実行設定と承認済みOllama拡張は後続節に記載します。追加API課金や
クラウド接続には切り替えません。

検出結果の名前・サイズはシステム管理者にだけ返します。監査は操作名・対象種別・
結果だけを保存し、パス・モデル名・サービスの生応答は記録しません。
検出の同時実行は1件、モデル候補は合計100件、走査は場所ごと2000項目・深さ5まで。
HTTPは2秒の総時間上限と1MiBの応答上限を適用します。フォルダー走査の3秒予算は
メタデータ操作の間で確認するもので、OSのストレージ待ちを強制中断しません。
上限到達・利用できない場所・拒否した項目は、全件検出成功と区別して表示します。

対応形式の根拠：
[Ollamaのモデル一覧API](https://docs.ollama.com/api/tags)、
[GGUF／Safetensorsの取り込み](https://docs.ollama.com/import)、
[Hugging Faceキャッシュ構造](https://huggingface.co/docs/huggingface_hub/en/guides/manage-cache)。

自動試験には合成ファイル・模擬Ollama応答だけを使います。実モデルの検出や推論を
実施済みとは扱いません。

## ローカルRAG接続（オフライン実装承認済み）

最初の実行先は同一PCのOllama登録モデルとし、GGUF／Safetensors候補の自動取り込みや
任意Pythonコードの実行は含めません。既存Serviceの検索・権限・会話を再利用します。
HF由来モデルもOllamaで対応する形式として登録後に使う方式から進めます。
他の実行形式への対応は、この案で完成扱いにしません。

- 既定は原文検索のまま。管理者が選んだ登録モデルと、ローカル専用の実行環境という
  条件を明示的に設定した場合だけ、固定ループバック先の `/api/chat` を使います。
- Ollamaのクラウド機能は無効化が必要です。LocusはOllamaプロセスやOSの通信設定を
  自動変更しません。局所接続だけでOllama自体の外部通信禁止を証明できるとはしません。
- APIキー・ChatGPT認証は使わず、プロキシ・リダイレクト・外部URL・ツール実行なし。
  送る資料は現行検索で許可された最大5チャンクだけとし、初回は過去の生成回答を
  プロンプトへ再送しません。Locusからの同時HTTP要求1件、待機30秒（明示設定時120秒）・回答2万文字
  の上限から始めます。応答は受信中に総量1MiBを制限し、接続から受信完了までの
  総期限を選択した待機時間とします。圧縮応答・不正JSON・異常応答は拒否します。
  Ollama全体のGPU実行時間を強制制限する保証ではありません。
- 初回は非ストリーミングで一括検証し、送信前と回答返却前に会話・資料権限を再確認します。
  有効セッション・強制パスワード変更状態・選択モデル設定の失効も両時点で確認し、
  保存前にも検査します。HTTP待機中にDBトランザクションを保持しません。
  時間切れ・通信不明では自動再送せず、未完成回答を成功として保存しません。
- **現在と変わる保存保証**：生成回答本文とモデル名を、既存メッセージの出典ID群に
  紐付けてSQLiteへ保存する案です。出典IDはモデルの自己申告ではなく、入力に使った
  全資料のIDを保存します。拡張前は質問文と出典IDだけを保存していました。
  出典が一つでも削除・権限失効したら、履歴では生成回答全体を非表示にします。
  原文の複製をDBへ保存しないという現在の保証はなくなります。
  非表示は保存済み本文の物理削除を保証せず、保存期間の自動決定も含みません。
- 生成内容は提案として表示し、モデルが書いた出典文字列を権限・出典の根拠にしません。
  監査・ログに質問・資料・生成本文を記録しません。

この案の対象はオフライン実装・模擬試験です。実モデルの読み込み・推論・ダウンロード、
Ollama設定変更や再起動は別途確認します。保存内容と推論先の安全境界が変わるため、
実装前の所有者承認を必要とします。

別の小さな確認操作として、所有者の許可後にエージェントが一度だけ
`127.0.0.1:11434/api/tags` と `C:\Users\hirot\.cache\huggingface\hub` の検出を行う案です。
対象は名前・サイズだけで、設定・重み・認証ファイルの内容は読みません。

一次資料：[Ollama chat API](https://docs.ollama.com/api/chat)、
[クラウド機能の無効化](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features)。

## 今回の実装・実環境確認

所有者は上記案のオフライン実装・模擬QAと、一度のモデル一覧確認を承認しました。
実推論・設定変更・モデル読み込み・ダウンロードは承認範囲に含めません。

管理者は検出したOllama候補を選び「チャットの実行設定」を開きます。
ローカル専用構成の確認に同意して「選択モデルをチャットに使用」を押すと、以後の
資料検索で最大5チャンクをモデルへ渡す設定になります。候補選択だけでは有効化しません。
フォルダー候補は実行設定に使えません。「原文検索に戻す」で無効化します。
設定はプロセス内だけに保持し、サーバー再起動後は原文検索に戻ります。
検出情報の取得・設定変更はシステム管理者だけに許可します。
実行時は各利用者の資料権限を使い、管理者権限で資料を検索しません。
出典がない質問では推論しません。過去の生成回答は入力に使いません。

生成回答はSQLiteのgenerated_answersに既存message IDと紐付けて保存します。
新しい表を追加するため既存メッセージの変更・移行は不要です。会話削除時は外部キーで
生成回答も削除します。出典IDにはモデルへ渡した全チャンクを記録します。
APIエラー時は未完成メッセージ・回答を保存せず、ネットワーク結果不明でも自動再送しません。
接続切断・期限切れでOllama自身の実行停止が保証されるわけではありません。

## 実測に基づく待機設定（オフライン実装承認済み）

追加承認された別質問の単発試験は、gemma3:4bで39.089秒後に完了しました。
質問は成膜条件Bの処理時間で、17文字の回答に期待する20分の記述を確認しました。
直前のロード済みモデルは0件、直後はgemma3:4bのロードが報告されました。
最初の試行の失敗原因を確定する証拠ではありませんが、正常な新規試験が通常経路の
30秒上限を超えた事実は確認できました。試験だけの120秒設定は既に終了しています。

既存の実行設定に待機時間30秒／120秒の二択を追加します。
既定は30秒のまま。管理者が明示選択して保存した場合だけ、そのプロセス内の実行に
120秒を許可します。状態API・画面に選択値を表示し、設定世代の検証対象に含めます。
サーバー再起動で無効化・30秒へ戻ります。同時要求1件、受信1MiB、回答2万文字、
ローカル専用確認、失効時の保存拒否と自動再送なしは維持します。
長い待機はサーバーの要求占有時間を増やします。OllamaのGPU実行時間やメモリ解放を
強制制限する保証は追加しません。新しい実行基盤は追加しません。
単発試験とは別に、所有者はこの二択設定のオフライン実装を承認しました。
範囲はオフライン実装・模擬QA・独立レビューです。実環境の有効化や
追加の実推論・設定変更は含みません。

待機設定案の受入条件：APIは整数30/120だけを厳密に許可し、不正型・真偽値・
他の値を拒否します。省略・無効化・新規プロセスは30秒に戻します。
model/version/timeoutは同じロックで取得し、HTTPX各操作とHTTP全体の総期限へ
同じ値を適用します。待機時間だけの変更でも世代を更新し、実行中の旧世代回答の
返却・保存を拒否します。模擬時計で30秒超120秒未満が120設定だけで成功すること、
120秒超過の停止・ロック解放・無再送・未完成保存なしを検証します。
既存の全ACL失効・権限・異常応答・並行要求上限の試験を維持します。
